# 공통 데이터·기하·트랜잭션 계약

작성일: 2026-10-20

상태: 신규 구현의 공통 설계. 타입 이름은 이 문서를 기준으로 도입하고 세부 선언은 Core/Application 담당이 테스트와 함께 확정한다.

## 1. 값과 식별자

| 항목 | 공통 규칙 |
|---|---|
| 기하 단위 | 내부·JSON·네이티브 입출력은 mm, mm². 전기 계산 진입 시 저항 대상 길이를 한 번만 m로 변환 |
| 전기 단위 | Ω/m, Ω, V RMS, A, W. 면적 표시의 cm²/m² 변환은 표현 계층에서 수행 |
| 숫자 | 유한값만 허용. 누락은 nullable/명시 상태, NaN·무한·음수를 결측값으로 사용하지 않음 |
| 영속 ID | `ProjectId`, `FaceRefId`, `RegionId`, `BoundarySegmentId`, `HeatingPathId`, `HeatingPathSegmentId`, `ControlPointId`, `CircuitId`, `ConnectionPointId`, `ConnectionPathId`: Guid 기반 값 타입 |
| 임시 ID | `GeometryDocumentId`, `WorkingCoordinateSystemId`, `CandidateId`, 브리지 정수 piece ID: 런타임 전용. 프로젝트 JSON에 기록하지 않음 |
| 모델 식별 | `ModelIdentity` = 원본 바이트 SHA-256, 원래 단위→mm 변환 정보, 가져오기 구현/버전, Face 형상 특징 |
| revision | `DesignRevision`은 성공한 설계 변경마다 증가. `ModelRevision`은 열린 네이티브 문서의 기하 세대이며 서로 대체 불가 |
| 계산 근거 | `DependencyStamp`: DesignRevision, 원본 해시, 작업 좌표계 지문, 관련 입력 해시, 규칙 버전 |

`FaceReference`는 영속 ID, 원본 해시, 가져오기 당시 번호(힌트), 면 종류·실면적·중심·경계/인접 특징을 가진다. 네이티브 Face 번호는 세션별 대응표에서 얻는다. 번호가 같아도 특징이 다르면 자동 대응하지 않는다. 특징 매칭이 다대일이면 `AmbiguousFaceReference`로 반환한다.

## 2. 영속 설계와 파생 데이터

`DesignProject`의 권장 구조는 다음과 같다. Core는 도메인 모델을 정의하고 Infrastructure는 별도 JSON DTO로 매핑한다.

| 필드 | 내용 |
|---|---|
| Header | ProjectId, SchemaVersion, DesignRevision, 이름, 작성/수정 UTC |
| Source | ModelIdentity, 패키지 내부 `source/model.step` 참조 |
| WorkingCoordinateSystem | Origin, AxisX, AxisY, Normal. 오른손 정규직교계. 조회 방향은 `-Normal` |
| HeatingRegions | FaceReference 집합, 원래 통합 루프, 포함/제외 도형, 유효 루프/성분, 공통 출구 측면 |
| Specifications | WireSpecification, PlacementConstraints, 회로별 Supply |
| HeatingPaths | 생성 원본 정의, 최종 편집 정의, 공유 절점, 조각 순서/종류/활성 여부, 재생성 대응 정보 |
| Circuits | 조각 소속·순서/방향, 두 ConnectionPoint, 두 끝의 ConnectionPath, 회로 ID 계보 |
| Rules | 생성/깊이/검증/면적/전기 규칙 버전, 사용 수치 설정 |
| DerivedCache | 3D 길이·검증·면적·전기 결과와 DependencyStamp. 재열기에서 검증 후 사용 |

미생성 프로젝트도 저장 가능하도록 HeatingPaths/Circuits는 빈 집합을 허용한다. `DesignProject`는 성공한 입력 상태를 표현한다. UI 텍스트·드래그 중 후보는 별도의 `InputDraft`/`EditCandidate`이며, 확정 상태와 섞지 않는다. 일치하지 않는 초안이 있으면 ‘미적용 입력’과 ‘재계산 필요’를 표시하고 출력하지 않는다. 저장은 확정 상태를 대상으로 하며 미적용 입력을 조용히 버리지 않도록 UI에서 적용/취소를 안내한다.

`HeatingPathSegment`는 `HeatingRunSegment`, `TurnSegment`, `FixedJoinSegment`를 구분한다. 조각 ID와 활성 상태를 보존하고, 비활성 조각은 가이드 표시 외 길이·회로·출력에 포함하지 않는다. 조각이 공유하는 절점은 하나의 `ControlPointId`를 참조한다. 배열 순서를 ID로 사용하지 않는다. 표면 인출부터 `ConnectionPoint`까지는 `ConnectionPath`에 속한다.

`CurveDefinition`은 최종 3D 중심선을 복원할 수 있는 수학적 정의이다. Line/Polyline/Arc/BSpline의 명시 구분, 순서·방향·파라미터 구간을 기록한다. BSpline은 degree, poles, weights, knots, multiplicities, periodic 정보를 포함한다. 원본 곡선과 샘플 근사 곡선을 구분한다. 무조건 재보간해 형상을 바꾸지 않는다. 네이티브가 반환한 최종 곡선 정의·길이·샘플은 하나의 `GeometrySnapshot`에 속한다. AIS 객체나 포인터는 이에 포함하지 않는다.

생성 원본과 현재 편집 결과는 보존하지만 과거 상태 스택을 만들지 않는다. 편집 override는 현재 결과의 대응 정보이며 Undo/Redo 명령 이력이 아니다.

## 3. 간격·방향·측면

- `WireSpecification`: MaterialName, DiameterMm, ResistanceOhmsPerMeter. 직경으로 저항을 추정하지 않는다.
- `PlacementConstraints`: MinimumClearGapMm=g, BoundaryMarginMm, InsertionDepthMm=D, InsertionDepthReference=`MoldSurfaceToWireOutsideAlongWorkingAxis`, Direction=`AlongX|AlongY`, Start/End `SurfaceAnchor`, `ExitSideReference`.
- 중심 피치 `CenterPitchMm=g+d`. 현재 MVP의 `PatternParameters.CenterPitchMm`도 중심 피치 입력이다. 구버전 데이터에 `Spacing` 필드가 있으면 `g=Spacing-d` 검증을 거치고, d가 없으면 의미 변환을 보류한다.
- 이번 상세 구현에서 경계 여유는 **본 경로 중심선과 유효 영역 경계 사이의 최소 여유**로 유지한다. 실제 발열사 외곽이 영역 밖으로 나가지 않도록 필요한 중심선 경계 여유는 `max(BoundaryMarginMm, d/2)` 이상으로 검사한다. 곡면의 최종 경계 검증은 네이티브 측정으로 확인한다. 입력 g와 다른 조건이다.
- 가로는 작업 좌표계의 AxisX, 세로는 AxisY 방향의 레인이다. 카메라·모델 bbox 장축을 새 요청 방향으로 사용하지 않는다.
- `ExitSideReference`는 유효 외곽의 연결된 경계 구간 ID와 범위이다. 화면의 ‘왼쪽’ 문자열만 저장하지 않는다. 같은 측면은 한 회로의 두 인출 앵커가 이 범위에 속하는 것으로 판정한다.
- `SurfaceAnchor`는 FaceReference, Face UV, 작업평면 UV, 모델 표면점을 보유한다. UV 체계 두 종류를 혼동하지 않는다. 재열기에서 상호 일치를 확인한다.

외곽 간격의 하드 검사는 별개의 왕복 가지 사이 실제 3D 중심선 최단거리에서 각 반지름을 뺀 거리로 한다. 곡면의 표면상 레인 편차·미배치 공백은 별도 품질 측정으로 보고한다. 자기접촉은 같은 조각 내부도 검사한다. 정상적인 연속 곡선의 국소 인접점과 공유 접점은 비교에서 제외하지만, 같은 조각/이웃 조각 전체를 제외하지 않는다. 국소 제외 규칙은 DES-09/OCC-05에서 U턴·짧은 루프 fixture로 검증하고 규칙 버전으로 남긴다.

## 4. 삽입 깊이와 모델 질의

작업축 Normal=N일 때 모델 바깥 datum에서 `-N`으로 전체 모델의 가장 가까운 trim된 Face를 구한다. 선택된 Face를 먼저 투영한 후 다른 모델 장애물을 무시하는 구현은 허용하지 않는다. first hit가 비선택 Face, 접선, miss이면 후보가 실패한다.

삽입 깊이 D는 이 표면에서 `-N`을 따라 처음 만나는 발열사 바깥면까지 거리이다. 평판에서 접선⊥N인 경우 중심선은 `surface-(D+d/2)N`. 경사·곡면은 발열사 바깥면과 축방향 광선의 교차로 보정량을 구하고 검증한다. 모든 면에 D+d/2 또는 Face 법선 오프셋을 적용하지 않는다. D=0도 중심선이 표면에 놓이는 구기준과 다르다.

`IGeometryQueries`는 Core의 프레임워크 독립 계약이다. Infrastructure 구현은 문서/후보에 바인딩되고 Design이 사용한다.

| 질의 | 입력 → 출력 |
|---|---|
| QueryFirstHit | WorkingCoordinateSystem, 작업 UV, 선택 FaceReference → Hit/Miss/Tangent/Stale/Failure 및 표면점·법선·Face |
| GetSelectedTopology | 선택 FaceReference → 원래 공유 Edge, 외곽/홀 루프, 연결 성분, 경계 구간 |
| AreAdjacent | FaceReference 쌍 → 실제 공유 Edge 인접 여부 |
| MeasureClearance | 후보 CurveDefinition/조각 집합과 비교 규칙 → 최단거리·위치·오차 정보 |
| MeasureDepth | 최종 곡선·직경·표면 앵커·작업축 → 삽입 깊이 측정/판정 불능 |
| GetSurfaceElements | 유효 HeatingRegion·세분화 설정 → trimmed 표면 요소, 실면적, Face/UV, 근사 정보 |
| CheckConnectionPathObstacles | 구간별 경로·금형 안/밖 전이 정보 → 전체 모델 관통/충돌 위치 |

질의 실패는 빈 정상 결과로 바꾸지 않는다. 문서가 만료되면 `StaleGeometryContext`다. 순수 테스트에서는 이 계약을 fake로 대체한다. 전체 모델 실루엣은 선택 Face 영역을 대신하지 않는다.

## 5. 길이·전기·면적

`ConnectionPath`는 한 ConnectionPoint의 발열사 끝점→표면 인출→실제 연결부 경로다. 구간마다 `ConductorRole=HeatingWireExtension|SeparateConnectionWire`와 `GeometryDomain=OnMold|External`을 독립 지정한다. 재료 구분과 공간 구분을 혼동하지 않는다. 외부 연결점은 월드 XYZ, 금형 출구는 측면 표면 앵커를 저장한다. OnMold에서 External로 나가는 한 번의 명시적 전이와 그 이후 재관통 금지를 검사한다.

`LengthBreakdown`은 다음 비중복 원장을 가진다.

| 값 | 저항 길이에 포함 |
|---|---|
| 본 경로 + 활성 연결 조각의 최종 3D 길이 | 예 |
| 같은 발열사로 된 연장부의 최종 3D 길이 | 예 |
| 별도 연결선의 최종 3D 길이 | 아니오 |
| 발열사에 배정된 추가 여유 길이 | 예 |
| 별도 연결선의 추가 여유 길이 | 아니오 |

여유는 실제 형상에 아직 그리지 않은 추가분만 받는다. 동일 조각은 한 회로에만 소속되고 한 원장 행에만 계상한다. 화면의 ‘연결 길이’는 발열사 연장/별도 연결선을 세부 열로 나눠 합계를 표시한다. 전기 입력 `L=(본경로+발열사연장+발열사추가여유)/1000` m이다.

회로마다 Supply(ActualVoltageVrms, MaximumVoltage, MaximumCurrent, optional MaximumPower)를 둔다. Case 프리셋 선택 시 명시적으로 220/220/16을 채울 수 있지만, 최대전압만 있는 입력에서 실제전압을 추정하지 않는다. 저항 `R=rL`, 전류 `I=V/R`, 전력 `P=V²/R`. 회로 전류를 합산해 단일 16A 한도와 비교하지 않는다.

전기 상태는 `Pass|LimitExceeded|Incomplete|InvalidInput`으로 구분한다. 형상 변경은 유효하나 전기 한도 초과인 경우 설계 자체는 확정할 수 있고 판정을 그대로 표시한다. 필수 입력 누락은 0W가 아닌 계산 불가다. 계산값·판정은 반올림 전 값으로 결정한다.

Design은 유효 표면 요소를 본 발열 경로에 가장 가까운 회로에 배정해 `AppliedAreaAllocation`을 만든다. 동률은 CircuitId의 정규 문자열 순으로 고정하고, 경계 요소는 재분할한다. 면적은 투영 삼각형 면적이 아닌 실제 trimmed 표면 면적을 사용한다. 전체 적용면적, 미배정 적용면적, 근사/수렴 설정을 기록한다. Electrical은 Pass 회로의 회로별 적용면적만 합산해 전기 조건 만족 적용면적을 구한다. 별도 연결선을 면적 소유권의 거리 대상으로 삼지 않는다.

## 6. 후보·확정·표시 수명

Application 포트의 표준 흐름은 아래와 같다. C# 메서드는 단일 UI 스레드에서 호출하며 `CancellationToken`을 전달한다. 비동기 파일 IO를 쓰더라도 OCCT를 `Task.Run`으로 보내지 않는다.

1. `ProjectSession`에서 확정 `DesignProject`와 BaseRevision을 캡처한다. UI 초안으로 후보를 만들며 기존 연결·계산·장면을 지우지 않는다.
2. Design이 HeatingPathDraft/변경 정의를 만들고 `IGeometryWorkspace.Prepare(candidate, token)`이 전체 형상/연결 경로/길이를 비공개 staging에 준비한다. 모델 열기는 기존 문서와 분리된 후보 모델을 준비한다.
3. `IPreparedGeometry`는 `Snapshot`, 후보 전용 `Queries`, `Publish()`, `Dispose()`를 제공한다. Design 공통 검증과 Electrical 계산을 이 Snapshot으로 수행한다.
4. BaseRevision, 모델 세대, 입력 해시를 재확인한다. 취소·검증 실패·stale이면 Dispose로 후보만 제거한다.
5. 성공 예정 스냅샷·계산·이벤트를 모두 메모리에 준비한 뒤 Publish한다. 네이티브는 준비된 형상 소유권을 교체하고 이전 자원은 성공 전까지 해제하지 않는다.
6. Publish 성공 직후 이미 준비한 관리형 세션 스냅샷을 교체한다. 이 확정 구간에 사용자 콜백·파일 IO·새 계산을 넣지 않는다. 이후 장면 갱신·알림 실패는 PostCommitFailure로 분류한다.
7. graphics 실패 시 네이티브 형상 확정 여부를 receipt로 확인한다. 관리형 설계는 이 결과에 맞추고 `PresentationOutOfSync`를 표시한다. 확정 설계에서 장면 재구성을 제공하며 완전한 드라이버 rollback을 보장하지 않는다.

수정 전/후 이력을 저장하는 기능은 없다. 실패한 후보 폐기·현재 확정 스냅샷 유지·저장 파일의 안전한 교체는 Undo/Redo와 별개다.

전기값만 변경하면 형상 입력 해시가 같음을 확인하여 기존 곡선을 재사용하고 파생 결과 stamp를 새 revision으로 승격할 수 있다. 오래된 파생 결과를 stamp 숫자만 바꾸어 최신이라고 표시하지 않는다.

## 7. 오류·판정 공통 형식

`OperationResult<T>` = 성공 값 또는 오류 목록. `ValidationReport`는 다음 issue를 가진다.

`ValidationIssue(Code, Severity, MessageKey, EntityIds, Location3D?, DatumUV?, MeasuredValue?, RequiredValue?, Unit?, RuleVersion, Evidence)`

Severity는 `Error|Warning|Info`. Error는 기하 후보 확정을 막는다. 과대 간격은 수치 상한이 없으므로 편차/위치 정보로 보고하며 임의의 열적 합격/불합격을 붙이지 않는다. 전기 한도 초과는 ElectricalResult의 별도 판정이다.

표준 Code: `InvalidInput`, `StaleGeometryContext`, `SurfaceMiss`, `OccludedSurface`, `TangentSurface`, `DisconnectedRegion`, `InvalidBoundaryTopology`, `ObstacleCrossing`, `EndpointConstraintUnsatisfied`, `UnsupportedGeometry`, `GeometryDiscontinuity`, `MinimumClearanceViolation`, `DepthUnresolved`, `SameSideViolation`, `AmbiguousCircuitMapping`, `AmbiguousFaceReference`, `StaleDerivedResult`, `PackageVersionUnsupported`, `PackageIntegrityFailure`, `PostCommitFailure`.

오류는 사용자에게 위치·측정값·수정 가능한 조건을 제공한다. 네이티브 예외 텍스트는 기술 로그에 보존하고 UI에는 MessageKey 기반 설명을 표시한다.

## 8. 수치 정책과 미정 항목

`GeometryToleranceProfile`은 기존 연결 공차 0.01mm, 메시 목표 0.05mm/각도 0.1rad, 매핑 평면 leaf 0.1mm/현오차 0.05mm/최대 재귀 18·probe 100,000·연속 샘플 최대 2mm를 **출발 설정**으로 보존한다. 용도별 필드를 분리하고 설정값·규칙 버전을 결과에 남긴다. 이는 납품 허용오차가 아니다.

최소 간격 g는 입력 하드 제약이다. 거리 근사의 오차구간이 g를 걸치면 세분화/정밀 재측정하고, 판정할 수 없으면 불확실 후보를 통과시키지 않는다. 단순 `g-0.01`을 새 허용 기준으로 만들지 않는다.

GEO-00 보고서에는 깊이·간격·길이·면적의 최대 관측 오차, 지원 표면, 접선/고곡률 실패 사례, 실행시간·probe 수를 남긴다. 납품 오차, 과대 간격 상한, 연결부 표준, 별도 연결선 재료 전이점은 상위 계획 10절처럼 미정으로 관리한다. 이 미정 사항은 기존 합의 기능 개발을 중단할 이유가 아니며, 해결 전에는 측정값/근사/제한을 명시한다.

## 9. 저장·출력 계약

패키지는 `manifest.json`, `project.json`, `source/model.step` 세 필수 entry를 가진다. v1 SchemaVersion으로 시작하며 SHA-256·입력/규칙 버전·단위를 기록한다. 원본 STEP 바이트를 다시 쓰지 않고 포함한다. 저장은 같은 디렉터리의 임시 파일 완성→닫기→ZIP/해시/JSON 검증→교체 순서다.

STEP/DXF는 같은 확정 revision의 `ExportSnapshot`을 사용한다. 경로·연결·회로·LengthBreakdown·ElectricalResult·품질 정보가 포함되고 미리보기/비활성 조각은 제외한다. 미적용 초안·기하 오류·stale 결과는 출력 전 차단한다. 최신 전기 한도 초과/계산 불가 결과는 그 상태를 사양표에 명시하며 합격으로 바꾸지 않는다. 열적 성능을 보장하는 문구는 출력하지 않는다.
