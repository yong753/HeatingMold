# HeatingMold.Design 상세 구현계획

작성일: 2026-10-20  
선행: [공통 계약](00.Shared.Contracts.md), CORE-01~04, 기하 실험 GEO-00  
목표: 사용자가 지정한 영역·간격·깊이·방향·양 끝점으로 하나의 연속 경로를 만들고, 편집·회로·접속을 공통 규칙으로 검증한다.

## 1. 경계와 현재 자산

새 `src/HeatingMold.Design/HeatingMold.Design.csproj`는 `net8.0`, Core와 기존 Clipper2 2.0.0만 참조한다. WPF/OccBridge/netDxf 참조는 없다. 기하 질의는 Core의 `IGeometryQueries`로 받고, 형상 준비/확정은 Application이 Infrastructure에 요청한다. 서비스는 입력 스냅샷을 수정하지 않고 후보 또는 진단을 반환한다.

| 현재 파일/함수 | 재사용 방식 및 주의 |
|---|---|
| `Core/Geometry/RegionOps.cs` | Regions로 이동. precision=2 기본과 작업면 precision=6을 명시 설정으로 분리 |
| `Serpentine.cs`의 ScanlineIntervals | 교차 구간 추출 재사용. bbox 자동 방향과 실제 방향 입력 분리 |
| 같은 파일 Generate/ArcInterior | 기본 사행/U턴 후보 재사용. 양 끝점·레인 수/위상 후보 탐색 추가 |
| 같은 파일 RouteAlongBoundary | 외곽 형상 안의 단순 U턴 구성과 금지된 구멍 자동 우회를 구별. 홀/제외 둘레 경로 탐색으로 호출하지 않음 |
| 같은 파일 GenerateComponents | 제외영역 전용 독립 선분 최종 결과를 폐지. 후보 진단용으로만 쓰거나 제거 |
| 같은 파일 SerpentineTopology.Compute | 조각 활성 관계에서 회로 성분 계산하는 초기 기반 |
| `SurfacePathMapper.cs` | GeometryMapping으로 이동. 전체 모델 first-hit delegate와 Face 메타데이터 사용 |
| `WorkingSide.cs`의 WorkingBoundary | Regions로 이동. 전체 모델 실루엣을 선택 영역으로 쓰지 않음 |

기존 테스트 중 홀/오목 경계를 자동 우회하는 기대가 있으면 상위 합의와 비교한다. 자동 우회를 전제로 한 기대는 명시적 실패 기대/수동 영역 조정 사례로 변경하고 변경 사유를 기록한다. 기존 모든 테스트를 무조건 그대로 유지해 제외 기능을 재도입하지 않는다.

신규 요청의 표준 결과는 `OperationResult<RouteDraft|RegionDraft|CircuitChangeDraft>`이다. 요청에 ProjectId/BaseRevision, 선택 영역, WireSpecification, PlacementConstraints, 프레임, 수치 설정을 전달한다. RouteDraft는 안정 ID·2D 생성 정의·표면 앵커를 포함한다. 최종 깊이 적용 곡선/길이는 별도 GeometrySnapshot으로 받는다.

## 3. Regions: 선택면과 포함/제외

### 3.1 RegionBuilder

1. 선택 FaceReference를 질의 어댑터의 세션 Face에 대응시킨다. 누락/모호한 대응은 실패한다.
2. GetSelectedTopology 결과의 원본 공유 Edge로 인접 그래프를 만든다. 투영된 좌표가 가깝다는 이유로 다른 층/비인접 Face를 합치지 않는다.
3. 공유 Edge를 내부 seam으로 제거하고, 남은 Edge 연결로 닫힌 루프를 만든다. 열린 루프·비정상 분기·중복 Edge를 `InvalidBoundaryTopology`로 분류한다.
4. nesting으로 outer/hole/island를 구별한다. 여러 루프라는 이유로 일괄 거부하지 않는다. 떨어진 성분은 유지하되 ‘단일 경로 생성에는 한 연결 성분 필요’를 명확히 보고한다.
5. 작업평면으로 투영할 수 없는 접선/중첩 영역은 UnsupportedGeometry 진단으로 반환한다. 전체 모델의 뒤쪽 투영면을 합쳐 채우지 않는다.
6. 경계 루프마다 stable ID, 3D 샘플, 작업 UV, 원래 Edge/Face 추적 정보를 유지한다.

### 3.2 RegionAdjustmentService

사각형 포함은 `선택된 유효 표면 ∩ 포함 도형의 합집합`, 포함 도형이 없으면 전체 선택면을 기본으로 한다. 제외는 여기에서 제외 사각형 합집합을 뺀다. 포함으로 선택 Face 밖을 새 발열면으로 확장하지 않는다. 각 사각형은 작업평면 좌표로 저장하고 모델 표면으로 매핑한다. 제외 취소는 RegionAdjustmentId를 삭제한 새 후보를 만든다.

마진은 본 경로 중심선용 inset으로 계산하고 `max(BoundaryMarginMm,d/2)` 및 최종 3D 외피 검사를 적용한다. 인출 통로는 경계까지 허용할 별도 EntryExit 구간으로 구분한다. 모든 조각에 본 경로 inset을 강제해 경계 앵커를 불가능하게 만들지 않는다.

홀/제외를 관통하는 후보는 `ObstacleCrossing`으로 거부한다. 잘린 레인을 자동 이어붙이거나 홀 둘레를 따라 재라우팅하거나 회로를 자동 추가하지 않는다. 홀을 포함한 영역 자체의 저장·표시는 허용하며, 해당 홀을 관통하지 않는 생성 후보는 검사 후 허용할 수 있다.

## 4. Routing: 제약 기반 사행 생성

### 4.1 입력과 전처리

`RouteGenerationRequest`는 g, d, D, margin, 명시 방향, 공통 측면, StartAnchor, EndAnchor를 필수로 받는다. g>0, d>0, D≥0, margin≥0의 유한값을 검사한다. Start/End가 일치하거나 측면/선택 표면 밖이면 생성 전에 오류를 반환한다. 프레임/모델 stamp도 검증한다.

가로는 AxisX, 세로는 AxisY로 local lane 좌표계를 구성한다. `CenterPitch=g+d`를 한 번 계산한다. 레인 중심 피치를 입력 g로 덮어쓰지 않는다. 카메라나 AutoAngleDeg 결과를 신규 요청에 사용하지 않는다.

### 4.2 LaneCandidateEnumerator

다음 탐색은 장애물 우회 탐색과 구분되는 고정 범위의 사행 배치 후보 탐색이다.

1. 유효 inset 높이와 피치에서 들어갈 수 있는 레인 수의 상한을 구한다. 가능한 수를 큰 값부터 줄이며 홀짝을 평가한다. 간격은 고정하고 레인 수만 바꾼다.
2. 위상 seed는 가운데 정렬, 최소/최대 허용 정렬, Start/End 횡좌표가 첫/마지막 레인에 정렬되는 위상에서 구한다. `[0,pitch)`로 정규화하고 수치 중복을 제거한다.
3. 레인 진행 순서 정/역, 첫 레인 진행 방향 정/역을 조합한다. 경로 반전은 양 끝점 역할까지 명시적으로 평가한다.
4. 각 레인의 ScanlineIntervals를 구한다. 구멍/제외로 잘린 interval 사이를 이어 건너뛰지 않는다. 단순 U턴으로 연결할 수 없는 interval 구조는 이 후보의 실패 사유가 된다.
5. 탐색 budget은 명시 설정으로 둔다(초기 최대 256개 후보). budget 소진은 ‘지원 탐색 범위에서 해결 못함’이지 수학적 불가능 증명이 아니다. 필요 입력과 사유를 반환한다.

위상 seed가 커버하지 못하는 임의 곡선·끝점 조합까지 성공을 보장하지 않는다. GEO-00에서 실제 몰드 양 끝점 사례를 먼저 재현하고 seed/후보 정책을 결정한다.

### 4.3 TurnBuilder와 EntryExitPlanner

U턴은 피치/2 반지름의 기본 반원 또는 그와 일관된 제한된 외곽 전환 후보를 사용한다. 샘플 수를 고정된 12점만으로 품질 보증하지 않고 현오차 설정으로 세분화한다. 생성 곡선이 영역·간격을 만족하지 못하면 해당 후보를 폐기한다. 홀/장애물을 따라 우회하는 연결선을 찾지 않는다.

EntryExitPlanner는 요청 시작/종료 앵커와 주 발열 경로 끝점을 잇는다. 직선, 레인 방향/측면 방향으로 된 한 번의 절점 연결을 유한 후보로 평가한다. 이 연결은 인출 허용 통로를 사용하되 선택면·구멍/제외·다른 레인 간격을 검사한다. 요청 앵커를 임의 최근접점으로 바꾸지 않는다. 스냅은 UI의 입력 단계에서 사용자에게 보여준 뒤 확정한 값만 사용한다.

### 4.4 최종 선택

2D 저비용 검사→전체 모델 매핑→외피 깊이→실제 3D 공통 검사 순으로 후보를 평가한다. 성공 후보의 우선순위는 제약 만족이 최우선이고, 이후 많은 유효 레인 수, 작은 최대 공백, 짧은 진입/마감 길이, 정규화된 후보 순서로 결정한다. 전압을 맞추기 위해 회로를 자동 분할하거나 피치를 조정하지 않는다.

결과는 한 Route의 순서 있는 조각들이다. 분기/불연속/자동 추가 회로는 없다. 모든 후보 실패 시 주요 실패 Code, 위치, 같은 측면/끝점/방향/영역 중 수정할 수 있는 조건을 반환한다. 임의 간격 변경이나 일부 경로 성공을 최종 성공으로 보고하지 않는다.

## 5. GeometryMapping과 깊이 연결

SurfacePathMapper의 delegate는 QueryFirstHit를 호출하고 실제 Face 소속을 유지한다. 샘플 순서상의 A→B→C 전환을 검사하며 A와 C가 직접 인접할 필요는 없다. 매핑 중간 miss/비선택 first-hit/비인접 전환/샘플 한도 초과는 실패다.

2D leaf 0.1mm, 현오차 0.05mm, 2mm 연속 step 등의 현재 설정을 초기 profile로 이전한다. 이 샘플링이 좁은 구멍/장애물이 없다는 증명이라고 주장하지 않는다. 본 경로 관통 검사는 가능한 BRep 교차/정밀 재검사와 결합하고, 검증이 해결되지 않는 경우 UnsupportedGeometry로 거부한다.

Design은 D를 설정/검증하고 Native가 계산한 최종 외피 깊이 측정 결과를 소비한다. 깊이 보정 알고리즘을 C#과 Native에 중복 작성하지 않는다. native prepare 이후 반환된 CurveDefinition을 최종 길이/간격/연속성 검사 대상으로 사용한다.

## 6. Editing: 공유 절점 이동과 재생성

`ControlPointEditService.Move(request)`는 ControlPointId, 목표 SurfaceAnchor/작업UV, BaseRevision을 받는다.

1. 존재하는 편집 가능 절점인지 확인한다. 곡선 샘플점과 실제 제어 절점을 구별한다.
2. 공유 절점이면 모든 연결 조각의 끝을 함께 변경한다. 한 조각만 이동해 틈을 만들지 않는다.
3. 레인 절점·U턴 접점·Start/End·측면 인출점 각각의 수정 정책을 적용한다. B-spline 샘플을 무작정 pole로 취급하지 않는다.
4. 영향 조각을 다시 정의하고 매핑·깊이·주변 간격·같은 측면·자기접촉을 검사한다. 초기 버전은 전체 경로를 재검증해도 된다.
5. 유효 후보만 반환한다. 드래그 중 빠른 preview는 별도이며 drop 최종 검사를 생략하지 않는다.

Start/End 이동도 동일 측면을 유지해야 한다. 미달 간격을 자동으로 g로 밀어내거나 입력값을 낮추지 않는다. 실패 시 원래 위치와 형상을 유지하고 문제 위치/실측값을 표시한다.

`RegenerationCompatibility`는 생성 원본의 RoutePieceId/앵커/의미 있는 레인 대응으로 현재 override의 재적용 가능성을 평가한다. 위상이 달라지면 index 기반 적용을 금지한다. Application의 명시 Preserve/Replace 정책으로 이어진다. 편집 이력/Undo/Redo는 구현하지 않는다.

## 7. Circuits: 절단·통합·ID 대응

`CircuitTopologyService`는 활성 조각을 Edge, 공유 절점을 Node로 하는 그래프를 만든다. 비활성 TurnConnector는 성분 연결에서 제외하고 가이드만 남긴다. FixedConnector를 기존 turn index로 잘못 토글하지 않는다.

- 각 성분은 두 degree-1 끝점을 가진 연속 경로여야 한다. 고립점·분기·폐회로는 별도 진단이다.
- 회로 순서는 그래프 순회로 얻는다. 문자열 ID 정렬로 경로 순서를 정하지 않는다.
- 절단 시 기존 시작 Terminal을 포함한 성분이 기존 CircuitId를 유지하고 다른 성분은 새 ID와 ParentCircuitId를 받는다.
- 통합은 요청에서 지정한 survivor CircuitId를 유지한다. 나머지는 계보 정보에 기록한다. 서로 다른 Supply는 Application이 명시 선택한 값만 받는다.
- 각 결과 회로의 양 끝점에서 공통 측면 인출을 다시 검증한다. 기존 커넥터 토글 자체가 항상 유효한 회로 분할이라는 가정은 하지 않는다.
- 절단점이 같은 측면 조건을 깨면 새 EntryExit/Terminal 배치를 후보에 포함하거나 `SameSideViolation`으로 거부한다. 사용자에게 꼭지점/인출 배치 조정을 제공한다. 전체 유효 상태에 미완성 회로를 섞어 확정하지 않는다.

수동으로 서로 다른 회로를 통합할 때는 기존 비활성 커넥터 재활성 또는 사용자가 명시한 단순 연결 조각을 검사한다. 분리된 표면을 잇는 자동 라우팅은 하지 않는다.

## 8. Leads: 접속 경로와 길이 원장

`LeadRoutePlanner`의 입력은 CircuitId/TerminalId, 실제 발열사 끝점, 표면 인출 앵커, 연결부 XYZ, 사용자 절점, 재료 전이점, 추가 여유다.

1. 실제 끝점에서 시작하며 표면상의 가상 2D 끝점으로 되돌아가는 단차를 만들지 않는다.
2. 금형 위 EntryExit/OnMold 구간은 선택 표면/전체 모델 first-hit와 외피 깊이를 검사한다.
3. External 구간은 발열영역 밖을 허용한다. 내부 포함 검사 대신 모델의 관통/충돌 및 명시 출구 이후 재진입을 검사한다.
4. 단순 직선/사용자 절점만 연결한다. 장애물이 있으면 위치를 반환하고 사용자가 절점을 수정한다.
5. 연속 접점과 방향을 검사하고 최종 3D 곡선 길이를 재료 구간별로 분리한다.
6. LeadLengthLedgerBuilder가 본 경로/발열사 연장/별도 리드선/추가 여유를 중복 없이 집계한다. 본 경로에 포함된 EntryExit를 LeadRoute에서 다시 더하지 않도록 소유 조각 ID를 사용한다.

재료가 바뀌는 위치가 없으면 사용자 입력에서 어느 구간이 별도 리드선인지 명시해야 한다. 프로그램이 저항을 줄이려고 전이점을 추정하지 않는다. Preview는 동일 검증을 쓰되 확정 원장/회로 길이에는 반영하지 않는다.

## 9. Validation과 품질

DesignValidator의 실행 순서를 입력/참조→영역/장애물→연속성→동일 측면→외피 깊이→최소 간격/자기접촉으로 고정한다. 선행 실패 후 의미 없는 거리 계산을 반복하지 않지만 사용자 조정에 유용한 독립 진단은 함께 반환할 수 있다.

| 검사 | 하드 기준 / 출력 |
|---|---|
| BoundaryValidator | 본 경로 inset/외피, EntryExit 허용 영역, 홀/제외 관통 없음 |
| ContinuityValidator | 공유 절점 일치, Face 전환 연속, 실제 곡선 연결 |
| SameSideValidator | 회로별 두 인출 앵커가 같은 ExitSideReference 범위 |
| DepthValidator | D와 외피 축방향 교점 측정 일치 또는 판정 불능 오류 |
| ClearanceValidator | 다른 왕복 가지의 실제 외곽 간격 ≥ g, 교차/자기접촉 없음 |
| SpacingQualityAnalyzer | U턴·Face seam·곡면 레인 편차/미배치 공백의 위치·수치; 열적 합격 판정 없음 |

Clearance는 AABB/broad phase로 쌍을 줄인 뒤 native 곡선 최단거리로 확인한다. 서로 다른 직경을 지원할 때는 거리에서 (d1+d2)/2를 뺀다. 같은 회로라도 멀리 떨어진 경로 파라미터가 공간상 접근하면 검사한다. 국소 인접 제외 범위를 거리/파라미터/위상으로 제한하고 큰 U턴 전체·이웃 조각 전체를 제외하지 않는다. 판정 경계에서 근사 오차가 g를 걸치면 정밀화하고 불확실하면 확정하지 않는다.

품질 공백은 표면 요소에서 가까운 본 발열 경로까지의 거리와 인접 레인 사이 표면상 간격을 측정한다. 제외/홀/인출 전용 통로를 미배치 공백으로 오인하지 않는다. 목표 대비 편차·방법·근사 설정을 제공하고 임의의 최대 허용치로 합불을 만들지 않는다.

## 10. Area: 회로 담당 실제 면적

`CircuitAreaAllocator.Allocate(region, circuits, queries, settings)`:

1. 선택 Face의 trimmed 유효 영역에서 구멍/제외/포함 범위를 반영한 표면 요소를 받는다. 겹치는 Face 투영을 단순 합산하지 않는다.
2. 각 요소의 표면 점에서 가장 가까운 활성 본 발열 경로의 CircuitId를 찾는다. 별도 리드선과 외부 발열연장은 담당영역 거리 대상에서 제외한다.
3. 꼭짓점/중심의 가장 가까운 회로가 다르면 요소를 세분화한다. trim/제외 경계와 회로 경계 요소를 우선 세분화한다.
4. 최종 요소는 한 회로에만 배정한다. 동률은 정규 CircuitId 순으로 결정한다. 실면적은 native 표면 적분/trim된 patch 측정으로 얻는다.
5. `합계 담당면적+미배정면적≈총 유효 실면적` 잔차와 세분화 수렴 정보를 보고한다. 좁은 제외영역이 샘플에서 사라지지 않도록 경계 patch를 clip/정밀 측정한다.

설정은 최대 세분화 깊이/요소 수·수렴 목표를 분리한다. 관측 수렴값을 납품 오차로 선언하지 않는다. 입력 회로가 없으면 면적을 0으로 숨기지 않고 전체를 미배정으로 반환한다. 전기 합격 회로 면적 합산은 Electrical이 담당한다.

## 13. 완료 기준

각 서비스가 동일 Core 모델/공통 Validator를 사용하고 생성·편집·회로·접속의 예외 경로가 검사를 우회하지 않아야 한다. 유효한 단일 경로 또는 이유 있는 실패를 반환하며 자동 장애물 우회·자동 회로 최적화·Undo/Redo를 포함하지 않는다. 과대 공백과 담당면적은 측정/근사 결과로만 표현한다. 고곡률 등 미지원 범위와 실제 몰드 검증 결과를 README에 기록한다.
