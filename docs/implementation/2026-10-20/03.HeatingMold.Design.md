# HeatingMold.Design 상세 구현계획

## 2026-10-24 추가 보강: 새 면적 규칙의 요소 전체 회로 인증

표본 승자가 모두 같아도 삼각 요소 내부를 가르는 작은 회로 경계가 표본을 비켜갈 수 있다. 신규 프로젝트 규칙을 `surface-area-v3`로 올리고, 평면 Face의 삼각 요소에서 정확한 직선·원호·다중선 회로 거리가 최근접 회로 주위에 요소 반경의 두 배와 동률 공차보다 큰 여유를 만들 때만 요소 전체를 배정한다. 거리는 1-Lipschitz이므로 이 여유 안에서는 요소 내부의 어느 위치에서도 승자가 바뀌지 않는다. B-spline 회로, 비평면 Face, 거리 여유 부족은 재분할하며 설정 한도에 도달하면 미배정·미수렴으로 남긴다. 저장된 `surface-area-v1`과 `surface-area-v2`는 기존 표본 규칙을 유지한다. 모든 기존 표본이 회로 A를 고르는 삼각형 안에 표본과 떨어진 작은 회로 B를 둔 반례로 새 규칙의 fail-closed와 v2 호환을 검사한다. 원호의 각도 구간 안·밖 측정을 포함한 Design 108개와 Managed Release/x64 전체 558개(Core 41, Design 108, Electrical 22, Application 72, Infrastructure 173, App 142)가 `x64/Verification/20261024-081205-7f20801e/run.json`에서 통과했다. Native 곡면 면적 오차 수렴은 검증하지 않았다.

## 2026-10-24 추가 보강: 회로 경계의 변 중점 표본

`AppliedAreaAllocator`가 표면 요소의 꼭짓점과 중심만 확인해 최근접 회로를 정하던 경로에 변 중점 표본을 추가했다. 꼭짓점·변 중점·중심의 승자가 다르면 해당 면적을 임의 회로에 넣지 않고 재분할하며, 한도 뒤에도 모호하면 미배정으로 두고 수렴 실패를 보고한다. 이 단계에서는 신규 프로젝트 면적 규칙을 `surface-area-v2`로 설정했고, 현재 신규 규칙 `surface-area-v3`의 바로 전 단계다. 저장된 `surface-area-v1`은 기존 꼭짓점·중심 표본 의미를 유지한다. 삼각 요소의 꼭짓점과 중심은 모두 회로 A를 선택하지만 한 변 중점은 회로 B를 선택하는 반례와 v1 호환 회귀를 추가했다. Design 105개와 Managed 전체 555개(Core 41, Design 105, Electrical 22, Application 72, Infrastructure 173, App 142)가 `x64/Verification/20261024-075515-6b8a545d/run.json`에서 통과했다. 이 표본 증가는 Native 실면적 수렴이나 요소 내부 최근접 회로의 연속 영역 증명을 대신하지 않는다.

## 2026-10-24 추가 구현: 안정 ID 기반 회전 내부 다중선 편집

`TurnSegmentCurveEditService`는 `HeatingPathId`, `HeatingPathSegmentId`, `BaseRevision`으로 활성 회전 구간을 찾고 기존 곡선과 제안 곡선 양쪽의 경로 방향 끝점이 공유 `ControlPoint.Position`과 정확히 맞는지 확인한다. 후보는 내부 형상만 교체하며 path/segment ID, 회전 역할, 순서, active 상태, lane index, 공유 절점 참조와 원본 generated segment를 보존한다. 다중선 방향을 그대로 유지하므로 역방향 정의도 경로의 시작·끝 의미가 바뀌지 않는다. Application이 반환된 경로를 전체 기하 후보 검증으로 보낸다. Design 회귀는 정상 교체, 역방향 endpoint mapping, stale·비활성·비회전 대상, endpoint 변경, 내부점 없음과 동일 형상을 검사한다. Design 103개와 Managed Release/x64 전체 551개가 `x64/Verification/20261024-072004-92d603b3/run.json`에서 통과했다. 현재 UI는 다중선 내부점 편집만 지원하며 원호/B-spline·Native 형상 검증은 범위에 포함되지 않는다.

## 2026-10-24 추가 연결: 비주기 B-spline 간격 검사

Design의 기존 `ClearanceValidator` 계약은 유지하고, Infrastructure가 Native 브리지 없는 호스트의 비주기 유리 1·2차 B-spline을 오차 상한이 있는 knot 구간 선분 근사로 검사하도록 연결했다. 1차 비국소 교차는 검출하고, 2차 이웃 구간이 접점 밖에서 겹칠 수 있으면 미확정으로 둔다. 주기·3차 이상 곡선·원호 혼합 질의·선언된 B-spline 연결 접점도 확정하지 않는다. ## 2026-10-24 구현 진행: 구간별 영역 Face 깊이 검증

`DesignValidator`가 각 발열 구간의 생성 영역을 찾아 그 Face 집합을 깊이 질의에 넘긴다. 참조 앵커는 같은 Face 집합에서만 선택한다. `DepthValidator`는 곡선 전체 최소·최대 깊이가 모두 요구 D의 오차 범위 안에 있는지 판정하고, 더 크게 벗어난 극값 위치를 `ValidationIssue`에 남긴다. Face 집합이 빠졌거나 adapter가 전체 envelope를 지원하지 않으면 차단 오류다. Design 91개를 포함한 Managed 449개가 `x64/Verification/20261024-020416-5f8c8315/run.json`에서 통과했다.

Design은 표면 경로 표본·직경·요구 깊이·앵커를 `IGeometryQueries.AdjustInsertionDepth`로 전달하고 Native가 반환한 최종 중심선을 소비한다. 깊이 보정 계산은 Design에 두지 않는다. Infrastructure가 Native 보정 결과를 다시 전체 곡선 envelope 질의로 검증한다. 현재 solver는 제한된 표본 root와 자기교차 검사를 사용하므로 연속 B-rep 단면 sweep의 엄밀한 극값·충돌 증명은 아니다. OCC-04는 실제 평판·경사·곡면 Native 회귀와 GEO-00 검증 전까지 미완료다.

## 2026-10-24 구현 진행: 생성 경로의 삽입 깊이 보정

이전 관리형 고정점 보정은 Design과 Native에 깊이 알고리즘을 중복시키므로 제거했다. `HeatingPathMaterializer`는 각 구간의 작업 평면 표본, 영역 Face, 앵커와 치수를 `IGeometryQueries.AdjustInsertionDepth`에 전달하고, 완결된 `PolylineCurveDefinition`과 알고리즘 버전을 받은 뒤 공유 절점·최대 표본 간격만 검사한다. Infrastructure는 Native 보정 결과를 별도 전체 곡선 깊이 envelope 질의로 재검증한 뒤 반환한다. 보정 실패, 미확정 root, stale context, 선택 영역 밖 first-hit, 작업 한도 초과와 비국소 도체 외피 접촉은 부분 경로를 만들지 않는다. 생성 근거 버전은 `native-axis-ray-bracket-v2`이다.

Design 테스트 대역은 Native query 경계가 반환한 중심선을 사용해 평판·경사면·곡면 경로와 공유 절점을 확인한다. Infrastructure에는 성공·미확정 상태 변환 회귀를 추가했고, WorkingSide에는 평판 활성 경로와 경사면 준비 후보 경로를 root 결과와 별도 envelope 측정으로 교차 확인하는 Native fixture를 추가했다. Managed Design과 Infrastructure 검증은 통과했다. Native preflight는 C++/CLI용 `MSBuild.exe` 부재로 중단되어 새 solver와 WorkingSide fixture는 미컴파일·미실행이다. solver는 유한 작업 평면 표본을 사용하며 연속 B-rep 외피의 극값 완전성이나 모든 자기교차를 증명하지 않으므로 OCC-04/GEO-00는 미완료다.

## 3. Regions: 선택면과 포함/제외

### 3.1 RegionBuilder

1. 선택 FaceReference를 질의 어댑터의 세션 Face에 대응시킨다. 누락/모호한 대응은 실패한다.
2. GetSelectedTopology 결과의 원본 공유 Edge로 인접 그래프를 만든다. 투영된 좌표가 가깝다는 이유로 다른 층/비인접 Face를 합치지 않는다.
3. 공유 Edge를 내부 seam으로 제거하고, 남은 Edge 연결로 닫힌 루프를 만든다. 열린 루프·비정상 분기·중복 Edge를 `InvalidBoundaryTopology`로 분류한다.
4. nesting으로 outer/hole/island를 구별한다. 여러 루프라는 이유로 일괄 거부하지 않는다. 떨어진 성분은 유지하되 ‘단일 경로 생성에는 한 연결 성분 필요’를 명확히 보고한다.
5. 작업평면으로 투영할 수 없는 접선/중첩 영역은 UnsupportedGeometry 진단으로 반환한다. 전체 모델의 뒤쪽 투영면을 합쳐 채우지 않는다.
6. 경계 루프마다 stable ID, 3D 샘플, 작업 UV, 원래 Edge/Face 추적 정보를 유지한다.

### 3.2 RegionAdjustmentService

사각형 포함은 `선택된 유효 표면 ∩ 포함 도형의 합집합`, 포함 도형이 없으면 전체 선택면을 기본으로 한다. 제외는 여기에서 제외 사각형 합집합을 뺀다. 포함으로 선택 Face 밖을 새 발열면으로 확장하지 않는다. 각 사각형은 작업평면 좌표로 저장하고 모델 표면으로 매핑한다. 제외 취소는 RegionAdjustmentId를 삭제한 새 후보를 만든다.

경계 여유는 본 경로 중심선용 inset으로 계산하고 `max(BoundaryMarginMm,d/2)` 및 최종 3D 경계 검사를 적용한다. 인출 통로는 경계까지 허용하는 별도 `ConnectionPathSegment`로 구분한다. 모든 발열사 경로 구간에 본 경로 inset을 강제해 경계 앵커를 불가능하게 만들지 않는다.

홀/제외를 관통하는 후보는 `ObstacleCrossing`으로 거부한다. 잘린 레인을 자동 이어붙이거나 홀 둘레를 따라 재라우팅하거나 회로를 자동 추가하지 않는다. 홀을 포함한 영역 자체의 저장·표시는 허용하며, 해당 홀을 관통하지 않는 생성 후보는 검사 후 허용할 수 있다.

## 4. HeatingPath: 제약 기반 사행 생성

### 4.1 입력과 전처리

`HeatingPathGenerationRequest`는 g, d, D, `BoundaryMarginMm`, 명시 방향, 공통 출구 측면, StartAnchor, EndAnchor를 필수로 받는다. g>0, d>0, D≥0, 경계 여유≥0의 유한값을 검사한다. Start/End가 일치하거나 측면/선택 표면 밖이면 생성 전에 오류를 반환한다. 작업 좌표계/모델 stamp도 검증한다.

가로는 AxisX, 세로는 AxisY로 local lane 좌표계를 구성한다. `CenterPitch=g+d`를 한 번 계산한다. 레인 중심 피치를 입력 g로 덮어쓰지 않는다. 카메라나 AutoAngleDeg 결과를 신규 요청에 사용하지 않는다.

### 4.2 LaneCandidateEnumerator

다음 탐색은 장애물 우회 탐색과 구분되는 고정 범위의 사행 배치 후보 탐색이다.

1. 유효 inset 높이와 피치에서 들어갈 수 있는 레인 수의 상한을 구한다. 가능한 수를 큰 값부터 줄이며 홀짝을 평가한다. 간격은 고정하고 레인 수만 바꾼다.
2. 위상 seed는 가운데 정렬, 최소/최대 허용 정렬, Start/End 횡좌표가 첫/마지막 레인에 정렬되는 위상에서 구한다. `[0,pitch)`로 정규화하고 수치 중복을 제거한다.
3. 레인 진행 순서 정/역, 첫 레인 진행 방향 정/역을 조합한다. 경로 반전은 양 끝점 역할까지 명시적으로 평가한다.
4. 각 레인의 ScanlineIntervals를 구한다. 구멍/제외로 잘린 interval 사이를 이어 건너뛰지 않는다. 복수 interval을 안전하게 잇는 라우터는 아직 없으므로 해당 후보를 거부하고 진단에 다중 구간 라우팅 미지원임을 기록한다.
5. 탐색 budget은 명시 설정으로 둔다(초기 최대 256개 후보). budget 소진은 ‘지원 탐색 범위에서 해결 못함’이지 수학적 불가능 증명이 아니다. 필요 입력과 사유를 반환한다.

위상 seed가 커버하지 못하는 임의 곡선·끝점 조합까지 성공을 보장하지 않는다. GEO-00에서 실제 몰드 양 끝점 사례를 먼저 재현하고 seed/후보 정책을 결정한다.

### 4.3 TurnBuilder와 ConnectionPathPlanner

U턴은 피치/2 반지름의 기본 반원 또는 그와 일관된 제한된 외곽 전환 후보를 사용한다. 샘플 수를 고정된 12점만으로 품질 보증하지 않고 현오차 설정으로 세분화한다. 생성 곡선이 영역·간격을 만족하지 못하면 해당 후보를 폐기한다. 홀/장애물을 따라 우회하는 연결선을 찾지 않는다.

ConnectionPathPlanner는 주 발열 경로 끝점에서 표면 인출을 거쳐 요청한 ConnectionPoint까지 잇는다. 직선 또는 사용자가 지정한 절점 연결을 유한 후보로 평가한다. 연결 경로는 인출 허용 통로를 사용하되 선택면·구멍/제외·다른 레인 간격을 검사한다. 요청한 연결부 위치를 임의 최근접점으로 바꾸지 않는다. 스냅은 UI 입력 단계에서 사용자에게 보여준 뒤 확정한 값만 사용한다.

### 4.4 최종 선택

2D 저비용 검사→전체 모델 매핑→삽입 깊이→실제 3D 공통 검사 순으로 후보를 평가한다. 성공 후보의 우선순위는 제약 만족이 최우선이고, 이후 많은 유효 레인 수, 작은 최대 공백, 짧은 진입/마감 길이, 정규화된 후보 순서로 결정한다. 전압을 맞추기 위해 회로를 자동 분할하거나 피치를 조정하지 않는다.

결과는 하나의 HeatingPath와 회로 양 끝의 ConnectionPath다. 발열사 경로에 분기/불연속/자동 추가 회로를 만들지 않는다. 모든 후보 실패 시 주요 실패 Code, 위치, 출구 측면/끝점/방향/영역 중 수정할 조건을 반환한다. 임의 간격 변경이나 일부 경로 성공을 최종 성공으로 보고하지 않는다.

## 5. GeometryMapping과 깊이 연결

SurfacePathMapper의 delegate는 QueryFirstHit를 호출하고 실제 Face 소속을 유지한다. 샘플 순서상의 A→B→C 전환을 검사하며 A와 C가 직접 인접할 필요는 없다. 매핑 중간 miss/비선택 first-hit/비인접 전환/샘플 한도 초과는 실패다.

2D leaf 0.1mm, 현오차 0.05mm, 2mm 연속 step 등의 현재 설정을 초기 profile로 이전한다. 이 샘플링이 좁은 구멍/장애물이 없다는 증명이라고 주장하지 않는다. 본 경로 관통 검사는 가능한 BRep 교차/정밀 재검사와 결합하고, 검증이 해결되지 않는 경우 UnsupportedGeometry로 거부한다.

Design은 D를 설정/검증하고 Native가 계산한 최종 삽입 깊이 측정 결과를 소비한다. 깊이 보정 알고리즘을 C#과 Native에 중복 작성하지 않는다. native prepare 이후 반환된 CurveDefinition을 최종 길이/간격/연속성 검사 대상으로 사용한다.

## 6. Editing: 공유 절점 이동과 재생성

`ControlPointEditService.Move(request)`는 ControlPointId, 목표 SurfaceAnchor/작업UV, BaseRevision을 받는다.

1. 존재하는 편집 가능 절점인지 확인한다. 곡선 샘플점과 실제 제어 절점을 구별한다.
2. 공유 절점이면 모든 연결 조각의 끝을 함께 변경한다. 한 조각만 이동해 틈을 만들지 않는다.
3. 레인 절점·U턴 접점·Start/End·측면 인출점 각각의 수정 정책을 적용한다. B-spline 샘플을 무작정 pole로 취급하지 않는다.
4. 영향 조각을 다시 정의하고 매핑·깊이·주변 간격·같은 측면·자기접촉을 검사한다. 초기 버전은 전체 경로를 재검증해도 된다.
5. 유효 후보만 반환한다. 드래그 중 빠른 preview는 별도이며 drop 최종 검사를 생략하지 않는다.

Start/End 이동도 동일 측면을 유지해야 한다. 미달 간격을 자동으로 g로 밀어내거나 입력값을 낮추지 않는다. 실패 시 원래 위치와 형상을 유지하고 문제 위치/실측값을 표시한다.

`RegenerationCompatibility`는 생성 원본과 현재 절점/곡선을 비교하고 같은 레인 의미에 조각을 대응한다. `ManualEditPreserver`는 호환 판정을 통과한 이동 절점의 모델 좌표와 활성 상태를 새 경로에 적용하고 연결 끝점을 함께 갱신한다. 고정 시작·끝 앵커 이동, 내부 곡선 형상 변경, 위상/절점 대응 모호성, 연결 구간 누락은 보존 불가로 반환한다. index 기반 재적용은 하지 않는다. Application 요청의 `ManualEditPolicy`가 Preserve 또는 Replace를 선택하며, 이 동작의 순수 회귀 검사는 `RegenerationCompatibilityTests`에서 수행한다. 편집 이력/Undo/Redo는 구현하지 않는다.

### 회전 구간 내부 다중선 편집 경계

회전 곡선 편집은 공유 절점을 직접 바꾸지 않고 현재 곡선 정의의 내부 다중선 점만 교체한다. 내부점 배열 위치는 현재 revision에서 입력을 재조립할 때만 사용하며 요청 식별자로 쓰지 않는다. 양 끝점을 변경하는 입력은 거부하고, 수정 후보는 기존 구간의 stable ID와 방향을 유지한다. 생성 원본은 보존되므로 형상 변경 뒤 자동 재생성으로 수동 곡선을 이어 붙인다고 가정하지 않는다. 재생성 호환성 판단이 실패하면 기존 정책대로 `Replace`를 명시해야 한다.

## 7. Circuits: 절단·통합·ID 대응

`CircuitPathTopologyService`는 활성 HeatingPathSegment를 Edge, 공유 절점을 Node로 하는 그래프를 만든다. 비활성 TurnSegment는 성분 연결에서 제외하고 가이드만 남긴다. FixedJoinSegment를 turn index로 잘못 토글하지 않는다.

- 각 성분은 두 degree-1 끝점을 가진 연속 경로여야 한다. 고립점·분기·폐회로는 별도 진단이다.
- 회로 순서는 그래프 순회로 얻는다. 문자열 ID 정렬로 경로 순서를 정하지 않는다.
- 절단 시 기존 시작 ConnectionPoint를 포함한 성분이 기존 CircuitId를 유지하고 다른 성분은 새 ID와 ParentCircuitId를 받는다.
- 통합은 요청에서 지정한 survivor CircuitId를 유지한다. 나머지는 계보 정보에 기록한다. 서로 다른 Supply는 Application이 명시 선택한 값만 받는다.
- 각 결과 회로의 양 끝점에서 같은 출구 측면을 다시 검증한다. 기존 회전 연결 구간 토글 자체가 항상 유효한 회로 분할이라는 가정은 하지 않는다.
- 절단점이 같은 출구 측면 조건을 깨면 새 ConnectionPathSegment/ConnectionPoint 배치를 후보에 포함하거나 `SameSideViolation`으로 거부한다. 사용자에게 절점/인출 배치 조정을 제공한다. 전체 유효 상태에 미완성 회로를 섞어 확정하지 않는다.

수동으로 서로 다른 회로를 통합할 때는 기존 비활성 회전 연결 구간 재활성 또는 사용자가 명시한 단순 연결 조각을 검사한다. 분리된 표면을 잇는 자동 라우팅은 하지 않는다.

## 8. ConnectionPath: 연결 경로와 길이 원장

`ConnectionPathPlanner`의 입력은 CircuitId/ConnectionPointId, 실제 발열사 끝점, 표면 인출 앵커, 연결부 XYZ, 사용자 절점, 재료 전이점, 추가 여유다.

1. 실제 끝점에서 시작하며 표면상의 가상 2D 끝점으로 되돌아가는 단차를 만들지 않는다.
2. 금형 위 표면 인출/OnMold 구간은 선택 표면/전체 모델 first-hit와 삽입 깊이를 검사한다.
3. External 구간은 발열영역 밖을 허용한다. 내부 포함 검사 대신 모델의 관통/충돌 및 명시 출구 이후 재진입을 검사한다.
4. 단순 직선/사용자 절점만 연결한다. 장애물이 있으면 위치를 반환하고 사용자가 절점을 수정한다.
5. 연속 접점과 방향을 검사하고 최종 3D 곡선 길이를 재료 구간별로 분리한다.
6. ConnectionLengthLedgerBuilder가 본 경로/발열사 연장/별도 연결선/추가 여유를 중복 없이 집계한다. ConnectionPath에 포함된 표면 인출 구간을 다시 더하지 않도록 소유 구간 ID를 사용한다.

재료가 바뀌는 위치가 없으면 사용자 입력에서 어느 구간이 별도 연결선인지 명시해야 한다. 프로그램이 저항을 줄이려고 전이점을 추정하지 않는다. Preview는 동일 검증을 쓰되 확정 원장/회로 길이에는 반영하지 않는다.

## 9. Validation과 품질

DesignValidator의 실행 순서를 입력/참조→영역/장애물→연속성→동일 측면→삽입 깊이→최소 간격/자기접촉으로 고정한다. 선행 실패 후 의미 없는 거리 계산을 반복하지 않지만 사용자 조정에 유용한 독립 진단은 함께 반환할 수 있다.

| 검사 | 하드 기준 / 출력 |
|---|---|
| BoundaryValidator | 본 경로 경계 여유, ConnectionPathSegment 허용 통로, 홀/제외 관통 없음 |
| ContinuityValidator | 공유 절점 일치, Face 전환 연속, 실제 곡선 연결 |
| SameSideValidator | 회로별 두 인출 앵커가 같은 ExitSideReference 범위 |
| DepthValidator | D와 외피 축방향 교점 측정 일치 또는 판정 불능 오류 |
| ClearanceValidator | 다른 왕복 가지의 실제 외곽 간격 ≥ g, 교차/자기접촉 없음 |
| CenterPitchQualityAnalyzer | U턴·Face seam·곡면 레인 편차/미배정 공백의 위치·수치; 열적 합격 판정 없음 |

Clearance는 AABB/broad phase로 쌍을 줄인 뒤 native 곡선 최단거리로 확인한다. 서로 다른 직경을 지원할 때는 거리에서 (d1+d2)/2를 뺀다. 같은 회로라도 멀리 떨어진 경로 파라미터가 공간상 접근하면 검사한다. 국소 인접 제외 범위를 거리/파라미터/위상으로 제한하고 큰 U턴 전체·이웃 조각 전체를 제외하지 않는다. 판정 경계에서 근사 오차가 g를 걸치면 정밀화하고 불확실하면 확정하지 않는다.

품질 공백은 표면 요소에서 가까운 본 발열 경로까지의 거리와 인접 레인 사이 표면상 간격을 측정한다. 제외/홀/인출 전용 통로를 미배치 공백으로 오인하지 않는다. 목표 대비 편차·방법·근사 설정을 제공하고 임의의 최대 허용치로 합불을 만들지 않는다.

## 10. AppliedArea: 회로별 적용면적

`AppliedAreaAllocator.Allocate(heatingRegion, circuits, queries, settings)`:

1. 선택 Face의 trimmed 유효 영역에서 구멍/제외/포함 범위를 반영한 표면 요소를 받는다. 겹치는 Face 투영을 단순 합산하지 않는다.
2. 각 요소의 표면 점에서 가장 가까운 활성 발열사 경로의 CircuitId를 찾는다. 별도 연결선과 외부 발열사 연장은 적용면적 배정 거리 대상에서 제외한다.
3. 꼭짓점·변 중점·중심의 가장 가까운 회로가 다르면 요소를 세분화한다. trim/제외 경계와 회로 경계 요소를 우선 세분화한다.
4. 최종 요소는 한 회로에만 배정한다. 동률은 정규 CircuitId 순으로 결정한다. 실면적은 native 표면 적분/trim된 patch 측정으로 얻는다.
5. `전체 적용면적+미배정 적용면적≈전체 실제 표면적` 잔차와 세분화 수렴 정보를 보고한다. 좁은 제외영역이 샘플에서 사라지지 않도록 경계 patch를 clip/정밀 측정한다.

설정은 최대 세분화 깊이/요소 수·수렴 목표를 분리한다. 관측 수렴값을 납품 오차로 선언하지 않는다. 입력 회로가 없으면 면적을 0으로 숨기지 않고 전체를 미배정으로 반환한다. 전기 합격 회로 면적 합산은 Electrical이 담당한다.

## 2026-10-23 추가 구현: 표면 품질 관측값을 확정 snapshot으로 전달

`AppliedAreaAllocator.AllocateWithSurface`가 수렴 판정에 실제 사용한 마지막 `SurfaceElementSet`을 면적 결과와 함께 돌려주도록 정리했다. ## 2026-10-24 추가 구현: 간격 query의 Native exact 거리 연결

`OcctGeometryQueries.MeasureClearance`는 Native bridge의 exact OCCT edge 결과를 우선하고, Native가 미확정하거나 없을 때 관리형 선분·원호·제한 B-spline fallback을 사용한다. B-spline fallback은 비주기 유리 곡선 중 비퇴화 2차, 또는 한 좌표의 극점이 단조인 3~8차만 인증하며 그 밖의 자기접촉 가능성은 `Unresolved`로 닫는다. 결과의 오차·위치·상태는 `ClearanceMeasurement`와 검증 문제에 보존한다. 회귀는 Native 결과 우선, 관리형 fallback의 지원 범위와 미확정 진단 전달을 확인한다. 이 관리형 범위만으로 DES-09 완료를 선언하지 않으며, OCCT 빌드와 D-09/D-10에 대응하는 실제 Native 곡선 fixture가 남아 있다. 최신 Managed Release/x64 602개가 `x64/Verification/20261024-122045-8b56bbdf/run.json`에서 통과했다.

## 2026-10-24 구현 진행: Native 1차 B-spline 간격

Native exact 간격 계산은 비주기 1차 B-spline을 knot 구간별 직선 edge로 나누고, 비공선 극점을 가진 비주기 단일 구간 2차 유리 Bezier는 원래 곡선 edge 그대로 OCCT에 전달한다. 역방향 1차 곡선도 구간 순서를 유지한다. 축퇴 2차, 주기·다중 구간 2차·3차 이상 B-spline은 자기접촉을 인증하지 못해 `Unresolved`다. WorkingSide source 회귀에는 1차 분리·역방향 거리, 3개 구간 자기교차, 비퇴화 단일 구간 2차 거리, 축퇴·다중 구간 2차 및 3차 미지원 상태를 추가했다. 전체 Managed Release/x64 593개(Core 41, Design 108, Electrical 22, Application 72, Infrastructure 178, App 172)가 `x64/Verification/20261024-110423-7255cd84/run.json`에서 통과했다. 최신 Native preflight `x64/Verification/20261024-111252-6d2c8611/run.json`은 C++/CLI용 `MSBuild.exe` 부재로 중단돼 Native 변경과 WorkingSide source 회귀의 컴파일·실행 결과는 없다.
