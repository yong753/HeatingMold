# HeatingMold 용어 기준

작성일: 2026-10-23  
적용 범위: 상위 구현계획과 `implementation/2026-10-20`의 구현 문서 및 신규 코드. 메일·발주처 자료·체크포인트의 원문 파일명은 변경하지 않는다.

이 문서는 설계 문서와 코드가 함께 사용하는 도메인 용어의 기준이다. Core 타입과 속성 이름은 코드 계약이며, UI와 설명 문장은 표준 한국어를 사용한다. 용어를 바꿀 때에는 이 문서와 Core 계약을 먼저 갱신한 뒤 소비 모듈을 함께 바꾼다.

## 표준 용어

| 표준 한국어 | 코드 이름 | 정의와 사용 규칙 |
|---|---|---|
| Face | `FaceReference` | CAD 모델을 이루는 개별 면. 발열 대상 전체 영역과 구분한다. |
| 발열 영역 | `HeatingRegion` | 선택한 하나 이상의 Face에서 외곽·홀·포함·제외 조건을 반영한 경로 생성 대상. Face 자체와 동의어가 아니다. |
| 발열사 경로 | `HeatingPath` | 한 회로 또는 설계에서 발열사가 배치되는 연속 경로의 설계 표현. 영어 `Route`를 도메인 이름으로 사용하지 않는다. |
| 경로 구간 | `HeatingPathSegment` | 발열사 경로를 구성하는 순서 있는 조각. 종류는 `HeatingRunSegment`, `TurnSegment`, `FixedJoinSegment`로 구분한다. |
| 발열 레인 구간 | `HeatingRunSegment` | 한 레인에서 발열사가 직선으로 지나가는 구간. |
| 회전 연결 구간 | `TurnSegment` | 인접 레인을 잇는 U턴 구간. 활성 상태를 바꾸면 회로가 분리될 수 있다. 전원 연결부를 뜻하지 않는다. |
| 고정 연결 구간 | `FixedJoinSegment` | 같은 레인의 분리 구간을 경계 안에서 잇는 비편집 구간. 회로 분할 조작 대상이 아니다. |
| 연결부 위치 | `ConnectionPoint` | 사용자가 지정하는 회로 끝의 실제 연결 위치. 일반 문서와 UI에서 연결 관련 개념의 기본 명칭으로 쓴다. |
| 연결 경로 | `ConnectionPath` | 발열사 경로 끝에서 연결부 위치까지 이어지는 실제 3D 경로. 길이 표시·저장·출력에 필요하므로 위치와 구분한다. |
| 연결 경로 구간 | `ConnectionPathSegment` | 연결 경로에서 길이·재료·검증 결과를 따로 관리해야 할 때만 쓰는 구간. 일반 사용자 용어로 세분하지 않는다. |
| 삽입 깊이 | `InsertionDepthMm` | 작업 좌표계의 작업축 방향으로 금형 표면에서 발열사 바깥면까지 측정하는 거리. 문서·UI에서 `외피 깊이` 또는 `중심선 깊이`라 부르지 않는다. 중심선 위치는 삽입 깊이와 발열사 직경으로 계산한다. |
| 최소 외곽 간격 | `MinimumClearGapMm` | 서로 이웃한 발열사 외곽 사이에 확보해야 하는 최소 거리 `g`. |
| 중심 피치 | `CenterPitchMm` | 이웃한 발열사 중심선 사이 거리 `p`. 새 입력에서는 `p = g + d`로 계산한다. 최소 외곽 간격과 혼용하지 않는다. |
| 경계 여유 | `BoundaryMarginMm` | 발열 영역 경계와 발열사 경로 사이에 두는 별도 여유. 최소 외곽 간격과 다른 조건이다. |
| 적용면적 | `AppliedArea` | 발열 영역 또는 회로에 배정된 실제 표면 면적의 통칭. 대상·회로·전기 판정에 따라 `전체 적용면적`, `회로별 적용면적`, `전기 조건 만족 적용면적`, `미배정 적용면적`으로 한정한다. 열 성능을 뜻하지 않는다. |
| 작업 좌표계 | `WorkingCoordinateSystem` | 모델에 고정된 원점과 X/Y/N 축. 가로·세로 경로 방향과 작업축 기준을 제공하며 카메라 회전과 무관하다. `프레임`은 이 개념의 사용자 용어로 쓰지 않는다. |
| 투영 좌표계 | `ProjectionFrame` | 3D 점과 작업 평면 좌표를 변환하는 수학적 값. 작업 좌표계 내부의 기하 표현으로만 사용한다. |
| 입력 초안 | `InputDraft` | 사용자가 아직 적용하지 않은 입력. 확정된 발열사 경로·계산 결과와 섞지 않는다. |
| 변경 후보 | `Candidate` | 검증과 실제 기하 준비 중인 변경 상태. 검증 전에는 확정 설계를 대체하지 않는다. |
| 미리보기 | `Preview` | 화면 확인용 임시 표시. 확정 길이·계산·저장·출력에 포함하지 않는다. |
| 확정 설계 | `CommittedDesign` | 검증과 적용이 끝난 설계 상태. 저장·계산·출력은 이 상태를 기준으로 한다. |
| STEP 형식 | `STEP` | 입력·출력 CAD 교환 형식. 파일 확장자를 설명할 때만 `.step`/`.stp`를 함께 쓴다. |
| DXF 투영도 | `DXF Projection` | 3D 모델과 경로의 2D 정사영 도면. 곡면 재단용 전개도와 구분한다. |

## 연결 관련 이름 줄이기

사용자와 설계 문서에서는 `커넥터`, `단자`, `리드선`, `접속선`, `전원 경로`를 일반 명칭으로 사용하지 않는다. 회로 끝에 사용자가 지정하는 것은 `연결부 위치`이고, 그 위치까지 실제로 이어지는 선형 형상은 `연결 경로`이다. 구현에서 재료 차이가 전기 계산에 영향을 주는 경우에만 연결 경로 구간을 `발열사 구간` 또는 `별도 연결선 구간`으로 구분한다.

`회전 연결 구간`과 `고정 연결 구간`은 발열사 경로 내부의 기하 조각이다. 이 둘을 `연결부` 또는 `연결 경로`와 같은 개념으로 부르지 않는다. 기존 코드·테스트에 남은 `PowerLead`, `Connector` 등의 표기는 이전 동작을 설명하는 기록에서만 허용하며 신규 API 이름으로 사용하지 않는다.

## 현재 코드와 목표 계약

현재 저장소에는 Core, Design, Application, Electrical, Infrastructure, App의 C# 제품 프로젝트와 OccBridge가 있다. 기존 `HeatingMold.Export` 제품 프로젝트는 Infrastructure로 이전하며 제거했다. 순수 관리형 모듈은 각자 테스트 프로젝트를 갖는다. 레거시 `PatternParameters.CenterPitchMm`는 `Design.Legacy` 안에서 이전을 위해 유지하며, 새 경로 요청은 `MinimumClearGapMm`과 도체 지름으로 중심 피치를 계산한다. 새 요청 계약에는 삽입 깊이와 연결부 조건이 있다. 후보 geometry workspace와 `.hmproj` 저장·복원, snapshot 기반 `ExportDesign`은 WPF 및 Application에 연결됐다. 화면에서만 변경된 레거시 경로는 session 반영 전 저장·출력을 거부한다. Native C++/CLI 실행 검증, 일부 깊이·간격·연결 충돌 질의와 경로·회로 편집 명령의 session 이전은 남아 있다. 적용면적 배정 로직은 관리형 코드에 있으며 OCCT 실면적 질의는 Native 빌드 환경에서 추가 검증해야 한다.

공통 설계 타입의 소유 위치는 `HeatingMold.Core`다. 경로 생성·경로 구간/회로 분할은 목표 `HeatingMold.Design`, 설계 수명과 연결부 위치 입력은 `HeatingMold.Application`, 3D 기하 질의와 표시·STEP는 `HeatingMold.Infrastructure`/`OccBridge`, 화면 표현은 `HeatingMold.App`이 맡는다. 모든 개념이 하나의 기능 모듈에 모이는 구조는 아니다.

## 문서 적용 순서

1. 이 용어 기준과 [공통 계약](00.Shared.Contracts.md)을 먼저 확인한다.
2. [상위 구현계획](../../Implementation.Plan.2026-10-20.md)은 요구사항과 합의 용어를 설명한다.
3. 모듈별 구현계획은 Core의 타입 이름과 정의를 재사용한다.
4. 발주처 원문과 구현 체크포인트는 당시 표현을 보존하고, 표준 용어와 다르면 이 문서 기준으로 해석한다.
