## 1. 책임과 프로젝트

새 `src/HeatingMold.Electrical/HeatingMold.Electrical.csproj`는 `net8.0`, Core만 참조한다. OCCT/WPF/Clipper/netDxf/파일 IO 의존은 없다. 현재 전기 계산 서비스는 없으며 MainWindow의 길이 표를 계산 구현으로 간주하지 않는다.

열해석, 온도 보정, 저항률/직경으로 단위 저항 역산, 병렬/직렬 복합 전원망, 자동 최적 회로 분할, 최대 가열영역 탐색은 구현하지 않는다. 회로마다 별도 전원이라는 합의를 따른다.

```text
Calculation/ CircuitElectricalCalculator.cs, ElectricalInputValidator.cs
Limits/      CircuitLimitEvaluator.cs
Area/        ElectricallyCompliantAreaAggregator.cs
Presets/     WirePresetCatalog.cs
README.md
```

## 2. 입력·출력 계약

`CircuitElectricalInput`은 CircuitId, WireSpecification, Supply, LengthBreakdown, DependencyStamp를 가진다. 이 입력 구성은 Core 타입을 사용하고 계산에 필요한 읽기 전용 DTO만 추가한다.

| 입력 | 조건 |
|---|---|
| 재료명 | 표시·추적용; 물성 DB 검색하지 않음 |
| DiameterMm | 기하 제원. Case 프리셋은 제공하되 저항 환산에 사용하지 않음 |
| ResistanceOhmsPerMeter | 필수 유한 양수 |
| ResistanceLengthMm | 실제 3D 길이 원장의 계산 대상 합계. 유한 양수 |
| ActualVoltageVrms | 필수 유한 양수. 최대전압으로 대체하지 않음 |
| MaximumVoltage | 회로별 필수 유한 양수 |
| MaximumCurrent | 회로별 필수 유한 양수 |
| MaximumPower | 선택 입력, 입력되면 유한 양수 |

계산 가능한 전압/저항/길이가 있지만 한도만 누락이면 수치는 계산하고 최종 상태는 Incomplete다. V/r/L이 누락이면 관련 계산값을 nullable로 둔다. 명시 0·음수·NaN·Infinity는 InvalidInput이다. 같은 입력에 누락과 무효가 함께 있으면 InvalidInput을 우선하고 모든 입력 문제를 반환한다.

`ElectricalResult`는 다음을 포함한다.

- CircuitId, DependencyStamp, LengthMm/LengthMeters, 입력 r/V/각 한도.
- ResistanceOhms, CurrentAmps, PowerWatts(nullable), 상태.
- 한도별 `WithinLimit|Exceeded|Missing|Invalid`, 초과량/비율.
- 원장 요약 및 저항에서 제외한 별도 연결선 길이, 계산 규칙 버전.

여러 회로를 계산하는 Batch 결과에서도 회로별 값과 상태를 유지한다. 전체 W 합계는 표시할 수 있지만 여러 회로의 A 합계를 단일 16A 기준으로 판정하지 않는다.

## 3. 계산 절차

`Calculate(input)`:

1. ID/원장 중복·음수·수치 유효성을 검증한다. 잘못된 입력을 0으로 정규화하지 않는다.
2. `L=ResistanceLengthMm/1000.0`으로 한 번 변환한다. 이미 m인 값이 이중 변환되지 않게 타입/필드명으로 구분한다.
3. `R=r*L`, `I=V/R`, `P=V*V/R`을 반올림 전 double 값으로 계산한다.
4. 계산 중 overflow/underflow로 0 또는 비유한값이 생기면 InvalidInput/계산 범위 오류로 반환한다. 임의 상한으로 clamp하지 않는다.
5. 실제 V≤MaxV, I≤MaxI, 입력된 경우 P≤MaxP를 각각 비교한다. 같은 한도값은 통과한다. UI 표시 반올림 결과로 판정하지 않는다.
6. 입력 불완전/무효가 없고 모든 한도 이내면 Pass, 하나라도 초과면 LimitExceeded다.

유효한 0V 비가동 모드를 별도로 도입하지 않는다. 현재 사용자 합의의 설계 계산 입력에서는 0은 계산 불가다. 변경 필요 시 Core/공통 계약부터 명시적으로 수정한다.

## 4. 프리셋과 길이 의미

| 프리셋 | 재료 | 직경 | r | 예시 전원 |
|---|---|---|---|---|
| Case 1 | SUS 316L | 0.3mm | 4Ω/m | 실제 220V, 최대 220V, 최대 16A |
| Case 2 | SUS 316L | 0.15mm | 8Ω/m | 실제 220V, 최대 220V, 최대 16A |

프리셋은 값 묶음이며 사용자가 편집할 수 있다. Diameter만 바꿨을 때 r을 자동 변경하지 않는다. Case를 명시적으로 선택했을 때만 프리셋 값을 적용하고 Application이 기하·전기 변경 영향을 각각 처리한다.

길이 원장에서 본 경로+같은 발열사 연장+해당 발열사 추가 여유만 사용한다. 별도 연결선과 연결부 저항은 PDF 기준으로 제외한다. ‘연결 길이 전체 제외’로 구현하면 같은 발열사 연장부를 빠뜨리므로 금지한다. 전이점은 Design/사용자 입력에서 오며 Electrical에서 추정하지 않는다.

## 5. FR-3.3 회로별 적용면적 집계

`ElectricallyCompliantAppliedAreaAggregator.Aggregate(allocation, results)`는 Design의 AppliedAreaAllocation과 같은 revision/회로 집합의 결과를 받는다.

1. allocation/results의 DependencyStamp와 CircuitId 대응을 검사한다. 잘못된 stamp는 StaleDerivedResult이며 이전 면적을 최신으로 복사하지 않는다.
2. 전체 적용면적, 회로별 적용면적, 미배정 적용면적은 allocation 값을 보존한다.
3. ElectricalResult가 Pass인 회로의 적용면적만 합산한다. LimitExceeded/Incomplete/InvalidInput 면적을 전기 조건 만족 적용면적에 넣지 않는다.
4. 누락된 회로 결과가 있으면 평가 완료로 표시하지 않고 미평가 면적을 별도 반환한다.
5. 기하 분할의 근사 수준·잔차를 그대로 전달한다. 전기 모듈이 투영면적으로 다시 계산하지 않는다.

출력 이름은 ‘회로별 적용면적’, ‘전기 조건 만족 적용면적’이다. 이를 실제 온도 도달 면적이나 가열 성능으로 혼동하지 않는다. 전기값만 변경되면 분할을 재실행하지 않고 동일 allocation 위에서 합계만 갱신한다.

## 8. 완료 기준

두 Case가 PDF 수치와 일치하고, 불완전 입력과 초과 판정이 분리되며, 회로별 전원/여유/별도 연결선 규칙이 명확해야 한다. Core 외 의존이 없고, 동일 결과를 UI와 DXF 사양표에서 사용한다. 회로별 적용면적은 Design 기하 분할을 그대로 집계하고 열적 성능을 추정하지 않는다.

### 2026-10-23 실행 진행 상태

Electrical 계산 결과와 면적 집계는 Application 확정 snapshot에 보관되고, Infrastructure 사양표와 App 검토 패널이 같은 `ElectricalResult` 및 `ElectricallyCompliantAreaResult`를 소비한다. App 패널은 발열사 연장·여유와 별도 연결선의 길이 원장을 나눠 보여 주고, stamp 불일치·누락·미적용 전기 초안을 통과 상태와 분리한다. App 표시 회귀를 포함한 Managed Release/x64 전체 404개가 `x64/Verification/20261023-225302-b9875957/run.json`에서 통과했다. UI의 간격 편차·문제 위치 강조는 DES-09/10 완료 전까지 남으며, 실제 DXF 재읽기 및 Native/WPF 앱 실행은 빌드 환경 복구 뒤 검증한다.
