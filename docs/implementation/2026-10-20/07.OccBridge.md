# OccBridge 상세 구현계획

> 용어 기준: [TERMINOLOGY.md](TERMINOLOGY.md).


작성일: 2026-10-20  
선행: [공통 계약](00.Shared.Contracts.md), CORE-01~04의 기하 DTO 의미  
목표: 세션이 소유하는 OCCT 모델·최종 경로·길이·질의를 제공하고 관리형 경계를 얇게 유지한다.

## 1. 현재 구조와 유지 범위

`src/OccBridge/OccBridge.vcxproj`는 v143, `/clr:netcore`, net8.0, Release|x64, 기존 OCCT 7.9.3을 유지한다. `OccBridgeApi.cpp`에 모델/투영/경로/리드/AIS 상태가 모여 있고 `WorkingCoordinateSystemNative.inc`를 단일 translation unit에 포함한다. 현재 static Bridge 호출을 한 번에 없애기보다 새 문서 소유 구현으로 위임하도록 단계적으로 바꾼다.

현재 브리지의 `WorkingSurfaceContext.Frame`, flat Points/Triangles, int FaceId, double 길이 배열 의미를 신규 관리형 DTO에서 명확히 한다. C# Core 프로젝트를 C++에서 참조하지 않는다. 의미가 같은 DTO를 브리지 경계에 두고 Infrastructure에서 Core로 변환한다.


| 소유자 | 소유 자원 |
|---|---|
| DocumentSession | 모델, Face/Edge 지도, revision, working contexts, 확정 기하, 후보, 해당 문서 표시 |
| ModelRepository | TopoDS 원형 모델, 단위/transform, Face 특징·원본 인접 정보 |
| WorkingSurface | frame/datum, 전체 모델 intersector/메시, first-hit 질의 |
| PreparedDesign | 비공개 최종 곡선·연결·길이·표시 준비 객체, source revision |
| ViewerScene | HWND/V3d/AIS와 표시용 ID 대응. 설계 계산 원본은 아님 |
| StepExchange/HlrProjection | 입력 session/snapshot에 대한 파일·투영 작업, 전역 설계 변경 없음 |

RAII로 OCCT Handle/컨테이너를 해제하고 C++/CLI wrapper에 명시적 Dispose/Close를 둔다. 문서 닫기는 UI 스레드에서 preview→AIS→candidate→working context→model→viewer 순서의 의존성을 지킨다. finalizer에서 임의 스레드로 AIS/뷰어를 조작하지 않는다. 명시 종료 누락은 진단하고 스레드 소유 자원 정리는 소유 스레드 경로로 보낸다.

PHASE 1은 활성 문서 하나이며 모델 열기/재열기 실패 보존을 위한 후보 문서는 내부적으로 둘 수 있다. 이 구조를 다중 문서 UI·병렬 OCCT 지원으로 확대하지 않는다. static façade는 active DocumentSession에 위임하고 전역 개별 map을 계속 늘리지 않는다.

## 4. 신규 관리형 API 의미

이름은 아래를 기준으로 추가하고 기존 API는 이전 기간에 façade로 유지한다. 모든 변경/질의에 DocumentId/ModelRevision/WorkingSurfaceContextId를 확인한다. 결과 DTO에는 status와 진단을 제공한다.

| API군 | 입력 | 결과 |
|---|---|---|
| OpenModelCandidate/CommitModel/CloseDocument | STEP path/stream staging 파일, 단위 | 문서 handle, 모델 특징, candidate 상태 |
| CreateWorkingSurfaceContext/QueryFirstHit | doc/revision, N/X, 작업 UV, 선택 Face IDs | frame·가장 가까운 trim hit/Face/법선/status |
| GetSelectedTopology | 선택 Face IDs, sampling profile | 공유 Edge 인접, outer/hole/component, segment ID 힌트 |
| PrepareDesignGeometry | 경로 정의/앵커/직경/삽입 깊이/연결 | candidate handle, curve 정의/길이/샘플/오류 |
| PublishPreparedDesign/DiscardPreparedDesign | candidate handle, expected revision | Committed/PresentationSynchronized receipt 또는 precommit failure |
| MeasureClearance/MeasureDepth/GetSurfaceElements | 준비/확정 geometry, profile | 거리·위치·오차/삽입 깊이/표면 patch 실면적 |
| PrepareConnectionPathGeometry | actual start, exit anchor, XYZ 절점, 재료/외부 전이 | 동일 후보에 속한 연결 곡선·구간 길이·충돌 |
| GetHlrProjection | doc/snapshot, origin/X/Y/N | 작업 좌표계 기준 2D 외곽/은선 |

status는 Hit/Miss/Tangent/InvalidInput/StaleContext/GeometryFailure를 유지하고 경로/깊이/충돌 실패를 추가 구분한다. C++ 예외는 API 경계에서 포착한다. UI에 불명확한 `false`만 반환하지 않고 실패 Code/관련 조각/위치를 제공한다.

## 5. WorkingSurface·RegionTopology

datum은 선택면이 아닌 전체 모델 AABB support 바깥에 놓고 ray=-N을 유지한다. BRep intersector에서 가장 가까운 양의 trimmed hit를 찾는다. 가까운 접선을 건너뛰어 뒤 Face를 선택하지 않는다. first-hit가 비선택 Face면 OccludedSurface다. query와 최종 path mapping에 같은 질의를 사용한다.

선택면 인접은 원본 공유 Edge로 추출한다. 임시 sewing으로 틈을 보정하면 원래 topology와 수정 내용을 구별하고 허용 공차/변형량을 기록한다. 멀리 떨어진 Face나 다른 층을 2D 접촉만으로 합치지 않는다. 경계의 outer/hole/component, 열린 연결/분기는 타입 있는 결과로 반환한다.

현재 WorkingCoordinateSystemNative의 BuildProjectedWorkingWire는 선택 Face sewing target 투영 기반이다. 전체 모델 query가 이미 존재한다는 이유로 검증 완료로 간주하지 않는다. 새 PrepareDesignGeometry는 선택 domain projection과 별개로 전체 모델 first-hit/연속성/장애물 검사를 실제 최종 곡선에 적용한다.

## 6. HeatingPathGeometry·DepthEnvelopeSolver

### 6.1 생성/복원 경로

입력은 작업평면 경로+표면 앵커 또는 저장된 최종 CurveDefinition이다. 두 모드를 구분한다. 복원 모드는 저장된 최종 곡선을 그대로 만들어 검증하고 생성 알고리즘을 재실행하지 않는다.

매핑은 endpoint/quarter/midpoint 적응 검사와 원본 Face trim/인접 정보를 사용한다. 샘플 기반의 좁은 특징 한계를 기록하고, 가능한 교차 검사를 보완한다. 불연속 구간을 임의 B-spline으로 연결하거나 다른 뒤 표면으로 fallback하지 않는다.

### 6.2 삽입 깊이 알고리즘

1. 표면 기준 경로 S(t), 작업축 N, 반지름 r를 준비한다.
2. 평판·접선⊥N인 분석 가능한 구간은 중심선 `S(t)-(D+r)N`을 만든다.
3. 경사/곡면 구간은 축방향 이동량 함수 h(t)를 가진 `C(t)=S(t)-h(t)N`으로 시작한다. 초기 추정이 최종 깊이 보증은 아니다.
4. 원형 단면을 중심선 접선에 수직으로 둔 실제 외피 또는 동등한 단면 envelope를 구성한다. 기준점에서 -N ray가 처음 만나는 외피까지 거리를 측정한다.
5. 오차를 기준으로 h(t)를 제한된 bracket/root refinement로 수정하고, 접선 변화/곡률/면 전환 구간을 적응 세분화한다. 전체 wire 외피가 이웃 구간의 외피와 먼저 만나는 경우도 검출한다.
6. 최종 연속 곡선으로 다시 측정한다. 최대/최소 깊이·측정 위치·근사 오차·반복 budget을 반환한다. 수렴 실패/외피 교점 없음/자기교차는 DepthUnresolved 또는 UnsupportedGeometry다.

단면 외피는 검증용 내부 형상으로 사용할 수 있으며 제품의 발열사 솔리드 출력 기능을 추가한다는 뜻은 아니다. 기본 sweep가 실패하면 조용히 D+r로 돌아가지 않는다. GEO-00에서 분석해와 교차법을 비교하고 지원 범위를 결정한다. 미지원 고곡률에서 성공을 보장하지 않는다.

곡선 끝점/Face 전환에서 G0 연속을 확인한다. 길이는 최종 TopoDS_Edge/Wire의 실제 trimmed 구간을 OCCT 곡선 적분으로 구한다. 같은 curve 정의를 표시·길이·STEP에 사용한다. 평면 폴리라인 길이나 표시 tessellation 합으로 대체하지 않는다.

솔리드는 외피가 금형 내부에 있는지와 반대쪽 표면 관통을 추가 검사한다. 부피가 정의되지 않은 열린 셸은 내부 재료 판정을 자동 확정할 수 없음을 반환하고, 확정 작업축 방향과 삽입 깊이 측정/미리보기를 유지한다. Shell이라는 타입만으로 ‘열린 형상’이라고 판정하지 않는다.

## 7. ClearanceQueries·SurfaceAreaQueries

최소 간격은 edge/curve AABB로 쌍을 줄이고 최단거리 계산 후 반지름을 빼서 보고한다. 곡선 pair의 최소점/파라미터와 수치 오차 정보를 함께 반환한다. 샘플 간 최소거리만으로 연속 곡선 간격을 보증하지 않는다.

정상 공유 접점/국소 연속부는 Design의 topology 규칙을 받아 제외한다. 하지만 멀리 떨어진 파라미터의 자기접촉, 같은 조각의 되접힘, 인접 turn segment가 다른 레인에 가까워지는 사례를 검사한다. exclusion window와 그 근거를 profile/규칙 버전에 넣고 작은 루프 fixture로 검증한다. 거리 경계가 불확실하면 재측정/실패이지 g보다 작은 값을 공차만큼 자동 허용하는 방식이 아니다.

SurfaceAreaQueries는 Face trim/포함·제외 경계로 clip된 surface patch의 실제 면적을 제공한다. 전체 Face 실면적은 BRep 기반으로, 부분 patch는 원래 surface UV trim과 면적 적분으로 계산한다. 삼각형으로 분할하더라도 chord 면적을 곧 실면적이라 하지 않고 근사/수렴 정보를 반환한다. 선택 Face가 중첩 투영될 때 보이는 유효 영역만 집계하는 정책과 일치시킨다.

Design은 nearest circuit 배정/경계 재세분화를 담당하고 Native는 patch 실면적·거리·원형 표면 정보를 제공한다. Electrical 판정이나 회로별 적용면적의 합격 회로 선택을 Native에 구현하지 않는다.

## 8. ConnectionPathGeometry

실제 깊이 적용된 발열사 끝점이 start다. 표면상 가상 시작점을 경유해 길이를 늘리지 않는다. 표면 구간→명시 출구→외부 연결부의 순서와 연속성을 검사한다. 재료 전이점은 공간 domain 전이점과 다를 수 있다.

OnMold는 선택 표면/깊이/경계 인출 규칙, External은 전체 금형 재관통/장애물 충돌 규칙을 적용한다. 출구에서의 정상적인 접촉을 허용하되 외부 구간 전체를 충돌 검사에서 제외하지 않는다. 직선/사용자 절점 경로가 막히면 충돌 위치를 반환하고 자동 우회하지 않는다.

기존 ProjectConnectionPath의 status/total/surface/external을 신규 구간 결과로 바꾸고 재료 구간별 최종 길이를 반환한다. preview와 committed map을 분리한다. preview 취소·context release가 확정 연결 경로를 지우지 않아야 한다. ConnectionPathMigrationComplete 해제는 이 경로와 전체 검증이 연결된 뒤다.

## 9. staging·장면·HLR·STEP

PreparedDesign은 모든 새 본 경로/ConnectionPath/길이/가이드 객체를 private 소유한다. 준비 실패는 후보만 해제한다. Publish 전 expected model/context/revision을 다시 확인한다. 내부 확정 geometry pointer를 교체하는 지점과 AIS redraw를 분리하고 receipt에 각각의 결과를 기록한다.

기존 CommitWorkingHeatingPathGeometry가 path/polyline만 교체하는 범위에서 경로·리드·길이·ID 맵까지 한 후보로 확장한다. 이전 객체는 확정 전까지 해제하지 않는다. 표시 시스템 실패 이후에도 새 확정 geometry에서 AIS를 재구성할 수 있어야 한다. 완전한 graphics rollback을 주장하지 않는다.

HLR은 지정 Origin/X/Y/N을 기준으로 모델 선을 반환하고 final centerline의 같은 정사영과 일치하는지 검증한다. STEP writer는 최종 곡선을 회로별 wire/compound로 작성하고 원본 포함을 옵션으로 둔다. STEPControl 계열 writer로 이름/그룹이 충분히 보존되지 않으면 같은 OccBridge 안에서 XDE 방식의 필요성을 검증하고, 사용 툴킷을 vcxproj에 명시한다. 새 제품 프로젝트를 추가하지 않는다. writer 후 재읽기 요약으로 edge/curve 수·끝점·길이를 비교한다.

## 11. 검증과 완료 기준

기존 `tests/WorkingSide.Regression/Fixtures.cpp`, `Program.cs`, `tests/PowerLead.Regression/Fixtures.cpp`, `Program.cs`를 확장한다. 공개/새 Native DTO로 검증하며 offscreen Viewer 통과를 실제 장면 품질 통과로 기록하지 않는다.

| 검사 | 기대 결과 |
|---|---|
| 다층 occluder·접선·trim 밖 surface 연장 | 가장 가까운 실제 trim hit만 인정 |
| A→B→C·비인접 전환·닫히지 않은 경계 | 연속 정상/명시 topology 실패 |
| 평판 D=0/1, 두 직경 | 외피 D, 중심선 D+r, 최종 길이 일치 |
| 경사 접선 방향 변경·곡면 seam | 외피 교차 기반 측정, D+r 일괄 적용과 구별 |
| 최소 g 경계·교차·짧은 루프·U턴 | 정상 연결 허용, 비국소 자기접촉 검출 |

| 표면 patch 구멍/반원통/경계 분할 | 실제 면적 수렴, 투영 면적 혼용 없음 |
