## 2026-10-24 보강: 단조 3차 rational B-spline 관리형 간격 fallback

비주기·양의 가중치 B-spline에서 한 좌표의 극점들이 엄격히 증가 또는 감소하면 해당 좌표 투영이 단조여서 곡선 자기접촉이 없음을 인증한다. 이 인증에 한해 차수 3~8의 매듭 구간별 적응 근사와 간격 계산을 허용한다. 비단조 2차 span은 시작·중간·끝점 비공선성이 평가 오차보다 큰 경우에만 인증하고, 단일 구간 되감김과 겹치는 인접 span은 미확정 처리한다. 비단조 고차 곡선, 주기 곡선, 차수 한도 초과도 미확정으로 남긴다. 관리형 근사 표본의 내부 접점 검사는 인증된 조각에만 생략한다. 곡선 내부가 휘는 최대 지원 8차 처리와 9차 거부, 되감김 2차 회귀를 포함한 Infrastructure 183개가 `x64/Verification/20261024-114709-c6dfb17f/run.json`에서 통과했고, Managed 전체 598개는 `x64/Verification/20261024-114728-15d5eab4/run.json`에서 통과했다.

레거시 2D 경로 타입은 영속 설계 원본으로 확장하지 않는다. 이전 기간에만 Design 내부에서 사용하고, 새 생성 유스케이스는 Core의 안정 ID·공유 절점·CurveDefinition을 반환하도록 전환한다. Core namespace 호환 façade를 둔다면 CORE-05가 끝날 때 제거한다. 오래된 배열 index와 네이티브 int ID를 영속 ID로 승격하지 않는다.

공통 후보 확정기는 가장 먼저 실패 보존을 검증할 대상이다. 다음 순서를 모델 열기·축·생성·편집·회로·연결 변경에 재사용한다.

1. 확정 프로젝트·BaseRevision·문서/축/입력 stamp를 캡처하고 입력을 검증한다. 현재 경로와 연결 상태를 먼저 지우지 않는다.
2. Design 후보를 만들고 Native의 비공개 staging에 전체 곡선·연결·길이·ID 대응을 준비한다.
3. 후보 전용 질의와 최종 GeometrySnapshot으로 하드 기하 검사·길이 원장·면적·전기 결과를 준비한다. 취소/stale/검증 실패 시 후보만 폐기한다.
4. 새 관리형 스냅샷과 결과 객체를 미리 완성하고 Publish receipt를 받는다. 확정 구간에는 사용자 callback·파일 IO·새 계산을 넣지 않는다.
5. receipt의 확정 여부에 맞춰 세션을 교체한다. 이후 장면·알림 실패는 PostCommitFailure/PresentationOutOfSync로 보고하고 확정 설계에서 장면을 재구성한다.
