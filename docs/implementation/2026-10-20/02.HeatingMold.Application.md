`IGeometryWorkspace`는 현재 네이티브 문서를 소유하는 어댑터를 감싼다. 모델/축 변경용 후보 문서와 동일 문서의 경로 후보를 준비하는 API를 구분한다. `IPreparedGeometry`는 Snapshot/Queries/Publish/Dispose를 제공한다. Core 계약에서 네이티브 핸들을 영속화하지 않는다.

## 3. 세션 상태와 변경 규칙

`ProjectSession`은 CurrentProject, LastAppliedSnapshot, CurrentInputDraft, DirtySinceSave, ActiveOperation, RuntimeDocument를 보유한다. CurrentInputDraft는 UI 편집 편의를 위한 별도 값이며 확정 프로젝트에 접근해 setter를 호출하지 않는다.

| 상태 | 허용 작업/표시 |
|---|---|
| Empty | 모델/프로젝트 열기 |
| ModelReady | 작업 좌표계 선택·면/발열 영역 설정·프로젝트 저장 |
| ConstraintsReady | 프리셋/제약·출구 측면/양 끝점 입력·생성 |
| DesignReady | 편집·회로·연결·검토·저장·최신 출력 |
| DraftPending | 기존 확정 설계 유지, 새 입력 적용/취소 필요. 최신 결과처럼 출력 금지 |
| Busy | 겹치는 변경 명령 거부/취소. OCCT 동시 실행 금지 |
| PresentationOutOfSync | 확정 데이터 유지, 장면 재구성 제공 |

이 상태들은 현재 가능한 작업을 나타내며 Undo/Redo 스택이 아니다. 같은 작업축 재선택은 no-op으로 revision·선택·연결을 바꾸지 않는다. 새 모델 열기 실패는 이전 문서 전체를 유지한다. 성공한 모델/축 변경은 상위 계획에 따라 의존 데이터를 재설정하고 새 revision을 발행한다.

## 4. 공통 후보 확정 알고리즘

`CandidateCoordinator`를 모든 기하 변경이 사용한다.

1. CurrentProject와 BaseRevision을 읽고 요청 입력을 검증한다. 이미 Busy이면 두 번째 변경을 실행하지 않는다.
2. Design 서비스에서 후보 정의를 만든다. 전체 회로·연결부 위치·연결 경로와 관련된 변경 영향 집합을 생성한다.
3. 기하 포트로 후보를 준비한다. 유효한 이전 형상을 Clear/Cancel/Reset하지 않는다.
4. 반환된 실제 GeometrySnapshot으로 기하 하드 검사·길이 원장·회로별 적용면적·전기 계산을 준비한다. 전기값 누락/초과는 결과 상태로 유지한다.
5. BaseRevision과 문서/축/입력 stamp를 재확인한다. stale 또는 취소라면 후보만 폐기한다.
6. 메모리 할당과 결과 생성을 끝낸 새 SessionSnapshot을 준비하고 Publish를 호출한다. 네이티브 확정 여부를 receipt로 받는다.
7. 확정 성공이면 준비된 관리형 스냅샷을 교체하고 Dirty=true로 한다. 이후 장면 갱신·이벤트를 실행한다.
8. precommit 실패는 기존 snapshot을 그대로 유지한다. postcommit 표시 실패는 확정 상태를 되돌리지 않고 PresentationOutOfSync로 표시하고 재구성한다.
9. finally에서 미확정 staging·preview만 Dispose한다. 이미 현 상태가 된 후보의 자원을 해제하지 않는다.

파일 저장·출력은 세션의 기하 확정과 별도 파일 트랜잭션이다. 저장 실패가 현재 설계를 폐기하지 않고 Dirty 상태를 유지한다. 저장 시작 revision과 현재 revision이 다르면 새 변경을 저장 완료로 표시하지 않는다.

재생성 요청은 `ManualEditPolicy=PreserveIfCompatible|ReplaceEditedHeatingPath`를 명시한다. Preserve 정책은 생성 원본 대비 변경된 공유 절점의 모델 좌표를 같은 레인 의미에 적용하며, 새 시작·끝 앵커는 유지한다. 내부 곡선 형상 변경, 위상/절점 대응 모호성, 연결 구간 누락은 오류로 거부하고 이전 확정 설계를 보존한다. Replace 정책은 수동 편집을 폐기하고 새 경로로 교체한다. `AssessHeatingPathRegeneration`은 정책 선택 전 초안·호환성·영향 ID를 제공한다. App은 이 평가를 경로 생성 전에 실행해 단일 영역에서 처리할 수 없는 다중 경로 변경을 차단하고, 영향 수와 편집 보존 여부를 보여준 뒤 기존 경로를 갱신한다. App 확인 콜백은 대화상자 대신 테스트 대역을 주입할 수 있다.

회로 절단 후 새 회로는 부모 Supply의 명시 입력값을 복사하되 별도 객체/ID를 가진다. 통합 시 Supply가 다르면 요청에서 사용할 Supply를 명시해야 한다. 이전 ConnectionPath 중 유지되는 ConnectionPoint 참조만 재사용하고, 회로 내부가 된 연결부 위치의 ConnectionPath는 확정 시 제거한다.

## 2026-10-23 추가 구현: 생성된 발열 경로에서 회로 연결 경로 계획
