## 1. 책임과 이전 대상

새 `src/HeatingMold.Application/HeatingMold.Application.csproj`를 `net8.0`으로 만든다. Core/Design/Electrical만 참조한다. 파일 IO, WPF Dispatcher, OccBridge, netDxf를 직접 호출하지 않는다.

| 현재 위치 | 이전할 책임 |
|---|---|
| `App/MainWindow.xaml.cs`의 `_pattern`, 선택/제외, `_turnSegmentEnabled`, 길이/연결 상태 | ProjectSession과 현재 설계 스냅샷 |
| `GenerateMultiFace`, `ApplyTurnSegmentStates`, `UpdateCircuitTable` 조합 | 생성/회로 변경 유스케이스; 계산은 각 서비스로 위임 |
| `CancelConnectionPointSetup`, pending ConnectionPoint 목록 | 연결부 위치 지정 draft 수명; 확정 ConnectionPath와 분리 |
| `MainWindow.WorkingCoordinateSystem.cs`의 ApplyWorkingCoordinateSystem/ResetWorkingCoordinateSystem | 작업 좌표계 변경 use case, 후보/확정/후처리 경계 |
| `Core/Geometry/WorkingCoordinateSystem.cs`의 WorkingCoordinateSystemSession | Sessions로 이전; UI에 미리보기 승인 단계를 새로 추가하지 않음 |

현재 `GenerateMultiFace`는 시작 시 연결 상태를 취소한다. 새 구현에서는 후보가 성공할 때까지 이전 연결·회로·계산을 그대로 보유해야 한다.

`IGeometryWorkspace`는 현재 네이티브 문서를 소유하는 어댑터를 감싼다. 모델/축 변경용 후보 문서와 동일 문서의 경로 후보를 준비하는 API를 구분한다. `IPreparedGeometry`는 Snapshot/Queries/Publish/Dispose를 제공한다. Core 계약에서 네이티브 핸들을 영속화하지 않는다.

| 포트 | 권장 진입점 | 결과/수명 |
|---|---|---|
| IGeometryWorkspace | PrepareModel(ModelSource), Prepare(DesignProject), Restore(DesignProject) | 모델/작업 좌표계/발열사 경로 후보. 성공 전 현 문서 미변경 |
| IProjectPackageStore | Read(path), Write(path, ProjectSaveSnapshot) | 읽은 DTO를 Core로 검증 매핑한 후보 / 안전한 파일 교체 결과 |
| IModelSourceStore | Capture(path), OpenRead(ModelIdentity) | 외부 STEP가 이동돼도 저장할 수 있는 세션 소유 원본 바이트/스트림 |
| IDesignExporter | Export(ExportSnapshot, ExportOptions, path) | 타입별 STEP/DXF 출력 결과와 검증 정보 |
| IOperationContext | VerifyGeometryThread(), IsCancellationRequested | App이 주입. 플랫폼 독립 테스트 가능 |
| IApplicationEvents | Publish(SessionChanged/OperationFailed/PresentationRepairNeeded) | 확정 이후만 발행; 실패가 설계 rollback을 유발하지 않음 |

기본 공개 호출 형태는 `OperationResult<SessionSnapshot> Execute(Request, CancellationToken)`이다. 파일 작업을 async로 제공하는 경우에도 네이티브 진입은 지정 UI 스레드에서 수행한다. UI 이벤트 콜백을 트랜잭션 중간에 실행하지 않는다.

## 3. 세션 상태와 변경 규칙

`ProjectSession`은 CurrentProject, LastAppliedSnapshot, CurrentInputDraft, DirtySinceSave, ActiveOperation, RuntimeDocument를 보유한다. CurrentInputDraft는 UI 편집 편의를 위한 별도 값이며 확정 프로젝트에 접근해 setter를 호출하지 않는다.

| 상태 | 허용 작업/표시 |
|---|---|
| Empty | 모델/프로젝트 열기 |
| ModelReady | 작업 좌표계 선택·면/발열 영역 설정·프로젝트 저장 |
| ConstraintsReady | 프리셋/제약·출구 측면/양 끝점 입력·생성 |
| DesignReady | 편집·회로·연결·검토·저장·최신 출력 |
| DraftPending | 기존 확정 설계 유지, 새 입력 적용/취소 필요. 최신 결과처럼 출력 금지 |
| Busy | 겹치는 변경 명령 거부/취소. OCCT 동시 실행 금지 |
| PresentationOutOfSync | 확정 데이터 유지, 장면 재구성 제공 |

이 상태들은 현재 가능한 작업을 나타내며 Undo/Redo 스택이 아니다. 같은 작업축 재선택은 no-op으로 revision·선택·연결을 바꾸지 않는다. 새 모델 열기 실패는 이전 문서 전체를 유지한다. 성공한 모델/축 변경은 상위 계획에 따라 의존 데이터를 재설정하고 새 revision을 발행한다.

## 4. 공통 후보 확정 알고리즘

`CandidateCoordinator`를 모든 기하 변경이 사용한다.

1. CurrentProject와 BaseRevision을 읽고 요청 입력을 검증한다. 이미 Busy이면 두 번째 변경을 실행하지 않는다.
2. Design 서비스에서 후보 정의를 만든다. 전체 회로·연결부 위치·연결 경로와 관련된 변경 영향 집합을 생성한다.
3. 기하 포트로 후보를 준비한다. 유효한 이전 형상을 Clear/Cancel/Reset하지 않는다.
4. 반환된 실제 GeometrySnapshot으로 기하 하드 검사·길이 원장·회로별 적용면적·전기 계산을 준비한다. 전기값 누락/초과는 결과 상태로 유지한다.
5. BaseRevision과 문서/축/입력 stamp를 재확인한다. stale 또는 취소라면 후보만 폐기한다.
6. 메모리 할당과 결과 생성을 끝낸 새 SessionSnapshot을 준비하고 Publish를 호출한다. 네이티브 확정 여부를 receipt로 받는다.
7. 확정 성공이면 준비된 관리형 스냅샷을 교체하고 Dirty=true로 한다. 이후 장면 갱신·이벤트를 실행한다.
8. precommit 실패는 기존 snapshot을 그대로 유지한다. postcommit 표시 실패는 확정 상태를 되돌리지 않고 PresentationOutOfSync로 표시하고 재구성한다.
9. finally에서 미확정 staging·preview만 Dispose한다. 이미 현 상태가 된 후보의 자원을 해제하지 않는다.

파일 저장·출력은 세션의 기하 확정과 별도 파일 트랜잭션이다. 저장 실패가 현재 설계를 폐기하지 않고 Dirty 상태를 유지한다. 저장 시작 revision과 현재 revision이 다르면 새 변경을 저장 완료로 표시하지 않는다.

## 5. 유스케이스별 구현

| 요청 | 처리 | 성공 시 영향 / 실패 시 |
|---|---|---|
| OpenModel | 원본 capture→후보 load→기본 +Z 작업 좌표계→소유권 교체 | 새 모델/빈 설계 / 이전 모델 유지 |
| ChangeWorkingAxis | 동일 축 no-op, 그 외 작업 좌표계/장면 후보 준비 | 선택·영역·앵커·경로·회로·연결·계산 재설정 / 이전 전체 유지 |
| UpdateRegion | Face 참조→통합 루프→포함/제외 검증 | 재생성이 필요한 draft와 이전 결과 구별 / 추출 오류 위치 |
| GenerateHeatingPath | 지정 방향/양 끝점→DES-04 후보→매핑/깊이→공통 검사 | 신규 경로·회로·파생 결과 원자 교체 / 연결 포함 이전 상태 유지 |
| MoveControlPoint | ID 기반 공유 접점 변경→영향 조각 재매핑 | 최소 간격·동일 측면 통과 시 교체 / 이전 위치 복원 |
| ChangeCircuitTopology | TurnSegment ID/활성 또는 통합 대상→성분/연결부 위치/Supply 대응 | 새 회로 전부 동일 출구 측면 검증 / 불가능 조정과 사유 제공 |
| UpdateConnectionPath | ConnectionPoint/절점/재료 전이/여유 입력 | 확정 시만 길이·전기 변경 / preview 취소는 영향 없음 |
| RecalculateElectrical | 새 Supply/저항, 형상 stamp 일치 확인 | 형상 재사용, 전기·전기 조건 만족 적용면적·사양표 갱신 |
| SaveProject | 확정 저장 snapshot+원본 바이트→패키지 writer | 성공한 revision의 저장 상태만 갱신 |
| OpenProject | ZIP 검증→모델 후보→Face 대응→최종 편집곡선 복원→검증 | 길이/좌표 일치 확인 후 교체 / 기존 문서 유지 |
| ExportDesign | draft/stale/기하 오류 검사→같은 revision ExportSnapshot | preview·비활성 제외, 한도 초과/계산불가는 상태 표기 |

재생성 시 수동 편집의 ControlPointId/anchor/생성 원본 대응을 확인한다. 위상이 바뀌면 index로 이동량을 재적용하지 않는다. 요청에 명시된 `ManualEditPolicy=PreserveIfCompatible|ReplaceEditedHeatingPath`를 사용한다. 호환 불가 시 `AmbiguousCircuitMapping` 또는 편집 대응 오류를 반환하고 기존 설계를 유지한다. UI가 구체적인 영향과 재생성 선택을 보여준다.

회로 절단 후 새 회로는 부모 Supply의 명시 입력값을 복사하되 별도 객체/ID를 가진다. 통합 시 Supply가 다르면 요청에서 사용할 Supply를 명시해야 한다. 이전 ConnectionPath 중 유지되는 ConnectionPoint 참조만 재사용하고, 회로 내부가 된 연결부 위치의 ConnectionPath는 확정 시 제거한다.

## 8. 테스트 및 완료 기준

`tests/HeatingMold.Application.Tests`에서 fake Design 결과와 IGeometryWorkspace/IPreparedGeometry/저장 포트를 주입한다. 구현 호출 횟수만 확인하는 테스트 대신 이전/이후 상태·ID·길이·계산·자원 수명을 비교한다.

| 검사 | 기대 결과 |
|---|---|
| 생성 도중 매핑/삽입 깊이/간격 실패 | 기존 발열사 경로·회전 연결 구간·연결 경로·길이·전기 snapshot 동등, revision 불변 |
| prepare 이후 다른 revision 또는 취소 | publish 미실행, staging 해제, 현재 상태 유지 |
| publish 전 실패 | 이전 네이티브 상태 유지; 후보 Dispose 한 번 |
| publish 후 알림/장면 실패 | 새 설계 유지, PostCommitFailure와 장면 복구 요청 |
| 같은 작업축 재선택 | 선택/수동 편집/회로/Supply 보존 |
| 모델 열기 또는 프로젝트 복원 실패 | 이전 문서/모델/장면 유지 |
| preview 20회 후 취소 | 확정 ConnectionPath·길이·전기값 불변 |
| 전압만 변경 | 형상 불변, 새로운 전기/전기 조건 만족 적용면적 stamp |
| 분할/통합 Supply 충돌 | 명시 선택 없는 통합 거부, 임의 한도 채택 금지 |
| 저장 실패/저장 중 새 변경 | Dirty 유지, 잘못된 revision을 저장 완료로 표시하지 않음 |
| 미적용 draft 또는 stale 전기 | 최신 출력 거부; 명확한 재계산 이유 |
| 최신 전기 한도 초과 결과 | 설계 보존, 사양표에 초과 판정 전달 |

```powershell
dotnet test tests/HeatingMold.Application.Tests/HeatingMold.Application.Tests.csproj -c Release
```
