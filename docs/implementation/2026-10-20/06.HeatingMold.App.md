# HeatingMold.App 상세 구현계획

작성일: 2026-10-20  
선행: [공통 계약](00.Shared.Contracts.md), APPFLOW-01/02, INF-01, OCC-01  
목표: 합의한 설계 순서를 WPF 화면으로 제공하고 Viewer 입력·표시·서비스 조립과 실행 패키지를 책임진다.

## 1. 경계와 기존 파일

`src/HeatingMold.App`은 `net8.0-windows`, WPF, x64를 유지한다. Application/Infrastructure/Core를 사용하고, Design/Electrical 구현 연결은 조립 위치에서만 한다. OccBridge 직접 호출은 Viewer와 시작 시 런타임 준비에 한정한다. MainWindow가 경로·전기·직렬화를 계산하지 않는다.

| 현재 파일/영역 | 변경 |
|---|---|
| `MainWindow.xaml/.cs` | Views/MainWindow, ViewModels와 유스케이스 바인딩으로 분리 |
| `MainWindow.WorkingSide.cs` | 작업축 변경은 Application; 카메라/선택 표시는 Viewer |
| `OccViewport.cs` | HwndHost/Win32 수명은 유지하고 입력 모드/preview 조합 분리 |
| `OcctEnv.cs` | 개발 저장소 탐색과 배포 폴더 런타임 탐색을 구분 |
| `App.xaml.cs` | CompositionRoot를 호출하고 종료 시 문서/뷰어 순서대로 Dispose |
| `WorkingRouteMigrationComplete=false` | UI-04/OCC-06 검증 전 유지; 단순 true 전환 금지 |

## 3. 작업 순서와 화면 계약

화면은 다음 순서를 안내하되 이미 유효한 설계에서는 필요한 단계로 돌아가 수정할 수 있다.

1. STEP/프로젝트 열기, 원본 이름·작업축 표시.
2. Face 클릭/Ctrl 토글/사각 선택, 포함/제외/취소, 유효 영역/구멍/성분 표시.
3. Case/재료/직경/r, 외곽 최소 간격 g, 중심 피치 파생 표시, 경계 마진, 외피 깊이 D.
4. 공통 인출 측면, 시작/종료 앵커, 작업축 기준 가로/세로 지정.
5. 자동 생성과 생성 실패 위치·이유 확인.
6. 꼭지점 이동, 커넥터 절단/연결, 회로 통합, 단자/접속 절점/재료 전이 설정.
7. 회로별 전원·길이·R/I/P·한도, 담당면적, 간격 편차/문제 위치 검토.
8. `.hmproj` 저장/다른 이름 저장, STEP/DXF 출력.

필드 레이블에서 ‘외곽 간격(mm)’과 ‘중심 피치(mm, 계산값)’, ‘외피까지 깊이(mm)’, ‘실제 인가전압(V RMS)’과 ‘최대전압(V)’을 분리한다. 화면 선 두께를 직경 입력으로 사용하지 않는다. `D=0`은 외피가 표면에 닿는 새 기준임을 간단한 도움말로 제공한다.

선택 Face가 여러 성분이면 임의 병합하지 않고 생성할 영역 조정이 필요한 이유를 표시한다. 구멍/제외 관통 실패는 위치와 사용자 조정 방법을 표시한다. 전기 한도 초과는 빨간/경고 색만이 아니라 수치와 텍스트로 표시한다.

프리셋을 명시적으로 선택했을 때만 제원/예시 전원을 채운다. 사용자가 MaximumVoltage만 편집했다고 ActualVoltage를 자동 추정하지 않는다. 각 회로의 Supply 입력은 별개이며 표의 총전류를 16A와 비교하는 UI를 만들지 않는다.

## 4. Viewer와 입력 모드

`ViewerMode`는 `Navigate`, `SelectFaces`, `IncludeRectangle`, `ExcludeRectangle`, `PickExitSide`, `PickStart`, `PickEnd`, `MoveControlPoint`, `EditConnector`, `PickLeadWaypoint`, `PickConnectionPoint`를 구분한다. 한 번에 하나의 설계 입력 모드만 활성화한다. 카메라의 pan/zoom은 가능한 모드에서 유지하되 진행 중 preview를 취소/다시 계산하는 정책을 일관되게 적용한다.

| 동작 | 입력·출력 규칙 |
|---|---|
| Face 선택 | 화면좌표→Viewer pick→세션 FaceRef. UI가 네이티브 번호를 영속 ID로 저장하지 않음 |
| 측면/양 끝점 | 경계 구간 ID·SurfaceAnchor를 받음. 화면 좌우 문자열만 저장하지 않음 |
| 꼭지점 이동 | 실제 ControlPoint ID만 pick. 샘플점이나 AIS 표시 index를 편집 ID로 사용하지 않음 |
| connector click | RoutePieceId를 명령에 전달. turn index 계산을 ViewModel에서 재구현하지 않음 |
| 실제 연결부 | 표면점과 External XYZ를 구별. 사용자 작업 평면/직접 좌표 입력으로 외부 연결점 지정 가능 |
| 회로 hover | snapshot의 회로 조각 ID 집합을 Viewer에 전달해 highlight. 회로 계산은 하지 않음 |

`OccViewport`의 Win32 client pixel과 WPF DIP 변환을 PickingAdapter 한 곳에서 처리한다. DPI 변경·모니터 이동·창 크기에서 HwndHost 실제 크기로 resize하고 동일 pick 좌표계를 사용한다. 현재 4px drag threshold도 장치 픽셀인지 DIP인지 정해 일관되게 변환한다.

### 4.1 드래그/preview

마우스 down에서 BaseRevision/원래 절점/모드를 캡처하고 capture를 건다. move는 최신 요청만 묶어 preview한다(초기 최대 약 30Hz, UI dispatcher 기준). 오래된 요청/다른 revision 응답은 표시하지 않는다. preview는 확정 접속/길이/계산 표를 갱신하지 않는다.

마우스 up에서 Application의 최종 명령을 호출하고 공통 검증을 거친다. 실패하면 preview만 지우고 확정 장면으로 돌아간다. Esc, capture lost, 창 비활성, 모델/축 변경, 모드 전환, 종료 때 preview·예약 callback을 취소한다. late-hover callback이 취소 후 lead를 다시 만들지 않게 세대 토큰을 사용한다.

### 4.2 표시 수명

확정 장면은 GeometrySnapshot/SessionSnapshot에서 다시 만들 수 있어야 한다. Viewer는 표시 객체만 소유하고 계산 원본이 아니다. context 해제 전에 해당 문서의 highlight/preview/AIS를 제거한다. PresentationOutOfSync이면 재구성 명령과 실패 상태를 제공한다. 드라이버 실패를 이미 확정된 설계 실패로 표시하지 않는다.

## 5. ViewModel·결과 표시

ViewModel은 Application SessionChanged를 받아 한 snapshot에서 패널·표·상태·명령 활성화를 갱신한다. `_pattern`, `_turnEnabled`, `_leadLengths`와 같은 중복 설계 원장을 보유하지 않는다. CollectionView 행 모델은 Core 결과를 표시용으로 투영한 값이다.

| 표/패널 | 필요한 필드 |
|---|---|
| 조건 | 프레임/모델, 선택 Face 수, g/d/pitch/D/방향/측면/앵커 상태 |
| 회로 | 표시 번호+stable ID, 조각 수, 양 끝점/같은 측면 상태, 접속 설정 여부 |
| 길이 | 본 경로, 발열사 연장, 별도 리드, 재료별 추가 여유, 저항 대상 길이 |
| 전기 | 실제/최대 V, I/MaxI, P/optional MaxP, R, 판정과 누락 항목 |
| 면적 | 총 실제 면적, 회로 담당면적, 전기 조건 만족 면적, 미배정/근사 상태 |
| 검증 | code/설명/대상/위치/측정값/기준. 행 선택 시 해당 3D 위치 강조 |

미적용 입력은 ‘미적용’으로 표시하고 기존 결과에는 해당 revision을 붙인다. 생성 실패 후 새 입력과 옛 결과가 섞여 최신인 것처럼 보이지 않게 한다. 재생성 시 수동 편집이 호환되지 않으면 영향 목록과 현재 편집 보존/새 생성 선택을 제공한다. Undo/Redo 버튼·Ctrl+Z/Y·커넥터 이력은 추가하지 않는다.

파일 대화상자는 STEP 열기/프로젝트 열기를 구분하고 저장은 `.hmproj`, 출력은 STEP/DXF로 구분한다. 경로 선택 이후 실제 쓰기는 Application 포트로 위임한다. 저장/출력 실패는 현재 설계를 유지한다. 시작 시 `resource/Mold.stp` 자동 탐색은 개발 편의에 한정하고 배포 실행에서 저장소 경로를 필수로 요구하지 않는다.

## 6. 빌드 재편과 격리 러너: UI-01

App 담당이 솔루션/공용 빌드 파일의 변경을 모아 처리하고 각 프로젝트 담당은 자신의 패키지/소스를 제공한다.

UI-01은 01a(빈 프로젝트/포트 참조 연결)와 01b(실제 구현 빌드·격리 회귀)로 나눈다. 각 모듈 담당은 자신의 전체 선행 기능 완료를 기다리지 않고 csproj/폴더/최소 공개 타입 선언을 01a에 먼저 제공한다. DES-01/INF-01 등의 UI-01 선행은 01a를 뜻하며, 전체 회귀는 01b에서 마친다. 이를 통해 프로젝트 생성과 솔루션 연결이 서로 완료를 기다리는 순환을 피한다.

1. 6개 C# 제품 프로젝트/OccBridge와 테스트 참조를 솔루션에 등록하고 구 Export를 제거한다.
2. 현재 OccBridge는 Release|x64만 정의되어 있다. 처음에는 실제 지원되는 Release|x64를 공식 전체 빌드로 정리한다. 동작하지 않는 Debug/AnyCPU/x86 매핑을 성공 구성처럼 남기지 않는다. Debug 지원을 추가하면 native 설정과 런타임까지 별도 검증한다.
3. `NativeBridgeAssembly`/`NativeBridgeOutputDir` MSBuild 속성을 도입한다. 기본 Release 경로와 override를 App/Infrastructure/회귀 프로젝트 모두 사용한다. 고정 HintPath 때문에 새 DLL이 오래된 DLL로 덮이는 문제를 제거한다.
4. `scripts/Verify.ps1`가 `x64/Verification/<run-id>/{native,app,tests,fixtures,logs}`를 만든다. 프로젝트별 C++ IntDir/관리형 obj 경로를 분리해 산출물 충돌을 막는다.
5. 네이티브→관리형→fixture→회귀 순으로 빌드하고 모든 프로세스에 같은 BridgeAssembly/OCCT resource/PATH를 전달한다. 테스트 csproj의 고정 `PowerLeadBuild`/`WorkingSideBuild` HintPath도 override 가능하게 바꾼다.
6. MSBuild는 vswhere/설정 가능한 경로로 찾고 기존 VS 2022 Community 경로를 fallback으로 쓴다. OCCT는 현재 third_party 위치를 우선한다. 실패를 환경/기능으로 구분해 로그에 기록한다.
7. 실행 중 Viewer 프로세스를 종료하지 않고 DLL 잠금을 피한다. 삭제/이동은 확인된 해당 run 디렉터리에 한정한다.

목표 실행 인터페이스는 다음과 같다(스크립트 구현 후 사용).

```powershell
& ./scripts/Verify.ps1 -Configuration Release -Platform x64 -Group All
& ./scripts/Verify.ps1 -Configuration Release -Platform x64 -Group Native
```

기존 Run.ps1는 공통 러너로 위임하거나 동일 속성을 사용하도록 고친다. 회귀의 private MainWindow handler reflection은 신규 Application 테스트와 공개 Viewer 검증으로 옮기되 실제 행동·실패 보존 검사를 삭제하지 않는다.

## 7. 배포: UI-07

`scripts/Publish.ps1`는 Release/win-x64를 `PublishSingleFile=false`로 폴더 출력한다. .NET 런타임은 self-contained 배포를 우선 검증한다. C++/CLI 혼합모드에서 필요한 ijwhost, OccBridge, OCCT/그 종속 DLL, OCCT 리소스를 함께 복사한다. 한 exe로 합치는 방식은 이 계획에 포함하지 않는다.

`scripts/Package.ps1`는 실행 폴더·설치/실행 안내·버전/파일 목록·필요 VC++ 런타임 안내를 ZIP 설치 묶음으로 만든다. VC++ 런타임 준비 방식은 실제 배포 환경에서 검증하고 개발용 PATH/third_party/VS가 없는 PC에서도 실행해야 한다. 조직이 특정 설치 프로그램 형식을 요구하면 동일 publish 폴더를 입력으로 포장한다. 새 설치 도구 도입 때문에 기하/설계 모듈을 바꾸지 않는다.

앱 데이터/로그/임시 프로젝트는 쓰기 가능한 사용자 경로에 저장한다. 설치 폴더에 output 폴더를 강제 생성하지 않는다. 설치/시작 시 개발 저장소를 탐색하지 않아도 되도록 runtime resources를 실행 폴더 기준으로 해결한다.

## 9. 검증과 완료 기준

| 검사 | 기대 결과 |
|---|---|
| 로드·기본 +Z·축 변경/같은 축 no-op | 기존 회귀 동작 유지; 실패한 축 변경은 기존 선택/설계 유지 |

| 20회 preview 후 Esc/모드 변경/close | 확정 길이·전기 불변, transient AIS/callback 제거 |
| 최소 간격 미달 drag drop | 기존 절점 복원, 수치/위치 오류 표시 |
| 회로 hover/절단/통합 | 같은 snapshot으로 highlight/표/단자 갱신 |
| 실제 연결부가 발열면 밖 | 외부 XYZ 입력 가능, 관통 실패 위치 표시 |
| 오래된 결과/미적용 조건 | 명확한 상태, 최신 출력 차단 |
| graphics postcommit 실패 | 확정 설계 유지, 장면 재구성 가능 |

자동검사는 공통 Verify 러너로, 실제 장면/DPI/외부 CAD/설치는 수동으로 검사한다. ViewModel 단위검사는 입력·상태 전이의 의미 있는 경계만 추가하고 단순 바인딩/XAML 스냅샷 테스트를 남발하지 않는다.

완료 시 code-behind는 UI 이벤트→명령 전달과 플랫폼 수명만 담당한다. native 전원 경로 gate는 검증이 완료된 기능만 해제하며, 기존 gate 검사도 새로 구현된 정상/실패 동작 검사로 교체한다. Undo/Redo 제거 상태를 유지한다.
