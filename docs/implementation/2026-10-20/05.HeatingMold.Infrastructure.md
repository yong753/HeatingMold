## 2026-10-24 보강: STEP 원본 스트림과 패키지 메모리 복사 축소

`ModelSource.CaptureFromStream`과 `ReadFromStream`이 스트림을 정확한 길이의 소유 배열에 직접 읽어 해시를 검증한다. `StepModelSourceStore`는 파일 전체를 먼저 읽고 다시 복사하던 경로를 취소 가능한 스트림 캡처로 바꿨다. `.hmproj` 저장도 `ModelBytes.ToArray()` 없이 원본 메모리를 ZIP에 청크로 쓰며, 임시 패키지 검증은 STEP 압축 해제 스트림의 길이와 SHA-256을 청크 단위로 확인한다. 패키지 receipt 길이와 SHA-256은 임시 파일에서 취소 가능하게 계산하고 교체 전에 확정한다. Infrastructure 185개와 Managed 전체 602개(Core 41, Design 108, Electrical 22, Application 72, Infrastructure 185, App 174)가 한글 XML summary 3,904개 검사와 함께 `x64/Verification/20261024-122045-8b56bbdf/run.json`에서 통과했다. 큰 모델을 디스크 기반 세션 임시 저장소로 보관하고 세션 종료 시 제거하는 요구는 아직 남아 있다.

## 2026-10-24 보강: 큰 유한 깊이 envelope의 중간값 계산

`CurveDepthEnvelopeCalculator`가 중점 깊이와 대표 깊이를 `(a + b) / 2`로 계산하던 경로를 부호 분기형 안정 중점 계산으로 바꿨다. 좌표·깊이 규모를 합쳐 반올림 오차를 추정하던 계산도 각 항을 machine epsilon으로 먼저 축소해 overflow를 막는다. `1.3e308`부터 `1.5e308`까지 증가하는 가짜 first-hit 깊이를 이용한 Infrastructure 회귀가 전체 곡선 최소·최대·대표 깊이와 오차가 유한하게 유지되는지 확인한다. Infrastructure 184개를 포함한 Managed Release/x64 전체 601개가 `x64/Verification/20261024-120752-445b7756/run.json`에서 통과했다.

## 2026-10-24 보강: 단조 고차 유리 B-spline 간격 fallback

비주기·양의 유리 가중치 B-spline은 차수 3~8이라도 한 좌표의 극점이 엄격히 단조로우면 해당 좌표 투영의 단조성을 이용해 자기 접촉이 없음을 인증한다. 이 조건에서 매듭 구간별 오차 상한 근사와 선분 간격 계산을 허용하고, 인증된 근사 조각의 내부 표본 접촉 검사는 생략한다. 어느 축도 단조롭지 않은 3차 이상, 차수 8 초과, 주기 곡선은 미확정이다. 비단조 2차 구간은 시작·중간·끝점의 비공선성이 평가 오차보다 큰 경우만 근사하며, 단일 구간 되감김이나 겹치는 인접 구간은 미확정으로 반환한다. 증가·감소 극점, 비균등 가중치, C0 다중 구간 3차, 단일 구간 되감김 2차, 최대 지원 차수 8과 차수 초과 거부 회귀를 추가했다. Infrastructure 183개가 `x64/Verification/20261024-114709-c6dfb17f/run.json`에서 통과했고 Managed 전체 601개는 `x64/Verification/20261024-120752-445b7756/run.json`에서 통과했다. 이 fallback은 제한된 관리형 근사이며 Native exact OCCT 결과를 대체하지 않는다.

## 2026-10-24 보강: STEP·DXF 원자 출력 receipt 경계 통일

## 2026-10-24 추가 구현: 비주기 유리 B-spline 최소 간격 fallback

`OcctGeometryQueries.MeasureClearance`는 Native 브리지가 없고 입력에 지원하는 비주기 유리 B-spline이 있으면 `BSplineCurveClearanceCalculator`를 사용한다. 매듭 구간별 곡률 상한에 맞춰 현을 세분하고, 유리 평가·매듭 위치·곡선 근사 오차를 거리 결과의 오차 한도에 포함한다. 선분 수·평가 횟수·전체 표본 수와 재귀 깊이에 상한을 둔다. 1차 구간은 정확한 선분 쌍으로 비국소 교차를 검사한다. 2차 구간은 각 span의 비퇴화 인증과 인접 매듭 경계 AABB 검사로 자기접촉 가능성을 제한하고, 차수 3~8은 극점 좌표 하나가 엄격히 단조인 경우에만 허용한다. 주기 곡선, 비단조 고차 곡선, 원호와 B-spline 혼합, 선언된 B-spline 연결 끝점은 추가 접촉을 배제할 수 없어 `Unresolved`다. 취소·잘못된 trim·끝점 불일치와 오차 예산 초과도 성공 없이 반환한다.

회귀는 유리 2차 단일·다중 knot 구간 간격과 되감김 자기접촉, 1차 B-spline의 비국소 자기교차, 단조·비단조 3차 처리, 곡선 내부가 휘는 8차 상한과 9차 거부, 주기 곡선, 선언 연결점, 원호 혼합과 엄격한 오차 예산 초과를 검사한다. knot 구간 적응 근사는 `BSplineCurvePolylineApproximator`에, 곡선 간 간격 결과 조립은 `BSplineCurveClearanceCalculator`에 둔다. 최신 Infrastructure 184개와 Managed 전체 601개가 각각 Managed 통합 기록 `x64/Verification/20261024-120752-445b7756/run.json`에서 통과했다. 실제 Native 경로는 OCCT exact edge 질의를 우선 사용하며, 이번 관리형 검증은 C++/CLI 빌드와 Native 형상 결과를 검증하지 않는다.

App 어댑터가 이 DTO를 `CurveDefinitionData`로 복사하고 OccBridge의 정확 곡선 투영 staging API가 소비한다. 해당 Native 경로의 빌드·실행 검증은 도구 환경이 확보된 뒤 수행한다. 확정 설계 DXF는 밀리미터 단위를 기록하고, 외부 연결점에 회로 순번·시작/끝 라벨을 표시하며 회로별 길이 원장·전기 한도·적용면적을 편집 가능한 `LINE`/`TEXT` 표로 출력한다. 미계산 값은 0이나 합격으로 치환하지 않는다. 패키지는 상위 경로와 중복 항목도 거부한다. 임시 패키지와 DXF 파일은 교체 전에 검증·임시 저장한다. 현재 패키지는 권위 있는 설계와 원본 STEP만 저장하며 기하·면적·전기 cache는 복원 과정에서 다시 계산해야 한다. Core는 OCCT B-spline 구성 조건에 맞춰 내부 knot, 주기 경계 중복도, 극점 수와 중복도 합을 검증한다. 2026-10-23 Managed 검증에서 Core 35개와 Infrastructure 40개를 포함해 전체 208개가 통과했다.

Infrastructure에는 `.hmproj` 저장소, 원본 STEP 캡처, 곡선 정의 매퍼, first-hit/선택 topology/표면 요소 어댑터, 설계 DXF·STEP writer와 HLR 정사영 writer가 있다. 곡선 간격은 관리형 line/polyline/arc 계산을 제공하고, 비주기 유리 B-spline은 비퇴화 2차와 한 좌표가 단조인 3~8차 범위에서 제한적으로 근사한다. Native bridge가 있으면 exact OCCT edge 질의를 우선하며, Native가 미확정한 B-spline도 관리형 지원 조건을 만족할 때만 fallback 성공으로 바꾼다. 주기·비단조 고차 곡선, 축퇴 2차, 반복 원호와 추가 교차 가능성이 있는 공유 끝점은 여전히 `Unresolved`다. 주기 곡선 깊이와 연결 장애물 Native 질의는 실제 bridge 실행 검증이 남아 있다. Native `GeometryWorkspace`와 준비/확정 기하 어댑터는 WPF `OcctGeometryWorkspace`까지 연결됐으며, `.hmproj` 저장·복원과 확정 설계 export도 WPF 명령에서 사용할 수 있다. 최신 Managed Release/x64 602개는 `x64/Verification/20261024-122045-8b56bbdf/run.json`에서 통과했다. C++/CLI `MSBuild.exe`가 없어 새 Native 코드와 제품 Native/App 빌드는 컴파일·실행 검증되지 않았다. 이 문서의 아래 절은 완료된 요구사항과 구현 대기 항목을 모두 포함한 목표 설계다.

## 2. Geometry.Occt 어댑터

### 2.1 브리지 변환과 수명

현재 API의 flat double 배열을 BridgeDtoMapper 한 곳에서 해석한다. 예를 들어 `WorkingSurfaceContext.Frame`은 origin/X/Y/N 12개, `HeatingPathSegmentResult`는 길이/시작/끝이며 `ProjectConnectionPath` 배열은 status/total/surface/external 길이다. 크기·유한값·단위·상태를 확인하고 모호한 실패 배열을 정상 결과로 변환하지 않는다. 신규 API는 의미 있는 브리지 DTO로 교체한다.

RuntimeIdMap은 Guid 기반 HeatingPathSegmentId/ConnectionPathId/FaceRefId와 세션 정수 ID를 대응시킨다. 새 문서를 열면 맵을 새로 만든다. staging/final/preview ID 공간을 구별하고 네이티브 핸들이 JSON DTO로 흘러가지 않도록 한다.

`OcctGeometryWorkspace`는 UI 스레드 소유권을 확인한 뒤 Bridge를 호출한다. `PreparedOcctGeometry`는 staging 후보를 소유하며 Dispose는 아직 확정되지 않은 자원만 폐기한다. Publish receipt가 Committed이면 후보 해제가 active geometry를 지우지 않게 한다. 맵·형상·길이·표시를 서로 다른 시점에 부분 교체하지 않는다.

### 2.2 기존 API 이전

| 현재 API | 새 어댑터에서의 처리 |
|---|---|
| LoadStep/CreateWorkingSurfaceContext | 후보 문서 모델/작업 좌표계 준비로 감싸기; 성공 전 기존 모델 보존 |
| QueryWorkingSurfaceForFaces | 전체 모델 first-hit 결과/선택 소속 변환; 발열사 경로/편집/연결 경로에서 공통 사용 |
| GetSelectedRegionBoundary | 루프/공유 Edge/성분이 구별되는 새 topology DTO 소비 |
| StageProjectedWorkingPathSegment | legacy 선택면 투영·중심선 이동 의미를 신규 삽입 깊이 API로 대체 |
| Commit/DiscardWorkingPathGeometry | 발열사 경로+연결 경로+길이 snapshot 원자 교체 포트로 확장 |
| ProjectConnectionPath | 실제 시작점·전이·작업축·장애물 검증이 있는 신규 ConnectionPath API로 이전 |
| HlrEdges | 프레임 origin/X/Y/N과 단위가 명시된 투영 결과로 변환 |

`BuildProjectedWorkingWire`가 선택 Face sewing target만 투영하는 현 경로를 새 first-hit 검증 완료로 간주하지 않는다. OCC-04/05 결과를 통해 실제 최종 곡선 검사까지 연결한다.

### 2.3 Face/곡선 복원

FaceReferenceResolver는 원본 해시 일치 후 가져오기 힌트 번호의 특징을 확인한다. 틀리면 전체 특징 후보를 찾되 유일한 대응일 때만 사용한다. 재선택이 필요하면 AmbiguousFaceReference와 대상 목록을 반환한다. 사용자가 재선택할 때는 새 anchor/영역/경로를 검증하는 명시적 변경 유스케이스를 거친다.

CurveDefinitionMapper와 `CurveDefinitionBridgeDto`는 line/polyline/arc/BSpline 원형 정의를 표본화 없이 wire 형식으로 왕복한다. poles만 저장하고 knots/weights를 누락하거나 모든 곡선을 표시 샘플로 재보간하지 않는다. DTO는 App 어댑터와 OccBridge의 exact curve staging API에 연결했고, 관리형 DTO 테스트는 통과했다. Native 빌드/실행 검증은 MSBuild 부재로 아직 수행하지 못했다. 다음 단계에서는 복원 끝점·연속성·총길이를 저장 cache와 비교하고, 불일치가 허용 수치 설정을 넘으면 cache를 폐기하고 오류/재검증 상태로 돌린다.

## 3. Persistence: .hmproj v1

### 3.1 패키지 wire 형식

필수 entry는 아래 세 개다. 원본 STEP의 파일명/대소문자가 달라도 패키지 내부 경로는 고정한다. 원본 내용을 STEP writer로 재생성하지 않고 capture한 바이트 그대로 보관한다.

```text
design.hmproj
  manifest.json
  project.json
  source/model.step
```

`manifest.json` 예시는 다음과 같다. 해시는 실제 값으로 기록한다.

```json
{
  "fileType": "HeatingMoldProject",
  "packageVersion": 1,
  "projectSchemaVersion": 1,
  "units": { "length": "mm", "area": "mm2" },
  "project": { "path": "project.json", "sha256": "<sha256>" },
  "source": { "path": "source/model.step", "sha256": "<sha256>" },
  "producer": { "applicationVersion": "<version>", "geometryVersion": "OCCT-7.9.3" }
}
```

`project.json`의 최상위 구조는 공통 계약 2절을 따른다. DTO는 camelCase, enum은 안정 문자열, Guid는 정규 문자열, 시간은 UTC ISO 8601로 저장한다. 숫자는 문화권과 무관한 JSON number이고 비유한값은 거부한다. 단위 정보와 DepthReference를 생략하지 않는다.

| DTO 묶음 | 반드시 보존할 데이터 |
|---|---|
| source/workingCoordinateSystem | 해시, 원래 단위 변환, importer 버전, Face 특징, 영속 작업 좌표계 |
| heatingRegions/constraints | 선택·외곽/홀·포함/제외·출구 측면·양 끝점·g/d/삽입 깊이/경계 여유/방향 |
| heatingPaths | 생성 원본과 현재 편집 곡선, 공유 절점, stable ID, 활성 상태 |
| circuits/connectionPaths | 소속/순서/방향, 연결부 위치, 실제 경로 끝점, 재료 전이/외부 구간, 회로별 Supply |
| rules/derivedCache | 규칙·수치 profile, 길이/전기/적용면적/검증 결과와 근거 stamp |

DTO의 runtime handle/context/pointer/AIS/HWND/절대 원본 경로는 제외한다. 사용자 파일명은 메타데이터로 선택 보관하되 재열기에 외부 원본 경로를 요구하지 않는다. 계산 cache는 권위 있는 수동 편집 정의를 대신하지 않는다.

### 3.2 저장 알고리즘

1. Application이 확정 ProjectSaveSnapshot과 source stream을 전달한다. 읽는 동안 snapshot을 바꾸지 않는다.
2. target과 같은 디렉터리에 유일한 임시 파일을 만든다. ZIP entry 중복을 만들지 않는다.
3. source 해시를 확인하며 원본 STEP를 기록하고 project JSON을 직렬화한다. 각 entry의 해시를 manifest에 쓴다.
4. ZIP를 닫고 flush한다. 임시 파일을 다시 열어 필수 entry/manifest/JSON/schema/해시를 검증한다.
5. 기존 파일이 있으면 같은 볼륨의 안전한 replace, 없으면 rename/move로 최종 이름에 놓는다. replace 실패 시 기존 파일을 지우고 재시도하는 fallback을 쓰지 않는다.
6. 실패는 임시 자원만 정리하고 기존 target과 현재 설계는 유지한다. 성공한 저장 revision/path를 Application에 반환한다.

원본 파일이 세션 중 외부에서 삭제되어도 저장할 수 있도록 `StepModelSourceStore`가 열기 성공 시 원본을 소유한다. 64 MiB까지는 메모리에 보관하고 그보다 큰 원본은 세션 소유 임시 파일에 청크 단위로 기록한다. 원본은 최대 1 GiB로 제한하며 `OpenRead`와 `CopyTo`로 파일 경로를 노출하지 않고 소비한다. 모델 교체·세션 종료 시 현재 원본을 정리하고, 진행 중 연산이 있으면 연산 종료까지 정리를 미룬다. 확정되지 않은 열기 후보도 실패·취소 시 정리한다. Native STEP 전달과 `.hmproj` 저장·복원은 `ModelBytes` 배열 복사 대신 스트림을 사용하며, 임시 저장 경로를 영속 프로젝트에 기록하지 않는다.

### 3.3 열기·호환·손상 처리

패키지 검사→DTO 파싱/구조 검증→원본 해시 검증→후보 모델 load→Face 대응→저장된 최종 곡선 복원→기하/길이/전기/면적 검증→Application 확정 순서다. 매개변수만 읽어 자동 재생성하면 안 된다.

- package/schema version 미지원은 PackageVersionUnsupported다. 상위 major를 임의로 읽지 않는다. 미래 optional 필드 추가는 schema 호환 정책/테스트로 다룬다.
- 필수 entry 누락/중복, 해시 불일치, 잘못된 참조는 PackageIntegrityFailure다. 손상 cache와 손상 권위 데이터는 구분한다.
- ZIP entry는 허용된 내부 경로만 읽는다. 추출이 필요하면 정규화한 목적지가 세션 임시 디렉터리 안에 있는지 확인한다. 절대경로/상위 이동/중복 정규 경로를 거부한다.
- entry 수·총 비압축 크기·JSON 깊이는 설정으로 제한하고 초과를 오류로 반환한다. 제한값은 실제 몰드 크기로 정하며 임의로 정상 파일을 잘라 읽지 않는다.
- Face 대응 모호·곡선 불일치는 현 문서를 유지하고 복원 진단을 반환한다. 임의 Face 대입이나 수동 편집 초기화를 하지 않는다.

## 4. ExportSnapshot와 사양 데이터

ExportSnapshot은 동일 revision의 최종 CurveDefinition, 회로/연결부 위치/ConnectionPath, LengthBreakdown, ElectricalResult, 회로별 적용면적/간격 문제, 출력 작업 좌표계를 포함한다. 파일 writer가 세션의 현재 mutable 값을 다시 조회하지 않는다.

`SpecificationDataBuilder`는 형식 중립 행을 만든다. 필수 열은 회로 표시명/ID, 본 발열사 길이, 발열사 연장/별도 연결선 길이와 연결 합계, 저항 대상 길이, R, 실제 V, I, P, 각 한도와 판정이다. 빈 값은 0이 아닌 ‘계산 불가/미입력’으로 표현한다. UI와 파일이 각자 식을 다시 계산하지 않는다.

기본 표시 규칙은 길이 mm 2자리(필요 시 m 3자리), 저항/전류 3자리, 전압/전력 2자리로 명시한다. 실제 값과 단위를 DTO에 보존하고 반올림은 문자열 작성 시만 수행한다. 한도 판정에는 반올림값을 사용하지 않는다. 이 기본 표 서식은 납품 표준 디자인 확정 전 제안이다.

## 5. STEP 출력

`StepDesignExporter`는 OCC-07의 writer를 사용한다.

1. 확정 snapshot의 활성 본 경로·연결 경로 곡선만 모아 회로별 wire/compound로 구성한다.
2. 실제 삽입 깊이가 반영된 최종 중심선을 사용한다. 2D 생성선이나 depth 적용 전 표면선을 다시 투영하지 않는다.
3. `IncludeSourceModel` 옵션을 기본 발열사 경로 출력과 구분한다. preview/비활성 TurnSegment는 포함하지 않는다.
4. path 선택은 Application/App이 제공하고 임시 파일에 출력→재읽기 검증→최종 교체한다.
5. 재읽기 후 curve/edge 수, 회로 그룹 대응, 시작/끝 좌표, bounding box, 총 3D 길이를 비교한다.

STEP 구조의 이름/회로 그룹은 reader/writer에서 보존 가능한 방식으로 OCC-07에서 검증한다. AP 포맷·외부 CAD가 이름을 보존하지 않아도 곡선 엔티티는 편집 가능해야 한다. 홈/발열사 솔리드를 제품 필수 출력으로 확대하지 않는다.

## 6. DXF 출력

현재 BuildViews/BuildHlrView는 모델 HLR만 채운다. 이 코드를 DxfProjectionBuilder로 옮겨 각 view에 최종 3D 경로/연결/연결부 위치를 더한다.

### 6.1 동일 투영 좌표계

각 view에 Origin/AxisX/AxisY/Normal과 공통 sheet offset을 저장한다. 점 p는 `(dot(p-Origin,X), dot(p-Origin,Y))`로 투영한다. 모델 HLR 결과와 경로가 같은 origin/축을 쓰도록 native 반환값을 확인한다. Native HLR의 숨은 평행이동을 추측해 경로를 이동하지 않는다.

각 view의 외곽·은선·경로·연결부 위치 전체 bounds를 계산한 뒤 같은 offset을 한 번 적용한다. 모델/경로에 별도 Fit 정렬을 하지 않는다. 초기 출력 view 세트는 현재 네 방향을 유지하되 작업 좌표계/자동축 선택을 옵션으로 명시한다. 카메라 회전은 출력의 작업 좌표계를 바꾸지 않는다.

## 2026-10-24 추가 구현: 관리형 원호 간격 fallback

Native bridge가 없는 `OcctGeometryQueries.MeasureClearance` 경로에 `ArcCurveClearanceCalculator`를 연결했다. 원호는 연결 공차의 1/64을 목표 현 편차로 다중선화하며, 한 원호 100,000개와 전체 1,000,000개 표본 예산, 취소 확인, snapshot 끝점 정합성을 확인한다. 최대 선분 거리 오차와 원호 근사 오차를 합친 상한이 연결 공차보다 크면 성공값을 만들지 않는다. 연결 선언이 있는 원호 끝점, B-spline, 2π를 넘는 반복 원호는 현재 계산 근거가 부족해 미확정으로 반환한다.

## 2026-10-24 진행: Native 삽입 깊이 보정 질의 연결
