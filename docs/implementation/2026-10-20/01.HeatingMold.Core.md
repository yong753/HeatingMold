## 1. 범위와 현재 코드

`src/HeatingMold.Core/HeatingMold.Core.csproj`의 `net8.0`을 유지하고 Clipper2 참조를 제거한다. WPF/OccBridge/netDxf/Clipper2 의존이 없는 순수 라이브러리로 만든다. 경로 생성·영역 boolean·파일 직렬화·전기 계산·변경 세션은 이 프로젝트에서 수행하지 않는다.

| 현재 코드 | 조치 |
|---|---|
| `Geometry/Vec2.cs`, `Vec3.cs` | 유지. 영벡터 정규화, NaN/Infinity 경계 검증 추가 |
| `Geometry/ProjectionFrame.cs` | 유지. 정규직교·오른손 좌표계·카메라 독립 왕복 검증 |
| `Geometry/WorkingSide.cs`의 ModelRevision/WorkingSideId/WorkingSideDefinition | 값 타입은 유지·정리; WorkingSideId가 영속화되지 않도록 분리 |
| 같은 파일의 WorkingSideSession | Application/Sessions로 이동 |
| 같은 파일의 WorkingBoundary | Design/Regions로 이동; Core에서 RegionOps 호출 제거 |
| `Geometry/RegionOps.cs`, `Serpentine.cs`, `SurfacePathMapper.cs` | Design으로 이동. Core의 계산 API로 남겨두지 않음 |
| `Model/PatternParams.cs` | Design/Legacy로 이동해 이전 기간만 유지. 신규 입력은 PlacementConstraints |

파일 이동은 DES-01 담당과 한 번만 수행한다. 먼저 목적지와 테스트 참조를 준비한 뒤 using/프로젝트 참조를 동시에 갱신한다. 동일 소스가 Core와 Design 양쪽에서 컴파일되지 않게 한다.

## 3. 공개 계약

### 3.1 집약과 불변성

`DesignProject`는 읽기 전용 스냅샷으로 만들고 공개 setter로 선택면·경로·회로를 부분 갱신하지 않는다. 구현 이름은 공통 계약의 영문명에 맞춘다. 호출자가 배열/리스트를 수정할 수 없도록 방어 복사 또는 불변 컬렉션을 사용한다. 기본 타입 생성 시 유한값과 범위를 검증한다.

- `CreateEmpty(ProjectId, ModelIdentity, WorkingFrame)`로 경로 없는 설계를 만들 수 있다.
- `ValidateReferences()`는 중복 ID·존재하지 않는 참조·공유 절점 불일치·동일 조각의 이중 소속을 반환한다. 거리·곡면·전기 판정은 수행하지 않는다.
- EntityId는 타입마다 구분한다. RoutePieceId를 CircuitId로 암시적 변환할 수 없다.
- `DesignRevision`은 성공 시에만 증가한다. 변경 처리 자체는 Application이 담당한다.
- 영속 모델에서 UI 좌표·네이티브 context·AIS를 참조할 수 없다.

### 3.2 경로·곡선

`Route`는 생성 원본과 최종 상태를 구별하여 가진다. `RoutePiece`는 종류, 안정 ID, 양 끝 ControlPointId, 순서, 활성 여부, CurveDefinition을 가진다. 생성 당시 LaneIndex는 진단 힌트이고 영속 식별자가 아니다.

`CurveDefinition`은 tag로 구분된 다음 형식을 지원한다.

| tag | 필수 정보 | 검증 |
|---|---|---|
| Line | 시작/끝 Vec3 | 유한값, 허용되지 않는 0길이 거부 |
| Polyline | 순서 있는 Vec3 집합 | 연속 중복 정리 규칙, 최소 2점 |
| Arc | 평면 프레임, 중심, 반지름, 시작/끝 각, 방향 | 양의 반지름, 명확한 각 단위(rad) |
| BSpline | degree, poles, weights, knots/multiplicities, periodic, trim range, 방향 | 차수/배열 길이/단조 knot/양의 weight/유효 범위 |

길이 계산 구현을 Core에 넣지 않는다. `CurveGeometrySnapshot`에 Native가 산정한 LengthMm, Start/End, 표시/품질용 샘플, 근사정보를 보관한다. CurveDefinition은 저장·재열기·STEP용 원형 정의이며 샘플과 역할이 다르다.

### 3.3 회로·접속·길이

`Circuit`는 순서와 방향을 가진 활성 RoutePiece 참조를 가진다. 하나의 활성 본 경로 조각은 정확히 한 회로에 속한다. 분기/폐회로는 현재 두 끝점 회로 규칙에 맞지 않으면 오류다. `Terminal`은 회로 시작/종료 역할, 발열사 끝점 참조, 인출 앵커, 실제 연결점과 연결한다.

`LeadRoute`의 각 구간은 재료 역할과 OnMold/External을 따로 기록한다. 여유 길이는 구간/재료에 연결된 추가분이며 형상 길이에서 재차 추출해 더하지 않는다. `LengthBreakdown`은 소스 조각 ID를 포함하는 원장과 다음 합계를 노출한다.

```text
HeatingBodyMm
HeatingExtensionMm
SeparateLeadMm
HeatingExtraAllowanceMm
SeparateLeadExtraAllowanceMm
ResistanceLengthMm = HeatingBodyMm + HeatingExtensionMm + HeatingExtraAllowanceMm
```

원장 중복·음수·비유한값은 구성 오류다. 실측 Native 길이가 없는 후보에 임시 2D 길이를 넣어 확정 길이처럼 표현하지 않는다.

### 3.4 결과와 오류

`OperationResult<T>`는 성공값과 실패 issue를 명확하게 구분한다. 정상적인 사용자 조건 불충족을 예외로 처리하지 않는다. 프로그래밍 불변식 위반은 예외/기술 로그 대상이다.

`ValidationIssue`는 공통 문서 7절 필드를 제공한다. 메시지 번역과 화면 서식은 App 책임이다. `ElectricalResult`는 회로ID, 입력/길이 stamp, 상태, 계산값 nullable, 초과 항목을 가진다. `CircuitAreaAllocation`은 TotalValidSurfaceAreaMm2, 회로별 담당면적, UnassignedAreaMm2, 오차/수렴 정보, stamp를 가진다.

기존 `ProjectionMappingTests.cs`, `WorkingSideTests.cs` 중 Core 값 계약 검사를 유지한다. 세션 검사는 Application으로, `RegionOpsTests.cs`, `SerpentineTests.cs`, `SurfacePathMapperTests.cs`는 Design으로 옮긴다.

| ID | 입력 | 기대 결과 |
|---|---|---|

## 6. 완료 기준 및 인계

- Core만으로 빈 설계, 생성 설계, 수동 편집·분할·접속 설계 fixture를 구성할 수 있다.
- ID·단위·깊이·간격·길이·오류 의미가 공통 계약과 일치한다.
- Core 단독 테스트에 Windows/OCCT/Clipper/netDxf가 필요하지 않다.
- 소비 모듈은 Core 타입을 사용하며 동일 의미의 DTO를 임의 도메인 모델로 재정의하지 않는다.
- JSON wire 형식은 Infrastructure에 맡기되 영속 값의 누락 여부를 함께 검토한다. 신규 속성마다 재열기 필요성과 파생 여부를 인계 기록에 남긴다.
