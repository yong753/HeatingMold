# 발열몰드 발열사 배치 자동화 프로그램 — 개발 계획서

**문서 버전:** 1.0 · **작성일:** 2026-10-08
**상태:** 확정 (스택: C# + OCCT(C++) 하이브리드)

---

## 1. 프로젝트 개요

### 1.1 목적
STEP 형식의 3D 발열몰드 모델을 불러와, 사용자가 선택한 면 위에 **발열사 배치 패턴을 자동 생성**하고, 이를 3D로 시각화하며 **2D 도면(DXF/DWG)으로 출력**하는 Windows 데스크탑 프로그램.

### 1.2 배경 (제품 공정)
발열사(와이어형 발열체가 삽입된 유리섬유 시트)를 몰드 면에 깔고 그 위에 소재를 적층·가열·경화시키는 공정. 몰드에 홈을 파지 않고 **표면 배치 표시 + 2D 도면**만 필요.

### 1.3 범위
| 구분 | 내용 |
|---|---|
| 포함 | STEP 로드 · 면 선택 · 사행 패턴 자동 배치 · 제외영역 설정 · 3D 표시 · 2D 도면(DXF) 출력 |
| 제외 (추후) | 전기계산(열량↔간격 변환 — 발주처 계산식 제공 예정), 홀 자동 회피, 곡면 전개도 |

## 2. 요구사항

### 2.1 기능 요구사항 (확정)
| ID | 요구사항 | 비고 |
|---|---|---|
| FR-01 | STEP(B-rep) 몰드 모델 로드 | 샘플: `resource\Mold.stp` (NX 12.0, AP242, mm, 수백 면, 자유곡면) |
| FR-02 | 3D 뷰어에서 단일 면 선택 | 평면·곡면 모두 |
| FR-03 | 선택 면에 사행(serpentine) 발열사 패턴 자동 생성 | 패턴 1종: 지렁이게임식 왕복 |
| FR-04 | 배치 간격 등 파라미터 입력 | 간격은 사용자 직접 입력 (전기계산 없음) |
| FR-05 | 가장자리 오프셋을 면마다 입력 | 예: 모든 변에서 100mm 안쪽 |
| FR-06 | 제외영역(구멍 등) 사용자 설정 | 자동 회피는 추후 |
| FR-07 | 생성 패턴 3D 표시 (몰드 위 오버레이) | 홈 모델링 없음 |
| FR-08 | 평면/측면 2D 도면 출력 (DXF/DWG) | 몰드 윤곽 + 발열선 경로 + 치수 |
| FR-09 | 2D 뷰 방향은 글로벌 좌표계 기준 | 평면(-Z)·측면(+Y) 기본값, 설정 가능 |
| FR-10 | 프로젝트 저장/불러오기 | JSON |

### 2.2 비기능 요구사항
- OS: Windows 10/11, 단일 사용자 데스크탑
- 자유곡면 포함 수백 면 B-rep을 무리 없이 로드·표시
- UV 등간격이 아닌 **3D 실길이 기준**의 균등 배치 품질
- 상용 배포 가능한 라이선스 구성 (OCCT LGPL 동적 링크 유지)

## 3. 기술 스택

| 계층 | 선택 | 근거 |
|---|---|---|
| 애플리케이션 | **WPF (.NET 8 LTS) + MVVM** (CommunityToolkit.Mvvm) | Windows 데스크탑 표준, HwndHost로 OCCT 뷰어 임베드 |
| 기하 커널 | **OpenCascade OCCT 7.9.x** (C++, 소스 직접 빌드 확정) | LGPL-2.1(+예외), 자유곡면 B-rep·HLR 전 기능 |
| 브리지 | **C++/CLI 혼합 어셈블리** (`/clr:netcore`) | VS 단일 솔루션, 생산성. 실패 시 C ABI+P/Invoke 대안 |
| 2D 폴리곤 연산 | **Clipper2** (NuGet) | 오프셋/불리언/클리핑 C# 표준 |
| DXF/DWG | **netDxf** or **ACadSharp** (M4 스파이크 결정) | netDxf 치수 성숙·아카이브 / ACadSharp 활발·DWG 지원 |
| 테스트 | **xUnit** (Core 프로젝트 한정) | 브리지 비의존 로직 검증 |
| 검증 | **AutoCAD** (사내 보유 확인) | DXF 열람·품질 검수 |
| 배포 | Inno Setup 또는 MSIX | OCCT DLL 포함, LGPL 고지 |

**참고:** C++/CLI가 지원하는 TFM(.NET 버전)은 M0에서 확정 — VS2022의 `/clr:netcore` 지원 기준. 기본 후보 .NET 8 LTS.

## 4. 시스템 아키텍처

### 4.1 계층 구조

```
┌─ HeatingMold.App (WPF, MVVM) ──────────────────┐
│ 3D 뷰어(HwndHost) · 파라미터 패널 · 제외영역 UI  │
├─ HeatingMold.Core (순수 C#, 브리지 비의존) ──────┤
│ Serpentine 생성기 · RegionOps(Clipper2) · 모델   │
├─ OccBridge (C++/CLI) ──────────────────────────┤
│ STEP 로드 · UV 추출 · UV→3D 매핑 · HLR · 뷰어   │
├─ HeatingMold.Export ───────────────────────────┤
│ DXF 라이터 (레이어/치수)                        │
└────────────────────────────────────────────────┘
        단방향 의존: App/Export → Core → (없음)
        App → OccBridge, App → Export
```

### 4.2 솔루션 구조

```
HeatingMold.sln
├─ src/
│  ├─ OccBridge/                    # C++/CLI — 유일한 비관리 코드
│  │  ├─ native/                    # 순수 C++ OCCT 로직 (STEP/UV/매핑/HLR)
│  │  ├─ managed/                   # 얇은 C++/CLI 래퍼 (마셜링 전담)
│  │  └─ viewer/                    # AIS 뷰어 HWND 임베드
│  ├─ HeatingMold.Core/             # .NET 클래스 라이브러리 (순수 C#)
│  │  ├─ Model/                     # PatternParams, FacePlacement
│  │  ├─ Geometry/Serpentine.cs
│  │  └─ Geometry/RegionOps.cs
│  ├─ HeatingMold.App/              # WPF
│  │  ├─ Views/  (MainWindow, ViewerHost:HwndHost, 패널)
│  │  └─ ViewModels/
│  └─ HeatingMold.Export/           # DXF 라이터
└─ tests/HeatingMold.Core.Tests/    # xUnit
```

### 4.3 브리지 인터페이스 (C# 노출면, ~20개 함수)

```
LoadStep(path) → model
GetSolidCount(model) / GetFaceCount(solid)
GetFaceUvBoundary(faceId) → 외곽 루프 + 홀 폴리곤 (double[] 벌크)
SampleUvTo3D(faceId, u, v) → Point3d
BuildWire(faceId, uvPath[]) → wire handle
BuildRibbon(wire, width)           # 표시용 두께
InitViewer(hwnd) / FitView / SetColor / PickFace(x, y) → faceId
HlrProject(projection) → 2D 선분 배열 (몰드+발열선)
Dispose(handle)
```

**원칙:** native 로직은 순수 C++로, managed는 마셜링만. 핸들은 C# `IDisposable` 1:1 래핑. 좌표는 `double[]` 벌크 전달.

## 5. 핵심 알고리즘 — 사행 패턴 파이프라인

```
STEP 로드
  → 면 선택 (AIS 픽킹)
  → UV 도메인 + 경계(pcurve) 추출 → UV 폴리곤 (외곽 + 홀)
  → ① 외곽 경계 마진 오프셋 / 제외영역 안전거리 확장 → Clipper2 차집합 = 유효영역
  → ② 방향축(기본: UV 경계 장축) 기준 간격 s마다 평행 레인 생성
  → ③ 유효영역 클리핑 → 레인 단편들
  → ④ U턴 반원(반지름 s/2, 홀수 레인 방향 반전)으로 순차 연결 → 단일 연속 와이어
  → ⑤ UV→3D 적응 샘플링 (3D 코드 길이 기준) → 3D 와이어/리본
  → 3D 표시 (AIS)
  → HLR → 투영 선분 → DXF
```

**설계 규칙:**
- 단계 ⑤의 샘플링 로직은 **C# Core에 유지** (브리지는 `SampleUvTo3D`/`BuildWire`만 제공) → xUnit 테스트 가능
- Serpentine 코어는 **세그먼트 기반 + 연결규칙 분리** 구조 — 추후 홀 자동 우회(v2)로 확장
- MVP: 제외영역에서 와이어 **분절 허용** (연속성 보장은 추후 단계)

### 데이터 모델

```csharp
record PatternParams {
    double OffsetMargin;      // 가장자리 오프셋 (면마다 입력)
    double Spacing;           // 레인 간격 (사용자 입력)
    double? DirectionDeg;     // null → UV 경계 장축 자동
    double WireWidth;         // 표시용
    double ExclusionSafety;   // 제외영역 확장 거리
}
record FacePlacement {
    int FaceId;
    PatternParams Params;
    List<UvPolygon> Exclusions;
    List<UvPoint[]> PatternUv;   // 생성 결과
}
```

### 2D 도면 규약
- 레이어: `MOLD_OUTLINE` / `HEAT_WIRE` / `DIMENSION` (회사 표준 있으면 대체)
- 치수: 몰드 전체 크기 + 레인 간격
- 뷰: 평면(-Z) / 측면(+Y) 기본값, 설정 가능

## 6. 단계별 실행 계획

| 단계 | 작업 항목 | 검증 기준 |
|---|---|---|
| **M0 스파이크** (최대 위험, 3~5일) | ① VS2022 C++ 워크로드·`/clr:netcore` 확인 ② OCCT 소스 CMake 빌드 (7.9.x 확정) ③ OccBridge: `Mold.stp` 로드 ④ WPF HwndHost 뷰어 임베드(줌/회전) ⑤ 면 픽킹→faceId 수신 ⑥ `GetFaceUvBoundary`→C# 폴리곤 수신 | ①~⑥ 데모 동작 |
| **M1 코어** | Clipper2 RegionOps + Serpentine 생성기, xUnit 테스트 (직사각형/홀/마진/간격 케이스) | 단위 테스트 통과 |
| **M2 매핑/표시** | 적응 샘플링, BuildWire/Ribbon, 색상 표시, 평면 면 실데모 | Mold.stp 평면 면 패턴 표시 |
| **M3 제외영역 UI** | 파라미터 패널(마진·간격·방향·선폭) + 제외영역 스케치 도구 | 제외영역 반영 확인 |
| **M4 2D 도면** | 브리지 HLR → 상면/정면 투영 → netDxf/ACadSharp 결정 → DXF(레이어 3종+치수) | **AutoCAD에서 열람·검수** |
| **M5 통합/배포** | JSON 저장, 설치 패키지, OCCT DLL 동적 링크 배포+LGPL 고지, 타 PC 테스트 | 배포본 독립 실행 |

**예상 일정:** M0 3~5일 · M1~M3 약 2주 · M4~M5 약 1주
