## 1. 개발 방향과 근거

개발 목표는 **여러 Face로 이루어진 발열면에 하나의 연속 경로를 생성하고, 사용자가 시작·종료 위치와 배치 방향을 지정한 뒤 꼭지점·회로·연결 경로를 수정할 수 있는 Windows 설계 프로그램**이다. 같은 설계 상태를 기준으로 3D 표시, 전기 계산, STEP/DXF 출력 및 프로젝트 재열기를 제공한다.

메일에 포함된 그림 9개와 PDF 3쪽의 그림·계산식을 함께 확인했다. 최상단 승인 회신 자체의 발신 일시는 본문에 없으므로, 10/20 제안이 최상단 회신에서 승인된 것으로 기록한다.

### 이번 대화에서 추가로 확정된 기준

1. 삽입 깊이는 **작업방향 축을 따라 발열사 외피까지의 거리**이다.
2. 꼭지점 수정 후에도 입력한 **최소 외곽 간격**을 지켜야 하며 미달하는 수정은 적용하지 않는다.
3. 자동 생성과 수동 편집 모두 **시작·종료를 동일한 측면으로 인출**한다.
4. 회로마다 별도 전원을 사용하므로 전압·전류 한도는 **회로별로 적용**한다.
5. FR-3.3은 **사용자가 구성한 회로의 전기 조건 충족 여부와 해당 적용면적을 계산·표시**한다.
6. 제공 자료는 현재 저장소 문서와 위 PDF까지이다.
7. **Undo/Redo는 기존 회전 연결 구간용을 포함해 삭제**하며 신규 구현하지 않는다.
8. **6개 C# 프로젝트와 OccBridge 1개, 총 7개 프로젝트**로 관리한다.
9. **발열사 경로와 연결 경로 모두 구멍·장애물 자동 우회를 구현하지 않는다.**
10. **설계 JSON과 원본 STEP을 단일 ZIP 패키지(.hmproj)로 저장**한다.

### 합의 사항의 적용

- 꼭지점 이동과 회로 절단·통합은 메일에서 합의된 기능이다.
- Undo/Redo는 사용자 지시로 삭제한다. 기존 회전 연결 구간용 버튼·이력 저장·이벤트 처리도 제거하며 선택 기능으로 남겨두지 않는다.
- 실패한 편집 후보를 적용하지 않고 이전 유효 상태를 유지하는 처리는 Undo/Redo 기능과 구분한다.
- 7개 프로젝트 구성과 JSON+STEP 단일 패키지는 이번 대화에서 사용자 확인을 받은 개발 기준이다.

Windows/WPF, .NET 8, C++/CLI와 OCCT라는 기존 기술 기반은 유지한다. 열해석, 전개도, 고곡률 곡면의 정밀 등간격 최적화, 구멍·장애물 자동 우회, 자동 회로 분할·연결부 최소화, DWG는 이번 계획의 PHASE 1 범위에 포함하지 않는다.

선택된 인접 Face를 연결하는 기능은 PHASE 1이다. 인접 Face를 프로그램이 자동으로 찾아 선택하는 기능은 별도 후속 기능이다.

## 3. 실제 코드 기준 구현 상태

### 재사용할 기반

- STEP 로드와 AIS 뷰어, Face 클릭/Ctrl 토글/사각 선택, 고정 작업 좌표계와 모델 revision.
- 선택 Face의 원본 공유 Edge를 이용하는 통합 경계 추출.
- Clipper2를 사용하는 영역 연산, 스캔라인 사행 생성, 경로 조각과 연결 회전 연결 구간 구분.

- 모델 HLR 투영, netDxf 출력, Core 및 네이티브 회귀 검증 자산.

체크포인트 문서와 현재 호출 경로의 차이도 정리해야 한다. 전체 모델의 가장 가까운 충돌을 조회하는 QueryWorkingSurfaceForFaces와 SurfacePathMapper 기반은 존재한다. 그러나 현재 화면의 StageProjectedWorkingHeatingPathSegment 호출이 사용하는 BuildProjectedWorkingWire는 선택 Face를 sewing한 target에 투영한다. 문서에 기재된 전체 모델 first-hit 검증이 모든 생성 경로에 연결되어 있다고 간주하지 않고, 가림·다층·비선택 장애물 검증을 실제 생성 및 편집 경로에 연결한다.

현재 생성은 시작 시 CancelConnectionPointSetup을 호출하므로 실패 전의 연결 상태까지 모두 보존하는 구조도 아니다. 신규 후보 처리에서는 경로·연결 경로·회로·계산 결과 전체의 원자적 변경을 목표로 한다. 그래픽 드라이버 실패 시의 완전한 표시 복원은 별도 한계이며, 저장된 설계 상태로 장면을 다시 구성할 수 있도록 한다.

## 4. 모듈 구성

**6개 C# 프로젝트와 기존 C++/CLI 브리지 1개, 총 7개 프로젝트**로 관리한다. 기능별 책임은 프로젝트 내부의 폴더·네임스페이스·서비스로 나눈다. 기존 Core/App/Export/OccBridge를 단계적으로 정리하고, 삭제하기로 한 Undo/Redo를 제외한 현재 동작을 유지하며 이동한다. 프로젝트 재편성은 아직 실행하지 않았다.

분리 기준은 변경 이유, 외부 라이브러리·플랫폼 의존성, 독립적으로 검증할 수 있는 단위이다. 함께 변경되는 설계 기능은 같은 프로젝트에 묶고, 기능별 세분화는 이 7개 프로젝트 내부에서 관리한다.

| 프로젝트 | 책임 및 내부 기능 모듈 | 기존 코드 활용 |
|---|---|---|
| HeatingMold.Core | 설계 모델·단위·식별자·좌표계·공통 기하 계약·오류 형식 | Vec2/Vec3/ProjectionFrame/WorkingCoordinateSystem 정리. Clipper 의존은 Design으로 이동 |
| HeatingMold.Application | 프로젝트 세션·작업 순서·기능 호출 조합·변경 영향과 후보 확정 | MainWindow의 설계 상태와 처리 흐름 이전. Undo/Redo는 구현하지 않음 |
| HeatingMold.Design | HeatingRegions / HeatingPathGeneration / Editing / Circuits / Validation. 발열 영역·발열사 경로·연결 경로·꼭지점 편집·회로·간격·연속성 검사 | RegionOps·HeatingPathGenerator·CircuitPathPartitioner와 기존 검증 활용 |
| HeatingMold.Electrical | PDF 계산식·회로별 한도·불완전 입력 판정·전기 조건 만족 적용면적 집계 | 신규. CAD 및 UI 의존 없음 |
| HeatingMold.Infrastructure | Geometry.Occt / Persistence / Export. OCCT 어댑터·프로젝트 패키지·STEP/DXF/사양표 출력 | Bridge 호출과 기존 Export 이전. 내부 폴더별로 외부 라이브러리 의존 구분 |
| HeatingMold.App | Views / ViewModels / Viewer. WPF 화면·서비스 조립·HwndHost·장면·피킹·입력 모드 | MainWindow와 OccViewport를 폴더·클래스로 분리 |
| OccBridge | 얇은 C++/CLI 변환 API 및 OCCT 네이티브 기능 | 기존 프로젝트 유지, 내부 소스 파일과 상태 소유권 분리 |

### 의존성과 관리 규칙

- Core에는 WPF, OCCT, netDxf, Clipper2 참조를 두지 않는다.
- Design과 Electrical은 Core를 사용한다. Design 내부의 각 기능은 입력·출력과 책임을 분리하고 화면 상태를 직접 수정하지 않는다.
- Application은 Design과 Electrical을 조합하고, 기하·저장·출력은 계약을 통해 호출한다.
- Infrastructure의 기하 어댑터와 App/Viewer에서만 OccBridge에 접근한다. Viewer는 설계 계산을 수행하지 않는다.
- App의 서비스 조립 위치에서 각 구현을 연결한다. MainWindow 이벤트에서 경로 생성·전기 계산·파일 직렬화를 직접 하지 않는다.
- Infrastructure 안에서도 Geometry/Persistence/Export의 폴더와 서비스를 구분한다. netDxf 의존은 DXF 작성 부분에 제한한다.
- 프로젝트와 기능 폴더별 README에 책임, 입력·출력, 의존성, 오류, 검증 명령, 알려진 한계를 기록한다.
- 테스트는 기능 단위로 관리한다. 실제 교체·격리 검증이 필요한 경계에 인터페이스를 둔다.
- 네이티브 API의 무형식 double 배열은 신규 어댑터에서 의미가 있는 결과 형식으로 변환한다.
- 네이티브 상태는 문서 세션 소유 객체로 모은다. PHASE 1은 단일 문서·UI 스레드 제약을 유지하며, 무리하게 병렬 OCCT 호출을 추가하지 않는다.
- App의 x64/Release 고정 DLL 참조는 구성별 빌드 순서와 출력 경로로 정리하고, 설치 패키지에 필요한 OCCT·C++/CLI 런타임 파일을 함께 관리한다.

네이티브 내부는 ModelRepository / WorkingSurface / RegionTopology / HeatingPathGeometry / ConnectionPathGeometry / ViewerScene / HlrProjection / StepExchange로 분리하고 OccBridgeApi는 인자 변환과 호출 위임만 맡긴다. 기존 WorkingCoordinateSystemNative.inc의 단일 포함 구조도 이 과정에서 정리한다.

## 6. 기능별 구현 방법

### 6.1 적용면 및 영역

1. Drag와 Ctrl+Click으로 선택한 Face 집합을 확정한다.
2. 실제 공유 Edge와 가져온 형상의 공차를 확인하여 내부 경계를 제거한다.
3. 외곽 루프, 실제 구멍, 떨어진 영역, 추출 오류를 구분한다. 전체 모델의 실루엣을 선택 영역 대신 사용하지 않는다.
4. 선택 영역 내부에서 사각형 포함/제외와 제외 취소를 제공한다. 포함은 선택 Face의 유효 표면 안으로 제한한다.
5. 곡면의 간단한 영역 조정은 작업 평면의 도형을 선택 표면에 매핑하는 방식으로 처리한다.

**발열사 본 경로와 연결 경로 모두 구멍·장애물 자동 우회는 구현하지 않는다.** 근거는 전체 메일의 FR-2.4와 구멍 자동 우회를 PHASE 2로 두는 발주처 회신이다.

경로가 구멍이나 제외영역을 가로지르는지는 검사한다. 가로지르면 해당 후보를 적용하지 않고 위치와 사유를 표시한다. 구멍 둘레를 따라 연결선을 찾거나, 잘린 선분을 자동 재연결하거나, 회로를 자동으로 늘리지 않는다. 사용자가 발열 영역 또는 회로를 조정한다. 제외영역 사용 여부와 무관하게 경로·회로·출력 데이터 구조를 일관되게 유지한다.

### 6.2 시작·종료·가로/세로를 반영한 자동 생성

- 입력 간격 g와 직경 d로 기본 중심 피치 g+d를 계산한다. 기존 Spacing 명칭을 CenterPitch로 명확히 구분한다.
- 사용자 방향은 고정 작업 좌표계의 X/Y를 기준으로 한다. 카메라를 돌려도 방향이 바뀌지 않는다.
- 사용자가 공통 인출 측면과 시작·종료 위치를 지정한다. 주 발열 경로와 연결부까지의 인입·인출 구간을 구분한다.
- 공통 측면은 화면의 좌우가 아닌 모델의 외곽 경계 구간으로 식별한다. 주 발열사 경로의 경계 여유와 경계까지 나가는 인입·인출 구간의 허용 범위도 구분한다.
- 기존 스캔라인 생성기를 확장하여 진행 순서, 경로 반전, 레인 수의 홀짝, 배치 위상을 후보로 평가한다.
- 시작·종료에 연결하는 짧은 진입/마감 구간을 구성하고, 경계·간격·동일 측면 조건을 함께 검사한다.
- 오목한 외곽에서도 선택 영역을 벗어나거나 간격을 침범하는 연결을 허용하지 않는다.

임의의 두 점·고정 간격·동일 측면·단일 연속 경로가 항상 동시에 가능한 것은 아니다. 충족하지 못하면 위치나 방향 변경이 필요한 이유를 보여준다. 지정점을 몰래 다른 위치로 옮기거나 입력 간격을 임의로 바꾸지 않는다.

### 6.3 3D 매핑과 삽입 깊이

기준은 선택 표면에서 금형 안쪽으로 작업축을 따라 처음 만나는 발열사 외피까지의 거리이다. 중심선 좌표를 단순히 입력 깊이만큼 이동시키면 이 기준을 충족하지 못한다.

- 평판에서 경로 접선과 작업축이 수직인 경우, 중심선은 입력 깊이에 반지름 d/2를 더한 위치가 된다.
- 따라서 새 기준의 깊이 0도 기존의 ‘중심선이 표면 위’인 깊이 0과 다르다.
- 경사면·곡면에서는 축과 경로 접선의 관계에 따라 외피의 축방향 교점이 달라질 수 있으므로, 일률적인 d/2 보정을 일반식으로 간주하지 않는다. 축방향 단면/외피 교차로 보정량을 검증한다.
- 이동 방향은 작업축이다. 개별 Face 법선 방향 오프셋으로 대체하지 않는다.
- 매핑한 표면점과 Face 소속, 입력 삽입 깊이, 최종 중심선을 함께 유지한다. 깊이 적용 후 실제 곡선의 연속성과 길이를 다시 계산한다.
- 여러 면이 경계 모서리로 이어진 표면 집합을 셸(Shell)이라고 한다. 셸은 열려 있거나 닫혀 있을 수 있으며, 부피를 정의하는 솔리드(Solid)의 경계에도 사용된다. 따라서 ‘셸은 항상 열린 모델’로 해석하지 않는다. [OCCT 모델링 자료](https://occt3d.com/dev/doc/overview/html/occt_user_guides__modeling_data.html)
- 특히 솔리드 부피가 정의되지 않은 열린 셸은 실제 재료 안쪽을 기하만으로 판정하기 어려울 수 있다. 이 경우에도 확정된 작업축과 미리보기로 삽입 방향을 명확히 한다. 셸 처리를 별도의 신규 제품 기능으로 추가한다는 의미는 아니다.

전체 모델의 첫 충돌, 선택 Face 소속, 인접 Face 전환, 실제 곡선의 연결을 검사한다. 최종 형상의 동일한 곡선을 3D 표시·길이 계산·STEP 출력에 사용한다.

기존의 0.01 mm 연결 공차와 0.05 mm 메시 목표 등은 구현 수치이다. 이를 완제품의 간격·깊이 오차 보증으로 사용하지 않는다. 특히 고곡률·접선·투영 중첩 구간은 근사 여부와 지원 한계를 표시한다.

### 6.4 꼭지점 편집 및 검증

드래그 시작 → 임시 후보 생성 → 3D 매핑·깊이 적용 → 공통 검증 → 유효한 경우 확정 순서로 처리한다. 마우스 이동 중에는 가벼운 미리보기를 하고, 놓을 때 최종 검증한다.

검사 대상은 선택 표면·적용 경계, 구멍·제외영역, 경로 연속성, 교차·자기 접촉, 최소 외곽 간격, 삽입 깊이와 동일 측면 인출이다. 연결된 경로 조각의 공유 접점은 정상 연결로 구분하고, 다른 왕복 레인 사이의 근접·교차를 검사한다.

최소 간격 미달 수정은 확정하지 않고 기존 형상을 유지한다. 연결부 위치와 시작·종료의 이동에도 동일 측면 제약을 적용한다. 수동 수정으로 등간격이 달라질 수 있으므로 목표 간격과 측정 간격의 차이를 함께 보여준다.

PDF가 요구한 과도한 공백은 별도 품질 결과로 다룬다. 곡면·Face 경계·U턴에서 인접 경로 간격 및 표면 샘플의 미배치 구간을 확인하고 위치·수치를 표시한다. 허용 최대 간격의 수치가 아직 없으므로, 우선 지정 간격 대비 편차를 표시하고 임의의 상한으로 온도 균일도 합격을 판정하지 않는다.

### 6.5 회로·연결 경로·전원

- 경로 조각의 연결 관계를 기준으로 절단·통합하고, 결과 회로의 ID와 끝점을 갱신한다.
- 회전 연결 구간를 끊거나 다시 연결한 후에는 회로마다 두 끝점과 동일 측면 인출 조건을 재검증한다.
- 회로별 전원은 별개이다. 기본 예시는 실제 인가전압 220V, 최대전압 220V, 허용전류 16A이며 사용자 변경이 가능하다.
- 발열사 끝점 → 표면의 인입/인출 경로 → 실제 연결부까지 연속 경로를 생성한다.
- 연결부가 발열영역 밖에 있을 수 있다. 연결 경로는 발열영역 안쪽 검사와 구분하여 금형과의 관계·전체 모델 장애물을 검사한다.
- 연결 경로는 직선 또는 간단한 절점 경로를 사용하며, 장애물 자동 우회는 구현하지 않는다.
- 미리보기, 확정된 연결 경로, 길이, 전기 결과를 구분한다. 미리보기만으로 회로 길이나 전기 결과가 바뀌지 않는다.

발열영역 밖으로 연장된 **같은 발열사**의 길이는 저항 계산 대상이다. **별도의 별도 연결선·연결부**는 기하 길이를 표시하되 PDF에 따라 저항 계산에서 제외한다. 여유 길이는 해당 재료 구간에 배정하고, 이미 그려진 길이와 입력 여유를 두 번 더하지 않는다.

### 6.6 전기 계산과 회로별 적용면적

PDF의 기본식 P=V²/(rL)을 사용하고 R=rL, I=V/R을 함께 계산한다. V는 실제 인가전압이며 교류는 실효값이다. 최대전압만 입력되어 있으면 실제 인가전압을 임의로 채우지 않는다.

L은 저항 계산 대상 발열사의 최종 3D 길이와 해당 발열사 여유 길이를 합친 값이며 m로 변환한다. 직경·저항·전압·전류를 각각 입력값으로 취급한다. 온도에 따른 저항 변화와 열해석은 포함하지 않는다.

| 제공 예시 | 재료 | 직경 | 단위 길이 저항 | 기본 전원 한도 |
|---|---|---|---|---|
| Case 1 | SUS 316L | 0.3 mm | 4 Ω/m | 회로별 최대 220 V, 16 A |
| Case 2 | SUS 316L | 0.15 mm | 8 Ω/m | 회로별 최대 220 V, 16 A |

회로별로 실제전압/최대전압, 계산전류/허용전류 및 별도 입력된 전력 한도를 비교한다. 필수 입력 누락·길이 0·음수·NaN은 ‘계산 불가’로 구분한다. 여러 회로의 전류를 하나의 16A 한도에 합산하지 않는다.

FR-3.3은 선택된 유효 표면에서 전체 적용면적과 회로별 적용면적을 표시한다. 별도 구역이 없는 절단 회로는 발열 영역의 표면 요소를 가장 가까운 발열사 경로에 배정하는 기하 분할을 사용하고, 경계 요소를 세분화하여 실제 표면적을 집계한다. 구멍·제외영역은 빼고 회로 간 중복 면적을 만들지 않는다.

이 결과는 ‘회로별 적용면적’과 ‘전기 조건 만족 적용면적’으로 표시한다. 실제 온도 도달 면적이나 열해석 결과로 표현하지 않는다. 곡면 면적은 투영 면적으로 대신하지 않고, 기하 분할의 근사 수준을 결과에 기록한다. 최대 적용면적 자동 탐색은 수행하지 않는다.

### 6.7 프로젝트 저장 및 재설계

**자체 확장자 .hmproj의 단일 ZIP 패키지**로 저장한다. 설계 내용은 JSON으로 기록하고 원본 STEP과 함께 묶는다. 메일의 구조화된 텍스트 저장 방침과 이번 대화에서 사용자가 확정한 JSON+STEP 패키지 방식을 적용한다. 패키지 저장 기능은 아직 구현하지 않았다.

패키지 구성은 manifest.json(파일 종류·버전), project.json(설계 상태), source/model.step(원본 모델)로 한다. 원본은 패키지 내부 상대경로와 파일 해시로 식별한다. 미리보기 이미지는 향후 선택 항목으로 추가할 수 있다. .NET의 기본 ZIP 기능을 사용한다. [Microsoft ZIP 문서](https://learn.microsoft.com/en-us/dotnet/standard/io/how-to-compress-and-extract-files)

프로젝트 파일 하나를 복사하면 설계 상태와 원본 모델이 함께 이동한다. 저장 시 패키지 전체를 작성하는 비용을 고려하며, JSON+STEP 패키지를 이번 구현의 저장 형식으로 고정한다.

저장 내용은 조건, Face 선택, 영역, 시작·종료·측면, 생성 원본, 최종 편집 경로, 회로 분할, 연결부 위치·연결 경로, 계산 기준 및 버전이다. 재열기 시 입력만 저장해 자동 재생성하는 방식으로 수동 편집을 잃지 않게 한다.

- 원본 해시와 Face의 형상 특징을 확인한다. Face 번호만 믿고 다른 모델에 붙이지 않는다.
- 다른 원본 또는 가져오기 버전 차이로 Face 대응이 모호하면 재선택을 요청하고 임의 대응하지 않는다.
- 네이티브 형상은 저장된 설계 데이터에서 복원·검증하고, 재열기 전후 길이·회로·좌표의 일치성을 확인한다.
- 간격·직경·방향을 바꿔 재생성할 때는 이전 수동 수정의 적용 가능성을 확인한다. 서로 다른 위상에 절점 index만으로 수정사항을 재적용하지 않는다.
- ZIP 자체가 트랜잭션을 제공한다고 가정하지 않는다. 패키지는 임시 파일로 완성하고 닫기·검증을 마친 뒤 기존 파일을 교체하며, schemaVersion에 따른 호환 처리와 명확한 오류를 제공한다.

일반 CAD에서 수정한 STEP/DXF를 원래의 매개변수 설계로 자동 역복원하는 기능은 포함하지 않는다. 프로그램 내 재설계는 .hmproj를 사용한다.

### 6.8 STEP/DXF/사양표 출력

내보내기 입력은 확정된 동일 revision의 설계와 계산 결과이다. 미리보기나 비활성 회전 연결 구간는 출력하지 않는다.

- STEP: 회로별 최종 중심선과 연결 경로를 실제 깊이가 반영된 3D 곡선으로 저장한다. 원본 몰드를 함께 포함하는 출력 옵션을 분리한다. 가공 홈이나 발열사 솔리드 모델 생성은 별도 요구가 없으므로 필수 범위로 확대하지 않는다.
- DXF: 모델 HLR과 최종 3D 발열 경로·연결 경로의 정사영을 같은 좌표계로 배치한다. 현재 HLR이 모델만 대상으로 한다는 점을 보완한다.
- 레이어: 기존 외곽/은선/발열사/치수에 연결 경로, 연결부·회로 번호, 전기 사양표, 간격 문제 표시를 추가한다.
- 사양표: 회로 ID, 발열사 길이, 연결 길이, 저항 산정 길이, 저항, 실제 인가전압, 전류, 전력, 허용 판정을 포함한다.
- 표 선은 도형, 셀 내용은 개별 TEXT/MTEXT 등 CAD에서 수정·복사할 수 있는 엔티티로 작성한다.
- 화면 표시용 선 두께와 실제 발열사 직경을 구분하고, 단위·축척·표의 반올림 기준을 명시한다.
- DXF는 투영도이며 곡면 재단용 전개도가 아니다. 길이 사양은 2D 투영 길이가 아닌 최종 3D 길이를 사용한다.
- 사양 데이터와 파일 작성기를 분리하여 추후 CSV/Excel 출력을 추가할 수 있게 한다.

## 9. 검증 계획

최초 계획 작성 시에는 빌드·테스트를 실행하지 않았다. 이후 2026-10-20 사용자 지시에 따른 Undo/Redo 제거를 반영하고 다음 검증을 수행했다.

- 기존 Undo/Redo 버튼, 이벤트 처리, 이력 저장과 초기화 코드를 제거했다. 회귀 검사에서 삭제된 이벤트를 호출하던 부분도 제거했다.
- 네이티브 브리지의 Release 빌드와 별도 출력 경로의 WPF 앱 빌드를 완료했다.
- 기존 PowerLead.Regression 검사 소스를 별도 실행 프로젝트에서 실행하여 **72개 검사 통과**를 확인했다. 경로 길이, 회로 분할, 연결 상태 초기화 및 미리보기 취소 검증을 포함한다.
- 기존 Run.ps1은 솔루션 출력 폴더에서 네이티브 재링크가 실패했다. 성공한 브리지 빌드와 별도 앱 빌드 출력을 사용해 동일한 회귀 검사 소스를 실행했다. 임시 실행 프로젝트와 형상은 무시되는 x64/UndoRemovalRegression에 둔다.
- 유지 관리 중인 C#/XAML 소스와 테스트에 Undo/Redo 참조가 남아 있지 않은지 확인했다. 실제 뷰어를 띄운 수동 검사는 수행하지 않았다.

이하 항목은 향후 전체 구현에 대한 검증 계획이며, 아직 해당 기능 전체가 완료되었다는 의미는 아니다.

- 기존 기준선: Core 단위 검증, WorkingSide.Regression, PowerLead.Regression. 네이티브 브리지와 앱을 함께 검증하며 기존 실행 중인 앱 출력물을 덮어쓰지 않는 러너를 활용한다.
- 간격: 같은 최소 외곽 간격에서 Case 1/2의 중심 피치가 각각 g+0.3, g+0.15가 되는지 확인한다. 직선·곡면·U턴·Face 경계 및 수동 이동의 실제 최소 외곽 간격을 확인한다.
- 양 끝점: 같은 측면, 홀수/짝수 레인, 가로/세로, 시작·종료 반전, 실현 불가능한 조건을 구분한다.
- 깊이: 표면 깊이 0의 새 의미, 양의 깊이, 경사면·곡면의 외피 교점, 실제 내보내기 좌표를 확인한다.
- 연속성: 인접한 A→B→C Face, 오목한 외곽, 가림·다층·작은 구멍 및 제외영역을 확인한다.
- 편집/회로: 최솟값 바로 위/아래 간격, 교차, 절단·통합 후 동일 측면 연결부 위치, 실패 후 전체 상태 보존을 확인한다. Undo/Redo 삭제 후에도 회전 연결 구간의 직접 절단·연결과 연결 상태 초기화 검증을 유지한다.
- 연결: 발열사 연장과 별도 연결선을 구분하고, 연결부 위치·여유 길이·중복 계상·미리보기 취소를 확인한다.
- 전기: 저항 대상 길이가 10m, 실제전압이 220V일 때 Case 1은 R=40Ω, I=5.5A, P=1210W, Case 2는 R=80Ω, I=2.75A, P=605W인지 확인한다. 서로 다른 회로의 전류가 합산 한도로 잘못 판정되지 않는지도 검증한다.
- 면적: 구멍/제외를 뺀 전체 적용면적, 곡면 실면적, 회로별 적용면적 합계, 전기 판정 변경 시 전기 조건 만족 적용면적 집계를 확인한다.
- 저장: 단일 패키지 이동, 내부 원본 변경·누락, 모호한 Face 대응, 버전 차이, 저장 실패, 수동 편집 복원을 확인한다.
- 출력: STEP 재읽기와 길이·좌표 비교, DXF 재읽기와 경로·레이어·TEXT 존재 확인, 일반 CAD 편집 확인을 수행한다.
- 실제 Mold.stp와 작은 생성 형상을 사용한다. 새로운 샘플 형상을 발주처와 공유할 때에는 PDF의 사전 공유 요청을 따른다.
- 실제 뷰어의 고해상도/DPI·선택·드래그·장면 표시, 새 Windows 설치 환경은 수동 확인한다.

| 항목 | 현재 진행 방법 | 최종 확정이 필요한 시점 |
|---|---|---|
| 과도하게 벌어진 간격의 허용 상한 | 지정 간격 대비 편차·위치·측정값 표시. 임의의 열적 합격 판정 없음 | 품질 판정 문구와 최종 검수 기준 결정 전 |
| 곡면 간격·삽입 깊이의 납품 허용오차 | 기존 수치 공차와 실측 오차를 구분하고 0단계에서 측정 | 곡면 지원 범위 및 완료 판정 확정 전 |
| 연결부 표준 형상·DXF 표 디자인 | 별도 사내 표준이 없으므로 연결부 위치 점/기호와 편집 가능한 기본 표 제안 | 출력 시제품 검토 시 |
| 발열사 끝점 이후 별도 연결선으로 바뀌는 실제 위치 | UI에서 구간 종류를 구분하고 PDF의 저항 제외 규칙 적용 | 연결 경로 시제품 검토 시 |

첫 구현 작업은 **현재 회귀 기준선 확인 → 공통 설계 모델·계약과 모듈 경계 확정 → 실제 몰드에서 동일 측면 양 끝점 및 삽입 깊이 기하 검증 → 기존 기능의 단계적 이전**이다.

## 11. 모듈별 상세 구현계획

이 문서를 기준으로 작성한 [모듈별 상세 구현계획 색인](implementation/2026-10-20/README.md)에서 7개 모듈 문서와 공통 계약을 확인한다. 각 문서는 기존 코드 이전 위치, 신규 파일·인터페이스, 구현 순서, 실패 처리, 테스트 입력·기대 결과와 완료 기준을 포함한다. 신규 API와 작업 항목은 구현 예정이며, 이 문서의 확정 요구사항과 아직 미정인 납품 수치 기준을 구분한다.
