# 발열경로 편집 (Phase 1)

## 목적
생성된 사행 발열 경로의 제어점(꼭지점)을 3D 뷰포트에서 직접 드래그해 수정한다.
KRRI 협의 내용(“자동 경로의 각 꼭지점 포인트를 이동 가능하도록”)에 대응하는 기능이며,
정밀 CAD 편집기가 아니라 **경로 형상의 간단한 수동 보정**을 목표로 한다.

## 사용 방법
1. 발열 경로를 생성한다(제외영역 경로는 지원하지 않음).
2. 뷰포트 상단 툴바의 **발열경로 편집** 체크.
3. 뷰가 작업 정면으로 전환되고, 모든 원본 제어점이 노란 점으로 표시된다.
4. 점을 드래그하면 수정된 구간이 미리보기로 표시되고, 놓으면 확정된다.
   이동은 발열 진행 방향 성분만 적용되므로(가로 생성=좌우, 세로 생성=상하) 발열사 간격이 유지된다.
   진행 방향과 수직인 이동만 요청하면 아무것도 바뀌지 않고 상태 표시줄에 안내가 나온다.
5. `Esc`: 진행 중인 드래그 취소. 드래그 중이 아니면 편집 모드 종료(카메라 복원).
   확정된 편집은 즉시 반영되며 경로 Undo/Redo는 제공하지 않는다.

편집 모드에서는 회전·팬·줌·면 선택이 비활성화된다(작업 정면 고정).

## 데이터 모델
- 정본은 2D 데이텀 `SerpentineRoutePiece.Points`이다. 3D는 항상 실제 모델 표면 매핑으로 재계산한다.
- 턴 커넥터는 **항상 직선 2점** `[레인 끝, 다음 레인 시작]`이다(호 내부점·경계 추적 폴백 없음).
  따라서 턴 커넥터의 편집 핸들은 양 끝점만 노출된다. 직선이 면 밖으로 나가면 매핑 단계에서 거부된다.
- `RouteVertexGroups.Build`는 **이웃 조각이 공유하는 끝점만** 하나의 핸들로 묶는다.
  같은 좌표라도 복귀 경로/교차처럼 위상적으로 무관한 점은 별도 핸들이다.
- 이동은 절대 좌표 지정이 아니라 **프레임 평면에서의 변위**로 적용한다
  (`new = origin + (cursor - press)`), 3D 직접 대입으로 인한 깊이 오차를 피한다.
- 이동 방향은 확정된 생성 방향(`SerpentineResult.AngleDeg`)으로 제한한다
  (`RouteVertexMoveConstraint.TryConstrain`): 변위의 진행 방향 성분만 남기고 수직 성분을 버리므로
  레인 피치(발열사 간격)가 유지된다. 축 정렬 방향(0/90/180/270°)은 잠긴 좌표를 그대로 복사한다.
  미리보기와 확정이 같은 제약을 다시 계산해, 미리보기와 커밋 결과가 갈라지지 않는다.
  제약 결과가 원래 점과 1e-6 이내면 패턴 재생성·Undo 기록 없이 안내 문구만 표시한다.
- 표면 매핑 규칙(`BuildSurfaceMapDelegate`): 같은 데이텀 점은 항상 같은 3D 점이 된다.
  1. 인출점(경로의 시작/종료 역할)은 저장된 원본 CAD 인출 edge 참조(모델 리비전, 작업 컨텍스트,
     trim 구간, parameter)로 3D를 직접 평가한다. 참조가 없거나 stale/모호하면 폴리라인 보간으로
     대체하지 않고 명시적으로 실패한다. 같은 좌표의 일반 점은 역할로 구분한다.
  2. 일반 점은 선택면 우선 레이캐스트(`MapWorkingPointOntoFaces`) 히트를 채택한다.
  3. 선택면에 없으면 전역 레이캐스트(`QueryWorkingSurface`) 히트를 **선택면 소속과 무관하게** 채택한다
     — 발열선은 실제 모델 표면 위에 있으므로 발열영역 밖으로 나가도 인접 면 위에 놓인다.
  4. 모델에도 표면이 없으면(실루엣 밖) 매핑 실패로 거부한다(fail-closed). 0.5mm 스냅 폴백은 쓰지 않는다.
- 평면 전용 영역도 같은 표면 매핑 경로를 쓴다(과거 BRepProj 분기 제거).
- 확정 시 `RebuildNativePatternGeometry`가 후보 패턴을 준비한다. 이번 세션에서 같은 조건으로
  이미 커밋까지 성공한 조각은 네이티브 커밋의 retain 목록으로 넘겨 다시 스테이징하지 않는다.
  재사용 증빙은 조각의 종류/레인/2D 좌표가 **비트 단위로 동일**하고, 영역의 검증 키 접두부
  (모델·작업면 리비전, 영역/인출 경계, 선택 인출점, 회로 구성, 제외영역, 검사 정책)가 이전 커밋과
  같으며, 인출 경계 객체가 동일하다는 것이다. 증빙이 없으면(프로젝트 로드 직후, 새 분할 영역,
  구조 변경) 기존처럼 영역의 모든 조각을 다시 스테이징한다.
  네이티브 커밋은 유지·교체·삭제가 기존 커밋 조각 전체를 정확히 덮을 때만 성공하므로,
  분류가 어긋나면 커밋이 실패하고 기존 영역·경로·길이는 그대로 남는다.

## 성능 처리
- 드래그 이동은 뷰포트에서 최신 커서만 33ms 간격으로 병합한다. 이는 입력 폭주를 줄이는 장치이며,
  한 번의 갱신이 오래 걸리면 UI 스레드가 그대로 점유된다.
- 드래그 미리보기는 **2D 표시 전용**이다. 확정 작업평면의 u,v 폴리라인만 네이티브 오버레이
  (`ReplaceVertexPreview2D`)에 넘기고 표면 매핑을 하지 않는다. 따라서 미리보기 선은 실제 모델
  표면 위의 점이 아니며, 길이·검증·저장·출력·표본 캐시 어디에도 쓰지 않는다.
  같은 조각을 조각별 AIS_Shape로 다시 만들지 않고 오버레이 객체 하나의 프레젠테이션만 갱신한다.
- 미리보기 폴리라인은 모두 갱신한 뒤 Redraw를 한 번만 호출하고, 커넥터 상태도 Rebuild 끝의
  Redraw 한 번으로 반영한다.
- 같은 핸들 호버는 재색칠/Redraw를 생략하고, 이동 없는 클릭은 재생성·Undo 기록을 만들지 않는다.
- 확정 표본 재사용: 후보 검증 단계의 strict 매핑 결과를 스테이징까지 보관하고, 스테이징의
  검증 키(모델/컨텍스트 리비전, 작업면·영역 프레임, 인출 binding, 조각 좌표, 검사 정책)가
  정확히 같을 때만 재매핑을 생략한다. 키가 다르면(예: 인출점 보정으로 표본 경로가 달라진 조각)
  기존 경로로 다시 매핑하며, 실패한 후보의 표본은 확정 캐시에 남기지 않는다.
- 확정 표본 캐시는 마지막 커밋 준비가 실제로 요구한 키만 남긴다. 편집을 반복해도 과거 키가
  누적되거나 다음 커밋에서 사전 전체를 복사하지 않는다. 캐시에 없는 조각은 다시 매핑할 뿐이며
  검증 결과가 달라지지는 않는다.

## 검증과 한계
검증:
- 매핑된 모든 점은 실제 모델 면 위에 있어야 한다(스테이징이 점별 지지면 거리를 확인).
- 인접 샘플의 면 전이는 별도로 검사하지 않고 매핑 결과를 그대로 스테이징한다. 점별 지지면 거리 검증은 유지된다.
- 확정 시 변경된 조각은 `SurfacePathMapper.TryMapRouteStrict`로 모델 표면 연속성을 확인한다.
  보강 표본 간격은 `RouteSurfaceValidationPolicy.GapSpacing`(1mm)이며, 이는 결함 허용 공차가
  아니라 조회 간격이다. 1mm 이하의 틈·끊김도 오류로 처리하고 자동 보정·메우기는 하지 않는다.
- 확정 시 회로의 모든 발열 런 선분을 정확 2D 경계(`ValidateSegments`)로 다시 검사한다.
  턴 커넥터와 고정 연결선은 제외영역을 지날 수 있으므로 이 검사에서 제외한다.
  이 검사는 조각을 유지(retain)하더라도 매번 수행한다.
- 드래그 중 2D 미리보기는 표시 전용이며 위 검증을 대신하지 않는다. 미리보기 선은 실제 표면점이 아니다.

한계(의도적 비범위):
- 표본 간격보다 좁은 결함은 보장하지 않는다.
- 굽힘 반경, 자기교차, 제조성 검증은 하지 않는다. 레인 피치(발열사 간격)는 이동 방향 제약으로 유지된다.
- 모델 실루엣 밖(표면 없음)은 거부한다.
- 제외영역(`Paths`) 경로는 편집 대상이 아니다.
- 패턴을 다시 생성하면 편집 내용은 사라진다. 삭제 전에 경고하며, 취소하면 기존 편집이 유지된다.
- 편집 이력은 영역별로 유지된다. 모델을 다시 로드할 때만 초기화된다.
