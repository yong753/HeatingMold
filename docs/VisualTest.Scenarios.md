## 1. 목적과 범위

실제 사용자가 앱에서 하는 행동을 순서대로 재현하고, 각 행동 직후의 중간 상태와
마지막 생성 결과를 함께 검사한다. OS 마우스·키보드 자동화는 사용하지 않고,
앱의 실제 기능과 실제 네이티브 선택·표시 경로를 호출한다.

종료 조건은 모든 시나리오에서 같다.

- 남아 있는 모든 작업영역에 발열경로가 생성되어 있고 화면에 표시되어 있다.
- 각 영역의 적용 조건(마진·간격·방향)이 선언값과 일치한다.
- 경로가 stale 상태가 아니고, 조각 ID·길이 대응이 서로 맞는다.
- 전체 영역 범위로 DXF 내보내기가 가능한 상태다.
- 자동 절차 완료(`Automation=Completed`)와 육안 합격(`VisualReview=NotRecorded`)은
  별도로 기록한다.

선택 취소·영역 삭제·생성 거부는 중간 단계다. 중간 상태를 검사한 뒤
마지막에는 반드시 생성 또는 재생성으로 끝난다.

## 3. 시나리오

각 시나리오는 독립된 앱 프로세스와 독립된 결과 폴더에서 실행한다.

### 01. 여러 면 선택 → 일부 해제 → 전체 해제 → 재선택 → 생성

사전 조건: 모델 로드, 작업방향 +Z.

1. 면 `9, 27, 76`을 차례로 선택한다.
2. 면 `27`만 해제한다. 선택 집합이 `9, 76`인지 관리 상태와 네이티브 선택에서 확인한다.
3. 전체 선택을 해제한다. 선택 집합과 하이라이트가 비었는지 확인한다.
4. 면 `9`만 다시 선택하고 영역 A로 확정한다.
5. 인출면 79, 마진 5, 간격 10, 앵커 인덱스 0을 적용한다.
6. 생성한다.

중간 검사:

- 2단계 후 선택 집합이 정확히 `{9, 76}`이다.
- 3단계 후 선택 집합이 비어 있고 네이티브 선택도 비어 있다.
- 확정 후 영역은 1개이고 면 집합은 `{9}`다.

최종 기대: 조각 17, 연결구간 7, 회로 1, 인출면 79.

### 02. 다른 영역 선택 취소 → A 보존 → B 확정·생성

1. A를 면 9 / 인출면 79 / 마진 5 / 간격 10으로 생성한다.
2. 면 27을 선택하되 확정하지 않고 선택을 해제한다.
3. A의 경로·앵커·길이·회로 수가 그대로인지 확인한다.
4. 면 27을 다시 선택해 영역 B로 확정한다.
5. B를 인출면 34 / 마진 5 / 간격 10 / 앵커 인덱스 0으로 생성한다.

중간 검사: 취소 직후 영역 수는 1, A의 경로와 마커가 불변.

최종 기대: A와 B 모두 생성. B의 조각·연결구간·회로 수는 fixture로 고정한다.

### 03. 영역 삭제 → 같은 위치에 재생성

1. A를 면 9 / 인출면 79 / 마진 5 / 간격 10으로 생성한다.
2. A를 삭제한다.
3. 영역 목록·경로·인출 마커·전기표에서 A가 제거됐는지 확인한다.
4. 면 9를 다시 선택해 같은 alias의 영역으로 확정한다.
5. 같은 조건으로 생성한다.

중간 검사: 삭제 직후 영역 0개, 네이티브 경로 0개, 끝점 마커 0개.

최종 기대: 이전과 같은 조각 17 / 연결구간 7 / 회로 1, 중복 표시 없음.

### 04. 세 영역을 다른 조건으로 순서 바꿔 생성

| 영역 | 선택 면 / 인출면 | 마진 / 간격 |
|---|---|---|
| A | 9 / 79 | 5 / 10 |
| B | 27 / 34 | 5 / 12 |
| C | 76 / 81 | 8 / 10 |

1. A, B, C를 확정하고 각 조건을 지정한다.
2. A를 생성한다.
3. C로 이동해 생성한다.
4. A로 돌아와 마진 5·간격 10, 기존 경로·앵커가 유지되는지 확인한다.
5. B로 이동해 생성한다.

중간 검사: C 생성 후 A와 B의 경로·조건이 변하지 않았다.

최종 기대: 세 영역 모두 각자의 조건·인출점·경로를 가진다.
B의 간격 12, C의 마진 8은 실제 앱에서 먼저 검증해야 하는 후보값이다.

### 05. 입력 초안만 변경 → 다른 영역 → 복귀 → 재생성

1. A와 B를 기본 조건으로 생성한다.
2. A의 마진을 5에서 8로 바꾸되 생성하지 않는다.
3. B로 이동했다가 A로 돌아온다.
4. A의 초안이 마진 8·간격 10으로 유지되고, 이전 결과가 stale로 표시되는지 확인한다.
5. 마진 8에 맞는 앵커를 다시 적용하고 A를 재생성한다.

최종 기대: A만 새 조건의 경로로 바뀌고 B는 불변.
참고: A(면 9)에서 간격 12로 바꾸면 인출면 79의 시작/종료점 후보가 0개가 되어
재생성할 수 없다(실제 앱 확인). 그래서 초안 변경 대상은 마진으로 정했다.

### 06. 같은 Face에 두 번째 영역 확정 → 독립성 보존

1. A(면 9)를 기본 조건으로 생성한다.
2. 같은 면 9를 다시 선택해 영역 B로 확정하고, 조건 초안만 7/14로 바꾼다. B는 생성하지 않는다.
3. C(면 27)를 기본 조건으로 생성한다.
4. A로 돌아와 같은 조건으로 재생성하고, A의 단일 회로·길이를 확인한다.
5. B의 초안 7/14와 미생성 상태, C의 경로가 그대로인지 확인한다.
6. B를 삭제한 뒤 A와 C가 보존됐는지 확인한다.

중간 검사: 같은 면에 경로가 이미 있어도 면 재선택·영역 확정이 가능하고,
B 확정·A 재생성이 서로의 초안과 경로를 바꾸지 않는다.

최종 기대: A와 C는 각각 단일 연속 회로, B 삭제 후에도 두 영역의 경로·길이·인출점이 불변.
참고: 이 시나리오의 B는 UI 독립성 검증용 미생성 초안이다. 같은 Face의 두 영역을
동시에 생성하려면 실제 유효 발열영역이 겹치지 않도록 제외영역을 먼저 구성해야 한다.

### 07. 같은 조건으로 3회 반복 생성

1. A를 기본 조건으로 생성한다.
2. 조건을 바꾸지 않고 3회 재생성한다.
3. 매회 조각 17, 연결구간 7, 회로 1, 총 길이 5266.022mm를 비교한다.
4. 매회 네이티브 경로 수·끝점 마커 수가 누적되지 않는지 확인한다.

최종 기대: 표시 객체와 마커가 누적되지 않고 결과가 동일하다.

### 08. 가운데 영역 삭제 → 같은 면에 새 영역 생성

1. A/B/C를 기본 조건으로 생성한다.
2. B를 삭제한다.
3. A와 C의 경로·조건·인출점이 보존됐는지 확인한다.
4. 면 27을 새 영역 B로 다시 확정한다.
5. 인출면 34 / 마진 5 / 간격 10으로 생성한다.

중간 검사: 삭제 직후 영역 2개, 경로·마커는 A와 C 몫만 남는다.

최종 기대: 세 영역 모두 생성. 표시 이름이 재사용되어도 alias 매핑으로 구분한다.

### 09. 같은 Face 영역 삭제·재확정 독립성

1. A(면 9)를 기본 조건으로 생성한다.
2. 같은 면 9를 다시 선택해 영역 B로 확정하고, 조건 초안을 6/12로 바꾼다. B는 생성하지 않는다.
3. A를 삭제하고 B의 초안 6/12가 보존됐는지 확인한다.
4. 같은 면 9를 다시 선택해 영역 A2로 확정하고 기본 조건으로 생성한다.
5. B를 삭제한 뒤 A2의 단일 회로·길이·인출점이 보존됐는지 확인한다.

중간 검사: A 삭제 후에도 같은 Face를 참조하는 B가 남고,
B 삭제는 A2의 경로·길이·마커를 바꾸지 않는다.

최종 기대: A2 단일 회로, 조각 15, 길이 5266.022mm. 같은 Face를 참조하는
영역 삭제가 다른 영역의 네이티브 경로·인출점을 제거하지 않는다.

### 10. 생성 불가능한 마진 → 거부 → 정상 복구

1. A와 B를 기본 조건으로 생성한다.
2. B의 마진을 5에서 1000으로 바꾸고 간격은 10을 유지한다.
3. 생성을 요청한다.
4. 요청이 거부되고 기존 A·B의 경로가 보존됐는지 확인한다.
5. B의 마진을 5로 복원하고 기본 앵커로 재생성한다.

중간 검사: 거부 사유가 기록되고 B의 이전 결과는 표시된 채 남는다.

최종 기대: A 불변, B 정상 복구. 마진 1000은 실패 유발 후보값이며
실제 거부 사유를 확인한 뒤 fixture에 고정한다.

### 11. 인출면 변경 취소 → 다른 인출면으로 재생성

1. A를 인출면 79 / 마진 5 / 간격 10으로 생성한다.
2. 인출면 변경 모드에 들어갔다가 취소한다.
3. 기존 인출면·앵커·경로가 보존됐는지 확인한다.
4. 인출면을 면 6과의 공유 경계로 변경한다.
5. 대체 인출 앵커를 적용하고 재생성한다.

중간 검사: 취소 직후 인출면 79, 인출 경계, 앵커, 경로가 모두 불변.

최종 기대: 인출면 6, 기존 인출 마커 없음, 새 인출점이 경로에 반영된다.

### 12. 일부만 생성 → 전체 저장 거부 → 현재 영역 저장 → 나머지 생성

1. A와 B를 확정하되 A만 생성한다.
2. 전체 영역 범위로 DXF 저장을 요청한다.
3. 미생성 B 때문에 저장이 거부되고 파일이 생성되지 않았는지 확인한다.
4. 현재 영역 범위로 바꿔 A를 저장하고 DXF를 다시 읽는다.
5. 전기표에 A의 회로만 있는지 확인한다.
6. B를 면 27 / 인출면 34 / 마진 5 / 간격 10으로 생성한다.

중간 검사: 거부 시 파일 없음, 현재 영역 저장 시 A 회로만 존재.

최종 기대: A와 B 모두 생성되고 전체 범위 저장이 가능하다.
DXF의 모델 투상은 확정된 작업평면 기준 전체 모델 평면도 한 장이며,
발열경로와 전기 사양표는 검토 범위에 적용된다.

### 13. 제외영역 추가 → 생성 → 제거 → 재생성

1. A와 B를 기본 조건으로 생성한다.
2. A의 작업평면에 사각형 제외영역을 추가한다.
   - 최소점 `(80, 250)`, 최대점 `(120, 270)`, 크기 40 × 20
3. A의 경로가 무효화되고 B는 보존되는지 확인한다.
4. 제외 조건의 앵커를 적용하고 마진 5 / 간격 10으로 명시적으로 생성한다.
5. 발열구간이 제외 사각형 내부를 통과하지 않는지 확인한다.
6. 제외영역을 제거하고 기본 앵커로 다시 생성한다.

중간 검사: 제외 추가 직후 A에는 경로가 없고 B의 경로는 그대로다.
연결구간은 발열구간과 별도 규칙으로 검사한다.

최종 기대: A가 기본 결과로 복구되고 B는 불변.

검증 결과: 제외 반영 생성은 21조각·9연결구간·5269.626mm였고, 제외 사각형 내부를
지나는 HeatingRun은 0개였다(경계에 정확히 닿는 구간은 0.01mm 안쪽 기준으로 제외).
제외 제거 후 17조각·7연결구간·5266.022mm로 복구되었고, B는 197/97/3767.323으로
불변이었다.

### 14. 수동 편집 → 재생성 취소 → 폐기 동의 → 재생성

1. A를 기본 조건으로 생성한다.
2. 인출 앵커가 아닌 첫 번째 편집 가능한 발열구간 끝점을 작업평면 +Y로 1mm 이동한다.
3. 재생성을 요청하고 편집 폐기 확인에서 취소한다.
4. 이동한 경로·길이·편집 표시가 유지되는지 확인한다.
5. 다시 재생성을 요청하고 폐기 동의를 선택한다.

최종 기대: 수동 편집이 제거되고 면 9 / 인출면 79 / 마진 5 / 간격 10의
자동 생성 결과로 돌아온다.

검증 결과: 꼭지점 그룹 1(인출 앵커가 아닌 내부 코너)을 작업평면 +Y로 1mm
이동해 `(410.9, 228.1) → (410.9, 229.1)`이 되었고, 편집 후 길이는
5266.185mm였다. 재생성 취소 후에도 경로·길이·편집 표시가 유지됐고,
폐기 동의 후에는 17조각·7연결구간·5266.022mm로 복귀하며 편집 표시가
해제됐다. 확인 응답은 테스트 실행 중에만 주입되고 완료·실패·중단 시 큐가
비워져 일반 앱 동작에 남지 않는다.

## 4. 구현 계획

### 4.1 계약

- `schemaVersion: 1`은 기존 6단계 시나리오로 그대로 동작한다.
- `schemaVersion: 2`는 `areas`와 `steps`를 사용한다.
- 영역은 `alias`로 추적하고, 면 집합·마진·간격·방향·인출면·앵커·최종 기대값을 선언한다.
- 단계는 허용된 행동 이름만 사용한다. 알 수 없는 행동·중복 alias·잘못된 참조는
  실행 전에 거부한다.
- 좌표 기반 행동은 작업평면 좌표를 저장하되 실제 좌표 변환과 핸들러를 통과한다.

1차 구현 행동:

`loadModel`(암묵), `selectFaces`, `toggleFaces`, `clearSelection`,
`expectSelection`, `confirmArea`, `activateArea`, `deleteArea`, `setAreaInputs`,
`pickExit`, `cancelExitPick`, `generate`,
`checkArea`, `checkAllAreas`, `exportDxf`

2차 구현 행동:

`addExclusion`, `removeExclusion`, `moveVertex`
(확인 응답 주입 포함)

### 4.3 실행 순서

1. 01~08을 먼저 구현하고 각각 실제 앱에서 실행한다.
2. B·C·변경 조건의 실제 결과를 확인해 fixture를 확정한다.
3. 09~12를 구현한다.
4. 제외영역·꼭지점 편집 공통 진입점을 추가하고 13~14를 구현한다.
5. 기존 `basic.json` 6단계 회귀를 유지한다.

### 4.4 판정 원칙

- 생성 성공은 새 패턴·적용 조건·표시 상태가 함께 갱신됐을 때만 인정한다.
- 예상 거부는 지정한 행동·사유·횟수와 일치할 때만 통과한다.
- 기존 경로가 남아 있다는 사실만으로 생성 성공을 판정하지 않는다.
- 최종 검사는 전기 검토 범위와 무관하게 모든 영역을 직접 순회한다.
- 네이티브 경로·마커는 개수 누적과 alias별 관리 경로의 허용오차 대응을 함께 본다.
- 모든 중간 검사 후 화면 관찰 대기 시간을 둔다.
